# 03-GitHub Issue 便携用法

GitHub Issue 可以作为每个真实触发点的便携卡片。

它适合保存：

```text
触发点原文
现场来源
当前状态
下一步动作
后续反馈
收口结论
```

## 为什么用 Issue

因为 Issue 有几个优点：

```text
每个问题有独立页面。
可以手机打开。
可以追加评论。
可以关闭。
可以打标签。
可以连接仓库文件。
可以后续进入 Project 看板。
```

这比把所有内容塞进一个长对话框稳定。

## Issue 标题格式

建议格式：

```text
TRG-日期-编号：一句话触发点
```

示例：

```text
TRG-20260616-001：为什么很多建材人觉得过两年市场会变好？
```

## Issue 内容模板

```text
## 真实触发


## 现场来源


## 我的反应


## 初步直觉


## 当前状态
先放着 / 要继续想 / 要问人 / 要验证 / 可以表达 / 已收口

## 下一步
只写一个动作。

## 后续反馈
后面用评论追加。
```

## 标签建议

后续可以用这些标签：

```text
S0-收件箱
S1-待确认
S2-分析中
S3-待验证
S4-交付判断
S5-表达中
S6-已反馈
S7-已更新规则
S8-暂停
S9-废弃
```

以及：

```text
真实触发
现实反馈
分支
规则候选
表达候选
```

## Issue 和运行中台的关系

```text
Issue
保存单个触发点的完整生命线。

07-运行中台/02-运行看板.md
保存所有触发点的总览状态。
```

Issue 是单张卡。
运行看板是总地图。

## 什么时候关闭 Issue

以下情况可以关闭：

```text
已经形成稳定规则。
已经完成现实验证并收口。
已经确认暂不继续。
已经转成长期项目或独立分支。
已经判断为无效触发。
```

关闭不等于删除。

关闭代表这一轮已经收口。
