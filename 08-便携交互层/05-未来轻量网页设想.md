# 05-未来轻量网页设想

本文件只记录未来方向，不作为当前优先开发任务。

当前阶段先用手机记录、口袋卡片、GitHub Issue、运行中台和仓库文件跑通。

## 为什么暂时不做重型网页

重型网页会带来：

```text
更多入口
更多字段
更多自动化
更多维护成本
更多伪系统感
```

如果底层规则没有稳定，网页只会把混乱包装得更像系统。

## 未来网页的定位

未来网页不应该是复杂后台。

它应该是一个轻量入口：

```text
口袋里的 Human-Environment-Lab
```

只负责让用户更轻地完成：

```text
记录一个触发
查看当前处理
查看待验证
查看已形成规则
查看分支停车场
写回现实反馈
```

## 最小页面设想

```text
首页
├── 记录一个触发
├── 当前只处理一个
├── 待现实验证
├── 已收口规则
├── 分支停车场
└── 写回反馈
```

## 一张触发点卡片的页面

```text
标题
真实触发
现场来源
我的反应
当前状态
下一步动作
证据缺口
数字生命分析摘要
Lab 交付判断
现实反馈
写回记录
```

## 暂不做的功能

```text
全自动内容生成
自动发布平台
复杂权限系统
复杂数据库仪表盘
多 Agent 可视化大屏
```

这些功能等规则稳定后再决定。

## 开发前置条件

只有满足以下条件，才考虑开发轻量网页：

```text
至少积累 20 张真实触发卡片。
至少完成 5 次现实验证。
至少形成 5 条稳定规则。
运行中台状态规则已经使用过一轮。
确认 GitHub Issue 或 Markdown 卡片的字段足够稳定。
```

## 当前结论

现在不要急着开发网页。

先让便携卡片跑起来。

网页是后续增强，不是当前内核。
