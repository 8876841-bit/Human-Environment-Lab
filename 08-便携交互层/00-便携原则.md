# 00-便携原则

## 1. 便携层解决什么

便携层解决的不是系统有多完整，而是用户能不能在真实生活里随时使用它。

Human-Environment-Lab 的真实输入来自物理世界。

因此它不能只存在于一个长对话框里，也不能被设计成必须坐在电脑前才能使用的系统。

它必须适应：

```text
走路时想到一句话
现场听到一个判断
和别人聊天后产生困惑
突然意识到一个矛盾
手机上临时记录一个感受
换一个对话框后继续处理
```

## 2. 便携层的核心原则

```text
不依赖某一个对话框。
不依赖某一个软件。
不要求用户先分类。
不要求用户理解全部流程。
不优先做复杂自动化。
不把碎片全部塞进仓库。
```

## 3. 最小动作

每次只保留最小动作：

```text
记一句。
成一张卡。
处理一个问题。
得到一个下一步。
必要时写回仓库。
```

## 4. 便携层不是降低系统深度

便携不是简化思考。

便携是把入口做轻，把后台规则做稳。

真正的结构仍然保存在：

```text
00-系统内核/
06-硅基数字生命工作流-V3/
07-运行中台/
```

08-便携交互层 只负责让这些结构可以被用户轻便调用。

## 5. 卡片优先

每个真实触发点优先形成一张卡片。

卡片不是完整文章。
卡片不是分析报告。
卡片不是内容脚本。

卡片只回答：

```text
我遇到了什么？
我为什么停了一下？
它现在处于什么状态？
下一步只做什么？
```

## 6. 写回优先于扩展

每次推演后，优先判断是否需要写回：

```text
是否更新触发点状态？
是否更新下一步？
是否形成规则？
是否进入分支停车场？
是否需要现实验证？
```

不写回的推演，会重新变成对话框里的临时意识流。

## 7. 未来可以自动化，但现在先不自动化

自动化应当建立在稳定规则之后。

当前阶段不优先做：

```text
自动分流
自动生成内容
自动写仓库
自动推送任务
自动跨平台同步
```

先让卡片、状态、写回跑顺。
