# 04-跨对话框迁移规则

本文件用于解决一个核心问题：

```text
数字生命不能被困在某一个对话框里。
```

对话框只是临时推演空间。

只要卡片、状态和规则能带走，系统就可以跨对话恢复。

## 最小迁移包

从一个对话框迁移到另一个对话框时，不要复制全部聊天记录。

只需要带走这个最小包：

```text
1. 当前触发点卡片
2. 当前状态
3. 本轮已形成的判断
4. 下一步动作
5. 需要遵守的系统边界
```

## 标准迁移格式

```text
请接着处理这个 Human-Environment-Lab 触发点。

触发点：

当前状态：

已有判断：

证据缺口：

下一步：

系统边界：
内容不是默认出口；证据不足不能下结论；新分支不要乱追；每轮需要收口。
```

## 示例

```text
请接着处理这个 Human-Environment-Lab 触发点。

触发点：
为什么很多建材人觉得过两年市场会变好？

当前状态：
待现实验证。

已有判断：
它不是单纯建材问题，而是旧行业下行时，人如何判断自己是在等待周期，还是在逃避重构。

证据缺口：
还缺少 5 个建材行业相关者的原话。

下一步：
去问 5 个人：你说的“变好”具体指什么？

系统边界：
先不要做内容；不要直接判断他们都在自我安慰；先补真实话语。
```

## 跨 AI 使用规则

无论使用 ChatGPT、Claude、Codex、本地模型或其他 AI，都先提供最小迁移包。

不要让新对话重新猜主线。

如果新模型开始直接生成内容，需要拉回：

```text
先不要做内容。
先判断这个触发点的真实来源、证据状态、下一步现实动作。
```

## 写回规则

跨对话处理完成后，必须返回仓库做一次写回判断：

```text
状态是否变化？
下一步是否变化？
是否新增证据？
是否形成规则候选？
是否产生新分支？
是否可以收口？
```

不写回，就不算进入系统记忆。
