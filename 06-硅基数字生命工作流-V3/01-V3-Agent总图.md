# 01-V3 Agent 总图

> 本文件定义 V3 硅基数字生命工作流的 Agent 结构。

---

## 一、总原则

V3 Agent 不是旧内容生产角色的改名。

旧角色：

```text
选题 Agent
脚本 Agent
视觉 Agent
视频 Agent
复盘 Agent
```

V3 角色：

```text
总控 Agent
碳基输入确认 Agent
硅基研究分析 Agent
数字边界守门 Agent
Lab 交付判断 Agent
表达传播 Agent
现实反馈复盘 Agent
规则进化 Agent
```

区别在于：

```text
旧 Agent 以内容产出为中心。
V3 Agent 以碳硅循环和现实验证为中心。
```

---

## 二、Agent 调用链路

```text
真实触发
↓
00-总控 Agent
↓
01-碳基输入确认 Agent
↓
02-硅基研究分析 Agent
↓
03-数字边界守门 Agent
↓
04-Lab 交付判断 Agent
↓
根据判断分流：
    ├─ 内部研究
    ├─ 公开表达 → 05-表达传播 Agent
    ├─ 工具 / 产品 / 服务
    ├─ 现实行动
    └─ 暂不表达
↓
物理世界验证
↓
06-现实反馈复盘 Agent
↓
07-规则进化 Agent
```

---

## 三、8 个 Agent 的职责

### 00-总控 Agent

负责判断一次输入是否进入 Human-Environment-Lab，并决定调用哪些 Agent。

核心问题：

```text
这次输入是否值得进入 Lab？
```

---

### 01-碳基输入确认 Agent

负责确认输入是否来自物理世界的真实触发。

核心问题：

```text
这是真实发生的、真实感受到的，还是脑内推演？
```

---

### 02-硅基研究分析 Agent

负责整理、分析、建模、推演和提出临时假设。

核心问题：

```text
这个真实触发背后的结构可能是什么？
```

---

### 03-数字边界守门 Agent

负责判断数字处理是否越界。

核心问题：

```text
哪些是事实？哪些是假设？哪些是推演？哪些不能公开？哪些必须回到现实验证？
```

---

### 04-Lab 交付判断 Agent

负责判断本轮输出应该交付成什么形式。

可选出口：

```text
内部研究
公开表达
内容传播
工具
产品
服务
现实行动
暂不表达
```

---

### 05-表达传播 Agent

只有当 Lab 判断“适合公开表达 / 内容传播”时才调用。

核心问题：

```text
如何把深判断说成人话，同时不扭曲真实？
```

---

### 06-现实反馈复盘 Agent

负责分析物理世界反馈。

核心问题：

```text
现实到底反馈了什么？
```

---

### 07-规则进化 Agent

负责判断本轮是否更新数字生命记忆与 Lab 规则。

核心问题：

```text
这一轮之后，系统哪里必须改变？
```

---

## 四、禁止事项

```text
不允许跳过碳基输入确认，直接生成内容。
不允许跳过数字边界守门，直接公开表达。
不允许把平台数据当成唯一反馈。
不允许把没有现实反馈的假设写入稳定规则。
不允许把表达传播 Agent 当成系统总入口。
```

---

## 五、最小可运行版本

最小版本只需要 5 个 Agent：

```text
00-总控 Agent
01-碳基输入确认 Agent
02-硅基研究分析 Agent
03-数字边界守门 Agent
04-Lab 交付判断 Agent
```

表达传播、现实反馈、规则进化可以在第二阶段接入。

但系统从第一天就必须保留：

```text
现实验证
规则更新
暂不表达
```
