# 01｜数字资产调用与隐私存储规范

> 适用范围：Human-Environment-Lab 生成图片、人物照片、视频片段、封面图、提示词、项目素材
>
> 核心目的：让生成过的图片、人物形象、提示词和视频片段可以复用，同时避免把个人隐私素材随意推送到仓库。

---

## 0. 核心结论

之前生成过的图片可以作为数字资产调用。

但必须区分两类：

```text
1. 可公开资产
例如：AI 生成的封面、图文卡、非隐私视觉素材、通用图标、提示词模板。

2. 私密资产
例如：用户本人照片、原始人像参考图、未公开视频片段、家庭场景照片、客户案例原图。
```

两类资产不能用同一种方式管理。

---

## 1. GitHub 仓库适合存什么

GitHub 仓库适合存：

```text
流程文档
内容脚本
提示词
发布包
检查清单
资产索引
版本记录
复盘结果
```

GitHub 不建议直接存大量图片 / 视频 / 私密照片，尤其是：

```text
本人原始照片
客户现场图
家庭生活图
未公开素材
大体积视频片段
```

原因：

```text
1. GitHub 更适合管理文本和代码，不适合管理大量媒体文件。
2. 图片和视频会让仓库变重。
3. 私密素材一旦上传，会增加误公开和误传播风险。
4. 即使仓库是私有的，也不建议把原始人像素材当成普通文件随意入库。
```

---

## 2. 推荐资产管理方式

采用“两层存储”：

```text
仓库：存资产索引、提示词、用途说明、版本关系。
资产库：存真正的图片、视频、照片文件。
```

推荐结构：

```text
GitHub 仓库
└── 07-资产库
    ├── 数字资产调用与隐私存储规范.md
    ├── 资产索引.md
    ├── 人物母版索引.md
    ├── 项目素材索引.md
    └── 提示词索引.md

外部资产库
└── HEL-Assets
    ├── 01-人物母版
    ├── 02-项目图文成品
    ├── 03-视频关键帧
    ├── 04-视频片段
    ├── 05-客户案例素材
    ├── 06-发布成品
    └── 99-归档
```

外部资产库可以放在：

```text
本地硬盘
移动硬盘
阿里云盘
百度网盘
飞书云文档
Google Drive
Notion / Airtable / 飞书多维表格索引
```

## 3. 人物照片怎么处理

用户本人照片属于私密资产。

默认规则：

```text
不自动推送到 GitHub。
不把原始照片直接放进仓库。
不把家庭环境、未公开生活图作为公共素材。
```

更稳的做法：

```text
1. 原始照片保存在私密资产库。
2. 仓库只记录“人物母版编号”和“用途说明”。
3. 生成图时调用对应人物母版，不在仓库暴露原图。
```

示例：

```text
人物母版 ID：CHAR-LONA-001
用途：TP-001 C1 AI 视觉角色参考
妆造：深色宽松外套 / 白色内搭 / 中性轻街头风
状态：可用于 AI 学习线内容
原始文件位置：私密资产库，不入 GitHub
```

---

## 4. 生成图片能不能复用

可以。

但要分等级：

```text
L1 临时图
只用于对话判断，不进入正式资产库。

L2 样张图
用于风格参考，可以进入项目素材文件夹。

L3 成品图
可发布，可进入发布成品库。

L4 母版图
可作为后续系列统一参考，必须编号管理。

L5 系统资产
可长期复用，如人物母版、封面风格、图文模板、关键帧风格。
```

TP-001 已确认的 B2 图文成品，属于：

```text
L3 成品图
部分视觉规则可升级为 L4 母版
```

TP-001 C1 的角色关键帧，如果后续稳定，可升级为：

```text
L4 人物视觉母版
L4 AI 视频风格母版
```

## 5. 是否需要重新生成

不一定。

判断规则：

```text
如果只是同一项目内复用，并且图像质量、人物一致性、内容准确性都通过，可以直接调用。

如果要换平台、换主题、换比例、换人物姿态、换妆造，通常需要重新生成或局部重做。

如果原图只是故事板，不是正式关键帧，不能直接拿去图生视频，需要重新生成“视频初始帧”。
```

特别注意：

```text
图文成品图 ≠ 视频初始帧
故事板图 ≠ 图生视频底板
人物参考图 ≠ 发布成品图
```

## 6. 数字资产命名规则

推荐命名：

```text
项目编号_资产类型_页码或镜头_版本_状态
```

示例：

```text
TP001_B2_XHS_P01_V1_FINAL.png
TP001_B2_XHS_P02_V1_FINAL.png
TP001_C1_KF01_STORYBOARD_V1.png
TP001_C1_KF01_SEEDFRAME_V1.png
TP001_C1_CLIP01_TEST_V1.mp4
CHAR_LONA_001_REF_PRIVATE.jpg
```

状态建议：

```text
DRAFT：草稿
TEST：测试
PASS：通过
FINAL：定稿
ARCHIVE：归档
PRIVATE：私密
```

## 8. 隐私分级

### P0 公开资产

```text
可发布图文
公开视频
通用提示词
通用模板
```

### P1 内部资产

```text
未发布图文
视频草稿
项目复盘
内部判断表
```

### P2 私密资产

```text
本人原始照片
家庭照片
未公开人像参考
未公开视频素材
```

### P3 高敏资产

```text
客户现场原图
客户隐私信息
合同/报价/身份信息
私人聊天记录
```

管理规则：

```text
P0 可以进入仓库或公开发布。
P1 可以进入仓库，但需要注意上下文。
P2 不直接进 GitHub，只在私密资产库保存。
P3 不进 GitHub，不进公开 AI 工具，必须单独脱敏。
```

## 11. 最终原则

```text
图片可以复用，但要编号。
人物可以调用，但要母版化。
照片可以参考，但不默认入仓库。
视频可以测试，但不要把草稿当资产。
仓库存规则、索引、提示词、复盘。
外部资产库存图片、视频、照片原文件。
```

这套规则用于防止：

```text
素材散落
版本混乱
隐私误传
重复生成
无法复用
成品和草稿混在一起
```
