# 07-运行中台

> 本目录是 Human-Environment-Lab V3 的状态控制层。  
> 它解决单一对话框容易乱线、分支失控、没有收口、长期状态看不见的问题。

---

## 目录定位

`07-运行中台/` 不负责提出理论，也不负责生产内容。

它负责：

```text
收集真实触发
标记当前状态
判断是否继续
判断是否收口
停放新分支
规定信息入口
进行每周整理
```

它是：

```text
对话框临时推演
↓
仓库长期记忆
↓
物理世界下一步行动
```

之间的中间控制层。

---

## 文件说明

```text
00-运行规则.md          什么时候继续、收口、暂停、写回仓库
01-真实触发收件箱.md    所有新触发点先进入这里
02-运行看板.md          每个触发点的当前状态
03-对话收口模板.md      每次重要对话结束时使用
04-分支停车场.md        对话中长出来但暂时不追的方向
05-每周整理日志.md      每周整理一次系统状态
06-入口协议.md          什么信息进入哪个入口，防止全部塞进对话框
```

---

## 当前最小运行方式

每天只做一件事：

```text
让一个真实触发点拥有明确状态。
```

每周只做一件事：

```text
整理哪些触发点值得继续、哪些该暂停、哪些必须进入现实验证。
```

---

## 使用顺序

每次启动一个新触发点：

```text
1. 先用 06-入口协议.md 判断信息类型和入口
2. 写入 01-真实触发收件箱.md
3. 在 02-运行看板.md 标状态
4. 进入对话框做临时推演
5. 对话结束后用 03-对话收口模板.md 收口
6. 长出的新方向写入 04-分支停车场.md
7. 每周写入 05-每周整理日志.md
```

---

## 入口判断

每次新信息进入系统，先问：

```text
这是新触发点、旧反馈、新分支、稳定规则、现实动作，还是表达交付？
```

对应入口：

```text
新触发点 → 收件箱 / Issue
旧反馈 → 原 Issue / 观察日志
新分支 → 分支停车场
稳定规则 → 规则库 / 对应系统文件
现实动作 → 运行看板
表达交付 → 先做 Lab 交付判断，再进 05-内容生产体系
深度推演 → 对话框
```

---

## 硬边界

```text
对话框不是长期操作系统。
仓库才是长期记忆。
运行中台负责防止系统乱线。
入口不是越多越好，入口必须分工明确。
没有状态的触发点不继续深聊。
没有收口的对话不进入下一轮。
```
