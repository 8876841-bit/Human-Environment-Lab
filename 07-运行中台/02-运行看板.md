# 02-运行看板

> 本文件用来让所有真实触发点拥有状态。  
> 目标是让系统看得见：哪些在推进，哪些该暂停，哪些该收口，哪些已经更新规则。

---

## 状态定义

| 状态 | 名称 | 含义 |
|---|---|---|
| S0 | 收件箱 | 刚进入系统，尚未判断 |
| S1 | 待碳基确认 | 需要确认是否来自真实经历、感受、关系、行动或反馈 |
| S2 | 硅基分析中 | 数字生命正在整理、拆解、建模、推演 |
| S3 | 待现实证据 | 证据不足，需要补现场、原话、数据或真实反馈 |
| S4 | 待 Lab 交付判断 | 需要判断进入研究、表达、工具、服务、行动或暂不表达 |
| S5 | 待现实行动 | 需要用户亲自带回物理世界验证 |
| S6 | 表达传播中 | 已判断适合公开表达或内容传播 |
| S7 | 已反馈 | 已收到物理世界反馈 |
| S8 | 已更新规则 | 已写回规则、日志、OBS 或决策记录 |
| S9 | 暂停 | 暂不推进，等待新证据或新触发 |
| S10 | 废弃 | 确认不再追 |

## 看板维护规则

```text
1. 每个触发点必须只有一个当前状态。
2. 状态变化时，必须写明下一步。
3. S3 不能直接跳到 S8，必须经过现实证据或反馈。
4. S6 不是默认出口，只有 Lab 判断适合表达传播时才能进入。
5. S9 暂停不是废弃，必须写明重新启动条件。
6. S10 废弃必须写明废弃原因。
```

---

## 每周清理动作

每周清理一次：

```text
1. S0 是否太多？如果太多，做一次筛选。
2. S3 是否长期无证据？超过两周无证据，转 S9 暂停。
3. S5 是否没有现实行动？超过一周未执行，重新评估是否值得追。
4. S7 是否已经反馈但未更新规则？补写规则更新或明确不更新。
5. S9 是否可以重启？不能重启的转 S10 废弃。
```
