# 07｜元数据标签库

> 作用：规定每条知识如何被标记、过滤、检索、组合、验证和回溯。  
> 本库是视频 RAG 的知识本体，不只是分类表。

---

## 0. 第一性原理

元数据不是“方便分类”，而是让导演 Agent 能判断：

```text
这条知识能不能用？
该在什么条件下用？
和哪些知识组合？
会影响观众哪个底层变量？
用完怎么验证？
```

因此，元数据必须支持三件事：

```text
过滤：先排除不适用知识。
组合：把任务、状态、平台、变量、案例接起来。
验证：把输出连接到可观察反馈。
```

## 5. Operator 类型

| 类型 | 用途 | 示例 |
|---|---|---|
| `task_classifier` | 判断用户到底在做什么任务 | “太平了”可能归入开头、节奏、声音或重剪 |
| `state_change` | 设计观众状态变化 | 不信任 → 愿意了解 |
| `style_translation` | 翻译主观风格词 | 真实 → 现场证据、同期声、低包装 |
| `production_principle` | 校验制作原则 | 证据优先原则 |
| `video_type_logic` | 定义视频类型胜负标准 | 广告片目标是记住卖点或品牌感受 |
| `output_contract` | 固定输出格式 | O01 导演方案 |
| `shot_variable` | 镜头变量 | 特写、手持、主观视角 |
| `editing_variable` | 剪辑变量 | 快切、留白、前后对比 |
| `sound_variable` | 声音变量 | 同期声、环境声、低频冲击 |
| `subtitle_variable` | 字幕变量 | 高亮、密度、层级 |
| `platform_context` | 平台观看场景 | 小红书收藏心态、B站结构期待 |
| `case_mechanism` | 案例可迁移机制 | 开头 3 秒用前后对比证明变化 |
| `asset_index` | 素材资产 | 某段 B-roll 可证明产品质感 |
| `workflow` | 工作流 | 导演方案生成流程 |

---

## 6. 权威等级

| 等级 | 含义 | 示例 | 使用方式 |
|---|---|---|---|
| A1 | 官方/标准 | Dify、LlamaIndex、Chroma、Dublin Core、PBCore、Schema.org、W3C、YouTube/TikTok 官方 | 字段、流程、平台指标、合规 |
| A2 | 专业教学/研究 | Yale Film Analysis、NN/g、HBR JTBD | 影视语言、用户状态、动机判断 |
| B1 | 多案例稳定观察 | 多平台通用的剪辑和视听经验 | 可做原则，但允许修正 |
| B2 | HEL 内部复盘 | 自己项目的数据和反馈 | 优先用于自身账号和客户项目 |
| C | 单案例观察 | 某一个爆款视频拆解 | 只能作为假设或案例，不可上升为原则 |

## 9. 检索过滤建议

第一层过滤：

```text
task_tags
affected_audience_variables
video_type_tags
platform_tags
```

第二层过滤：

```text
operator_type
output_supported
style_tags
scene_tags
constraints
```

第三层召回：

```text
summary + content 语义检索
causal_claim
related_cases
related_principles
related_variables
```

组合召回：

```text
operator_type = state_change
→ 找到观众变化
→ operator_type = style_translation
→ 找到风格翻译
→ operator_type = shot_variable / editing_variable / sound_variable
→ 找到执行变量
→ operator_type = case_mechanism
→ 找到案例校准
```

## 10. 停止标准

一条元数据规范可以入库，必须满足：

```text
1. 能帮助检索变准。
2. 能防止错误适用。
3. 能追溯来源。
4. 能连接任务、类型、平台、输出。
5. 能说明 Operator 类型、因果主张、失败模式和验证方法。
```
