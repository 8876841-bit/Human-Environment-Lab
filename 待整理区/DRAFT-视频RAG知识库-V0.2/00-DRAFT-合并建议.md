## 1. 这是什么

这是对 `09-内容与视频执行中台/` 中“视频生成 / 视频制作 / 平台适配 / 导演判断”能力的体系优化草案。

它不是新的最高系统，也不是替代 ROOT-LOCK 的新根基。

它的定位是：

```text
视频导演 RAG 子系统草案
= 让 Agent 在做视频时，能先判断任务、观众状态、平台观看场景、素材约束，再输出导演方案、分镜、剪辑表、提示词和工作流。
```

---

## 2. 它让系统哪里更清楚

当前 `09-内容与视频执行中台/` 已经有：

```text
03-内容与视频总链路.md
05-视频生成模块.md
06-视频制作模块.md
07-平台运营与转化规则.md
08-数据分析与反馈回流.md
```

这些文件已经定义了视频进入执行链路的位置。

本草案补充的是：

```text
视频生成 / 视频制作之前，导演 Agent 到底如何判断？
```

也就是把“做视频”从：

```text
脚本 → 分镜 → 提示词 → 剪辑
```

深化为：

```text
任务识别
→ 观众状态变化
→ 视频类型胜负标准
→ 平台接收条件
→ 素材现实约束
→ 视听变量组合
→ 案例机制校准
→ 输出格式
→ 验证指标
```

---

## 3. 它是补充还是深化

结论：主要是 **深化**，少量是 **补充**。

深化部分：

```text
1. 深化“视频不是文字脚本的机械翻译”这个判断。
2. 深化“视频能力不是剪一条，而是系统能力”这个判断。
3. 深化“平台不是发布渠道，而是观看场景”这个判断。
4. 深化“AI 给骨架，人工给灵魂”的视频执行层含义。
```

补充部分：

```text
1. 补充 12 个可检索的视频 RAG 知识库结构。
2. 补充 Operator 算子式元数据字段。
3. 补充导演 Agent 的状态机、视听变量、平台接收条件和输出契约。
4. 补充素材资产索引和提示词工作流之间的连接方式。
```

## 4. 是否挑战已有 CORE

不挑战 ROOT-LOCK。

它挑战的是旧执行习惯中可能存在的弱点：

```text
旧弱点 1：把视频生成理解成提示词生成。
修正：AI 视频提示词只是视频导演系统中的一个输出格式。

旧弱点 2：把视频制作理解成剪辑清单。
修正：剪辑表必须服务观众状态变化，而不是只排时间线。

旧弱点 3：把平台适配理解成改标题、改封面。
修正：平台适配要重算入口、速度、心态、上下文、互动和指标。

旧弱点 4：把“真实、高级、电影感”当风格标签。
修正：主观词必须翻译成视听变量，并说明影响注意力、理解、情绪、信任、记忆、行动中的哪一项。
```
