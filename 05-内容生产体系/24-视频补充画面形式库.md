# 视频补充画面形式库 V1

> 用途：为 HEL 的不同话题母线提供可选的补充画面形式，避免每条视频临时想“这里放点什么”。
>
> 重要边界：这不是死规则，不是模板库，不是每条视频都必须照抄。
> 它是一个“开放素材选择库”，后期可以根据平台、题材、真实素材、外部案例不断补充。

---

## 0. 总原则：画面补充不是填空

补充画面不能只为了让视频不空。它必须完成至少一个任务：

```text
证明真实
解释结构
承接转场
制造停顿
放大情绪
降低理解难度
提示下一步
补足现场缺失
展示过程证据
建立系统感
```

如果一个画面只是“好看”，但不能帮助理解、信任、情绪或推进，就不要硬放。

---

## 1. 这份库的使用方式

### 1.1 先问内容任务，再选画面形式

不要先问：

```text
这里放什么画面好看？
```

要先问：

```text
这一段要让用户看见什么？
这一段要证明什么？
这一段要让用户从哪里走到哪里？
```

然后再从本库选择画面形式。

---

### 1.2 不固定，不机械套用

同一条母线可以使用不同画面形式。
同一种画面形式也可以服务不同母线。

例如：

```text
XMind 演说模式
```

可以用于 AI 认知秩序，也可以用于商业服务、工艺机制、真实生活转型的系统解释。

再例如：

```text
手部操作特写
```

可以用于材料感官，也可以用于工艺机制、AI 工作流、生活转型。

---

### 1.3 每次使用前都要重新判断

每条视频都要重新判断：

```text
这条视频的主任务是什么？
所属母线是什么？
当前段落处于开头、中段、转折、解释还是结尾？
用户此刻最需要的是情绪、证据、结构，还是行动？
```

## 2. 通用补充画面形式库

### 2.1 真实场景类

适合证明真实、建立信任。

```text
真实空间空镜
人物使用动作
手部操作特写
桌面工作流
现场停顿
生活物品特写
环境建立镜头
时间流逝 / 延时
```

适合解决的问题：

```text
这件事是真实发生的，不是 AI 套话。
```

---

### 2.2 屏幕录制类

适合展示过程、工具、系统沉淀。

```text
电脑屏幕录制
手机屏幕录制
iPad 操作录屏
XMind 演说模式
Obsidian 文件结构
GitHub 仓库记录
Dify 节点流
剪映时间线
搜索 / 对比 / 选择过程
```

适合解决的问题：

```text
这不是想法，而是正在被执行的流程。
```

---

### 2.3 结构解释类

适合把抽象概念变清楚。

```text
思维导图
流程图
决策树
任务卡
信息卡片
对照表
责任链路图
平面图 / 动线图叠加
动态标注 / 红圈 / 箭头 / 高亮
```

适合解决的问题：

```text
用户不知道这件事的结构和顺序。
```

---

### 2.4 情绪与节奏类

适合承接转场、制造停顿、放大状态。

```text
空镜
慢镜头
真实停顿
光线变化
关电脑 / 打开电脑
整理桌面
走廊 / 窗边 / 夜晚台灯
蒙太奇快切
match cut 对应剪辑
cutaway 插入镜头
```

适合解决的问题：

```text
内容太硬，需要让用户感受到人的状态。
```

---

### 2.5 证明材料类

适合增加依据、减少空泛。

```text
评论截图
真实聊天片段
报价单局部
合同条款局部
图纸局部
项目清单
旧文件 / 新文件对比
历史资料
平台规则截图
工具页面截图
```

注意：

```text
涉及隐私、头像、姓名、电话、地址、价格敏感信息，必须打码或重制。
```

---

### 2.6 AI 生成补画类

适合补缺口，但必须谨慎。

```text
概念场景图
抽象转场图
统一风格工作台背景
任务分类视觉化
混乱到清晰的隐喻画面
场景复现
```

限制：

```text
不能为了好看乱生成。
必须对齐视觉母版、镜头任务、平台适配、图像生成反馈闭环。
```

## 3. 八条母线的画面方向

### 3.1 空间秩序母线

核心证明：

```text
空间不是审美问题，而是生活运行问题。
```

优先画面：

```text
空间全景
动线走位
开门 / 关门 / 拿取物品
收纳前后对比
玄关 / 餐桌 / 柜内 / 抽屉局部
平面图 / 动线图叠加
物品从混乱到归位
人在空间里真实使用
```

可补充形式：

```text
动线箭头
before-after 对比
局部放大框
生活痕迹特写
```

---

### 3.2 材料感官母线

核心证明：

```text
材料不是参数，是身体会感受到的东西。
```

优先画面：

```text
材料微距
手触摸表面
光线扫过材料
木纹 / 金属 / 石材 / 玻璃质感
色板和实景对比
材料边缘细节
使用痕迹
声音细节：开合、碰撞、摩擦
```

可补充形式：

```text
微距慢镜头
触感对比
光影变化
色板叠加
```

---

### 3.3 工艺机制母线

核心证明：

```text
翻车不是偶然，是机制没设清楚。
```

优先画面：

```text
安装现场
尺寸测量
图纸与现场对照
收口细节
错误案例特写
工人操作手部
工具使用
节点拆解图
责任链路图
```

可补充形式：

```text
图纸叠加现场
红圈标错
尺寸线标注
设计 → 生产 → 安装 → 验收流程图
责任边界表
```

---

### 3.4 案例探家母线

核心证明：

```text
一个家的布局暴露了人的生活方式。
```

优先画面：

```text
入户第一视角
空间路线推进
屋主使用痕迹
生活物品特写
人在空间里的动作
亮点设计局部
空间前后关系
情绪停顿镜头
```

可补充形式：

```text
动线路线图
空间亮点标注
生活细节慢镜头
第一视角推进
```

---

### 3.5 AI 认知秩序母线

核心证明：

```text
AI 学习不是追工具，是建立判断顺序。
```

优先画面：

```text
软件界面录屏
工具页面对比
XMind 演说模式
Obsidian / GitHub 文件沉淀
Dify 节点流
任务分类卡
桌面工作流
决策树
```

可补充形式：

```text
工具卡片退后
任务卡出现
当前节点高亮
搜索过程快切
前后系统树对比
```

---

### 3.6 真实生活转型母线

核心证明：

```text
这不是成功学，是一个真实的人在调整生存方式。
```

优先画面：

```text
空工作室
深夜桌面
旧项目文件
账本 / 清单 / 计划表
一个人坐着思考
收拾东西
重新打开电脑
日常生活切片
时间流逝
```

可补充形式：

```text
空镜
慢镜头
手写计划
旧文件关闭 / 新文件打开
日常与工作交叉剪辑
```

---

### 3.7 商业服务母线

核心证明：

```text
客户真正缺的不是工厂，而是判断系统和责任边界。
```

优先画面：

```text
报价单对比
服务流程图
工厂 / 展厅 / 材料样板
客户问题清单
责任划分表
价格结构拆解
合同 / 表格局部
咨询过程模拟
```

可补充形式：

```text
谁设计费给谁
谁管理费给谁
谁安装费给谁
价格透明表
责任边界流程图
源头工厂识别表
```

---

### 3.8 意义与文明观察母线

核心证明：

```text
技术越强，真实生活越不能丢。
```

优先画面：

```text
城市夜景
人群与屏幕
家里的安静片段
手写笔记
孩子 / 家庭 / 日常真实生活
AI 界面和真实空间对比
慢镜头
留白画面
光线变化
```

可补充形式：

```text
屏幕 → 餐桌
AI 对话 → 手写笔记
电脑关闭 → 真实空间声音
城市快节奏 → 家里慢节奏
```

## 4. 选择补充画面的判断表

| 当前段落任务 | 优先画面形式 |
|---|---|
| 抓住真实痛点 | 真实场景、停顿、评论截图、桌面工作流 |
| 解释方法结构 | 流程图、导图、任务卡、决策树 |
| 证明不是空想 | 操作录屏、仓库记录、现场细节、文件沉淀 |
| 表达情绪状态 | 空镜、慢镜头、光线、人物停顿 |
| 展示前后变化 | before-after、时间流逝、对比画面 |
| 解释责任机制 | 图纸、流程、责任链、报价表 |
| 降低理解难度 | 动态标注、局部放大、关键词卡片 |
| 形成结尾总结 | 总览导图、方法卡、复盘画面 |

---

## 5. 开放补充机制

这份库必须保持开放，不允许变成死模板。

后续新增画面形式时，按下面格式记录：

```text
新增日期：
来源：真实拍摄 / 平台案例 / 外部视频 / AI 生成 / 用户发现
画面形式：
适合母线：
适合段落：开头 / 中段 / 转折 / 方法解释 / 结尾
解决的问题：
使用限制：
是否已验证：未验证 / 已用于样片 / 已发布验证
复盘结果：
```

---

## 6. 反向淘汰机制

某类补充画面如果出现以下情况，要暂停使用：

```text
看起来高级但用户看不懂
信息太密导致划走
和主画面风格冲突
抢走口播重点
只是装饰，没有推进
和平台调性不符
制作成本过高但效果一般
```

---

## 7. 最小执行原则

每条视频不要贪多。

建议：

```text
1 个真实主画面
+
2-4 类补充画面
+
1 个结构总结画面
```

不要为了显得丰富，把所有类型都塞进去。

---

## 8. 总判断

补充画面不是素材库问题，而是判断问题。

每次只问一句：

```text
这个画面是在帮用户理解，
还是只是让我觉得画面不空？
```

能帮助理解，就保留。
只是填空，就删掉。
