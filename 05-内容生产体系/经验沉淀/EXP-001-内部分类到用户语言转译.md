# EXP-001：内部分类到用户语言的转译经验

> 本经验来自 TP-001「AI 工具越多，反而不知道怎么开始」的脚本讨论。  
> 它沉淀的是一个可复用判断：**内部分类可以专业，但对外表达必须低门槛。**

---

## 一、问题来源

原本平台表达是：

```text
不是你不会用 AI，是你还没想清楚现在要解决内容、代码，还是流程。
```

这个表达比“认知秩序”已经更像人话，但仍然有门槛。

因为目标用户可能并不知道：

```text
什么是内容？
什么是代码？
什么是工作流？
这些东西分别能帮我解决什么？
```

所以问题不是用户不会三选一，而是他连三个选项的含义都不清楚。

---

## 二、真正的用户卡点

用户嘴上说：

```text
AI 工具太多，我不知道先学哪个。
```

真正卡住的是：

```text
我不知道我现在到底想让 AI 帮我完成什么。
```

这才是更底层的问题。

---

## 三、我们的内部分类

内部可以使用专业分类：

```text
内容
代码
工作流
```

内部含义是：

```text
内容：生成文字、脚本、标题、笔记、方案。
代码：做网页、做工具、改文件、读仓库、搭项目。
工作流：把重复动作串起来，让它自动跑。
```

但这套词不适合直接拿到平台上说。

原因：

```text
内容：范围太大，用户不一定知道包括什么。
代码：容易让新手害怕，觉得和自己无关。
工作流：对普通用户太抽象。
```

---

## 四、对外转译方式

平台表达应该改成低门槛语言：

```text
写东西
做东西
重复干活
```

对应关系：

```text
内容 → 写东西
代码 → 做东西
工作流 → 重复干活
```

展开解释：

```text
写东西：标题、文案、脚本、笔记、方案。
做东西：网页、表格、工具、图片、视频、页面。
重复干活：整理资料、自动分类、定时提醒、同步文件、批量处理。
```

---

## 五、平台表达顺序

这类内容不能一上来讲工具分类。

正确顺序：

```text
先说用户的乱
↓
再告诉他不是不会用
↓
再提出真正问题：你想让 AI 帮你干什么？
↓
再给三个低门槛选项
↓
最后再对应工具
```

推荐表达：

```text
你不是不会用 AI。
是你还没想清楚：
你现在到底想让 AI 帮你写东西，
做一个东西，
还是替你把重复的事自动处理掉。
```

工具对应放到后面：

```text
写东西 → ChatGPT / Claude
做东西 → Codex / Claude Code / Canva / 即梦
重复干活 → Dify / n8n / Coze
```

---

## 六、这条经验的通用规则

```text
内部用专业分类。
对外用动作语言。
```

也就是说：

```text
内部分类负责判断。
平台语言负责让用户听懂。
```

不要为了“说人话”丢掉内部分类；也不要为了“专业准确”直接把内部分类扔给用户。

---

## 七、判断标准

以后遇到类似表达时，检查 5 个问题：

```text
1. 这个词用户真的懂吗？
2. 用户听到这个词会靠近，还是会退缩？
3. 能不能换成一个动作？
4. 能不能给 2-3 个具体例子？
5. 内部分类和外部表达是否还能一一对应？
```

---

## 八、可复用模板

```text
内部分类：A / B / C
↓
用户听不懂的风险：A 太宽，B 太专业，C 太抽象
↓
对外动作语言：做 X / 做 Y / 自动处理 Z
↓
具体例子：每类给 2-3 个用户熟悉的场景
↓
最后再对应工具或方案
```

---

## 九、一句话标准

```text
先用内部分类把问题判断清楚，再用用户听得懂的动作语言说出来。
```
