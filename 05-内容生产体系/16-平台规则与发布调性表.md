# 平台规则与发布调性表

> 本文件用于解决一个核心问题：内容逻辑正确，不等于适合平台。  
> HEL 的内容必须先从底层逻辑出发，再按不同平台的用户状态、内容消费方式、表达规则进行转译。

---

## 一、总原则

```text
同一个触发点，不同平台应该有不同表达。
```

不能把同一份脚本直接复制到所有平台。

平台适配要同时判断：

```text
1. 平台用户为什么停留？
2. 平台适合什么节奏？
3. 平台更重情绪、方法、真实感、过程，还是深度？
4. 平台有什么表达风险？
5. 这条内容应该做短冲击、中解释，还是长拆解？
```

---

## 二、平台总表

| 平台 | 主要用户状态 | 内容任务 | 推荐长度 | 适合表达 | 风险 |
|---|---|---|---:|---|---|
| 抖音 / 快手 | 快速刷、没耐心、被痛点抓住才停 | 抓停留、抓情绪、促评论 | 15-30 秒 | 强钩子、快节奏、冲突感 | 夸大收益、制造焦虑、标题党 |
| 小红书 | 搜索、收藏、做决策、找方法 | 讲清楚、可收藏、可复用 | 图文 3-6 页 / 视频 40-90 秒 | 清单、步骤、对比、经验 | 空泛鸡汤、信息密度低、封面不清楚 |
| 视频号 | 熟人传播、信任感、克制表达 | 建立可信度、温和共鸣 | 30-90 秒 | 稳定、克制、有判断 | 过度夸张、过度营销、太网感 |
| B站 | 愿意听逻辑、看过程、建立长期信任 | 深度拆解、系列沉淀 | 3-8 分钟起 | 真实困惑开场、逻辑链完整 | 空泛、结构散、开头太慢 |

## 三、抖音 / 快手规则

### 平台调性

```text
快
强
直接
前 3 秒决定去留
用户不等你铺垫
```

### 适合内容

```text
痛点强的触发点
冲突强的观点
一句话能说中的焦虑
前后反差明显的案例
短方法 / 短判断
```

### 推荐结构

```text
0-3 秒：痛点钩子
3-8 秒：说中真实状态
8-15 秒：反转判断
15-25 秒：给一个方法 / 对应关系
25-30 秒：评论互动
```

### 语言要求

要这样说：

```text
你是不是越学 AI 越乱？
不是你不会用，是你顺序错了。
```

不要这样说：

```text
AI 工具选择涉及认知秩序重建。
```

### 平台风险

避免：

```text
学会这个马上赚钱
普通人靠这个逆袭
不学就会被淘汰
全网最强
百分百有效
```

### 发布前检查

```text
1. 前 3 秒是否直接击中痛点？
2. 有没有一句能让用户停住的话？
3. 是否避免夸大收益？
4. 是否太像课程广告？
5. 是否有评论引导？
```

## 四、小红书规则

### 平台调性

```text
具体
可收藏
可截图
可复用
有方法
有审美但不能牺牲信息
```

### 适合内容

```text
清单
步骤
避坑
对比
工具选择
家装细节
个人经验
判断表
方法卡
```

### 推荐结构：图文

```text
P1：封面说中问题
P2：场景 / 痛点代入
P3：误区或关键判断
P4：表格 / 清单 / 对应关系
P5：最小行动 / 收藏理由
```

### 推荐结构：视频

```text
0-5 秒：问题开场
5-20 秒：真实状态
20-50 秒：方法 / 结构拆解
50-80 秒：对应表 / 清单
结尾：收藏或评论引导
```

### 语言要求

要这样说：

```text
选工具前，先问自己 3 个问题。
```

不要这样说：

```text
这是一个认知结构化方法论。
```

### 平台风险

避免：

```text
封面太虚
标题太大
内容像课程大纲
图文页数过多
每页信息没有主次
只有情绪没有方法
```

### 发布前检查

```text
1. 封面是否 1 秒看懂？
2. 是否有收藏价值？
3. 每页是否只讲一个重点？
4. 标题是否具体？
5. 是否有可执行步骤？
```

## 五、视频号规则

### 平台调性

```text
克制
可信
真实
适合熟人传播
不宜过度标题党
```

### 适合内容

```text
真实经历
稳定判断
行业观察
生活秩序
转型思考
客户判断系统
```

### 推荐结构

```text
真实困惑
↓
一个判断
↓
一个具体例子
↓
一个可执行建议
```

### 语言要求

要这样说：

```text
很多时候不是工具不够，而是我们没有先判断清楚要解决什么。
```

不要这样说：

```text
不学 AI 就一定会被时代淘汰。
```

### 平台风险

避免：

```text
过度网感
过度焦虑
过度炫技
过度商业转化
```

### 发布前检查

```text
1. 表达是否克制？
2. 是否足够可信？
3. 是否适合被熟人转发？
4. 是否避免过度制造焦虑？
```

## 六、B站规则

### 平台调性

```text
愿意看过程
愿意听逻辑
但开头必须抓住真实问题
```

### 适合内容

```text
深度拆解
学习路径
系统搭建
项目复盘
工具生态比较
个人转型记录
系列化内容
```

### 推荐结构

```text
真实困惑开场
↓
为什么这个问题普遍存在
↓
底层原因拆解
↓
具体方法
↓
案例或演示
↓
下一集延展
```

### 语言要求

可以比短视频更深入，但仍然要先说人话。

要这样说：

```text
我发现普通人学 AI 最大的问题，不是工具不会用，而是入口太多以后失去了判断顺序。
```

不要这样说：

```text
今天我们从认知秩序和复杂系统的角度展开。
```

### 平台风险

避免：

```text
开头太慢
逻辑链太散
只有观点没有案例
标题很大但内容很薄
```

### 发布前检查

```text
1. 开头是否从真实困惑进入？
2. 逻辑链是否完整？
3. 是否有具体案例或演示？
4. 是否能沉淀成系列？
```

## 七、同一触发点的平台拆分方法

触发点：

```text
AI 工具越多，我反而越不知道怎么开始。
```

### 抖音 / 快手版

```text
主题：AI 工具越多，为什么你越乱？
时长：15-30 秒
任务：抓焦虑，促评论
表达：你不是不会用，是顺序错了。
```

### 小红书版

```text
主题：选 AI 工具前，先问自己 3 个问题
形式：5 页图文 / 40-90 秒视频
任务：让人收藏
表达：内容、代码、流程，你现在到底卡在哪一类？
```

### 视频号版

```text
主题：普通人学 AI，先别急着追工具
时长：30-90 秒
任务：可信、克制地讲判断
表达：先判断要解决什么，再选择工具。
```

### B站版

```text
主题：为什么 AI 工具越多，普通人越难开始？
时长：3-8 分钟
任务：深度拆解工具过载和判断顺序
表达：工具不是问题，判断入口才是问题。
```

## 八、平台适配的 8 项检查

发布前必须检查：

```text
1. 当前平台是谁在看？
2. 这个平台用户为什么会停留？
3. 推荐时长是否合理？
4. 开头强度是否适合平台？
5. 信息密度是否适合平台？
6. 结尾互动是否自然？
7. 有没有平台风险表达？
8. 是否仍然从底层判断出发，而不是只迎合平台？
```

---

## 九、一句话标准

```text
平台适配不是迎合平台，而是把底层判断翻译成这个平台的人愿意停下来看、看得懂、用得上的表达。
```
