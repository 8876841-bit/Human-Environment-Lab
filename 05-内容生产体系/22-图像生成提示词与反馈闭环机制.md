# 22｜图像生成提示词与反馈闭环机制

> 版本：V1  
> 状态：已沉淀为图像批量生产硬规则  
> 适用范围：图文页图片、视频关键帧、封面图、过渡图、案例说明图、AI 生成视觉素材  
> 核心结论：**前期可以人工看提示词；批量生产时必须靠系统反馈闭环，而不是靠人逐张检查。**

---

## 一、为什么必须有反馈机制？

单张图片生成时，人可以人工检查：

```text
这张图任务对不对？
提示词是否清楚？
画面是否符合预期？
```

但一旦进入批量生产，人不可能每张都逐字检查提示词、逐图验收。

所以系统必须从：

```text
人工逐张把关
```

升级为：

```text
前期人工校准
+
批量自动检查
+
异常人工介入
+
结果反向修正提示词
```

一句话：

```text
人不负责看每一张。
人负责建立规则、抽查异常、修正系统。
```

---

## 二、第一性原理

图像生成不是“把概念变成图片”。

图像生成的本质是：

```text
把内容任务翻译成视觉约束，
再由模型生成候选画面，
最后用反馈机制判断它是否完成任务。
```

所以完整闭环必须包含：

```text
任务
↓
结构化提示词
↓
生成图片
↓
自动验收
↓
反馈分类
↓
修正提示词 / 重生成 / 人工介入
↓
沉淀经验
```

如果没有反馈机制，批量生成一定会逐渐失控。

---

## 三、图像生成的两种阶段

### 1. 校准阶段

适合前 1-3 张。

目标不是大量出图，而是确定：

```text
视觉母版是否成立
页面 / 镜头任务是否成立
提示词结构是否可控
验收标准是否准确
```

这一阶段允许人工逐张看。

### 2. 批量阶段

适合模板已稳定以后。

目标不是每张都人工判断，而是让系统自动完成：

```text
提示词生成
提示词自检
图像生成
图像验收
失败归因
自动修正
异常上报
```

批量阶段不能依赖人逐张确认。

## 四、图像生成前置卡

所有图片生成前，必须先形成图像生成前置卡。

```text
项目编号：
图片编号：P__ / KF__ / Cover / Other
所属形式：图文 / 视频 / 封面 / 说明图 / 过渡图
所属母线：
平台：
主任务：
允许副任务：
前后关系：上一页/上一帧是什么，下一页/下一帧是什么
继承的视觉母版：
必须保留：
允许发挥：
禁止项：
验收标准：
```

没有前置卡，不允许生成提示词。

---

## 五、结构化提示词格式

所有图像生成必须先产出结构化提示词，再进入生成。

提示词必须包含：

```text
1. 图片任务
2. 所属页/帧编号
3. 画面主体
4. 视觉风格
5. 版式结构
6. 必须保留
7. 允许发挥
8. 禁止项
9. 平台适配要求
10. 验收标准
```

提示词不是越长越好。  
提示词必须服务任务，不能堆砌形容词。

---

## 六、提示词自检机制

生成图片前，提示词必须先过自检。

### 自检问题

```text
1. 是否写清图片编号？
2. 是否写清主任务？
3. 是否写清允许副任务？
4. 是否写清所属视觉母版？
5. 是否写清必须保留和允许发挥？
6. 是否写清禁止项？
7. 是否写清平台适配要求？
8. 是否写清验收标准？
9. 是否存在互相冲突的要求？
10. 是否把任务写成了空泛概念？
```

### 自检结果

```text
通过：允许生成图片。
不通过：自动重写提示词，不进入出图。
```

## 七、图片自动验收评分

每张图生成后，必须按 6 项评分。

每项 0-5 分。

| 维度 | 检查什么 |
|---|---|
| 任务完成度 | 是否完成当前页/帧主任务 |
| 连续性 | 是否延续视觉母版、前后页/帧关系 |
| 表达清晰度 | 用户 1 秒内是否知道看哪里 |
| 平台适配 | 是否符合当前平台调性和风险边界 |
| 信息层级 | 是否没有堆满、没有抢任务 |
| 禁止项 | 是否没有出现明确禁止元素 |

### 通过标准

```text
总分 ≥ 24 分
且任务完成度 ≥ 4
且禁止项 ≥ 4
```

### 自动返工标准

```text
总分 18-23 分：自动归因并重写提示词，再生成一次。
```

### 人工介入标准

```text
总分 < 18 分
或连续 2 次重生成仍不合格
或出现严重平台/隐私/版权/事实风险
```

## 八、失败归因分类

图片不合格时，不能只说“不好看”。

必须归类失败原因：

```text
A. 任务偏离：画面没有完成页/帧任务
B. 视觉漂移：人物、空间、风格、色彩不一致
C. 信息重复：和上一页/帧没有推进
D. 信息抢跑：提前讲完下一页/帧内容
E. 文字问题：文字错误、错别字、不可读、太多
F. 平台风险：夸大、敏感、导流、版权、AI 标识风险
G. 审美问题：构图混乱、信息层级差，但任务方向正确
H. 幻觉问题：生成了不该出现的工具、场景、人物或细节
```

不同失败原因对应不同处理：

| 失败类型 | 处理方式 |
|---|---|
| 任务偏离 | 重写主任务和画面证据 |
| 视觉漂移 | 强化视觉母版约束 |
| 信息重复 | 重写页/帧任务差异 |
| 信息抢跑 | 删除下一页/帧内容 |
| 文字问题 | 减少画中文字，后期加字 |
| 平台风险 | 回到平台规则表核对 |
| 审美问题 | 调整构图和信息层级 |
| 幻觉问题 | 加强禁止项和必须保留 |

## 九、批量生产反馈闭环

批量生产时，系统必须记录每张图的生产日志。

```text
项目编号：
图片编号：
提示词版本：
生成时间：
图片文件名：
自动评分：
失败原因：
是否重生成：
最终状态：通过 / 返工 / 人工介入 / 放弃
人工备注：
```

每批完成后，必须做批次复盘：

```text
1. 哪类失败最多？
2. 是提示词问题，还是视觉母版问题？
3. 是页面/镜头任务不清，还是模型执行不稳？
4. 哪些禁止项需要加入模板？
5. 哪些表达方式效果稳定，可以沉淀为模板？
```

批量生产不是只产图，还要反向更新规则。

## 十、人工参与方式

批量阶段，人只看三类内容：

```text
1. 第一批校准样张
2. 自动评分不合格的异常图
3. 每批随机抽样 10%-20%
```

人不需要逐张检查所有提示词和所有图片。

人工反馈必须写成结构化意见：

```text
不是：这张不行。
而是：失败类型 = 信息重复；原因 = 和 P2 都在讲焦虑；处理 = P3 改成判断入口。
```

## 十一、TP-001 应用示例

### 前期校准

```text
先人工确认 P1 / P2 / P3 或 KF01 / KF02 / KF03 的任务边界。
确定视觉母版、页面任务、镜头任务都成立。
```

### 批量生成时

系统自动检查：

```text
P1 是否负责抓停留？
P2 是否负责痛点代入？
P3 是否负责判断入口？
P4 是否负责工具对应？
P5 是否负责行动收束？
```

视频关键帧自动检查：

```text
KF01 是否是混乱入口？
KF02 是否是认知反转？
KF03 是否是清晰选择？
```

如果 P3 生成得像 P2，判为：

```text
失败类型：信息重复
处理方式：重写 P3 提示词，强化“判断入口”，弱化焦虑情绪。
```

如果 KF02 生成得像 KF01，判为：

```text
失败类型：信息重复 / 任务偏离
处理方式：重写 KF02 提示词，强化“打断、停顿、认知反转”，不要只是减少工具卡。
```

---

## 十二、硬性禁止

```text
禁止一句概念直接生成图片。
禁止没有前置卡就写提示词。
禁止没有提示词自检就出图。
禁止只用“好看/不好看”评价图片。
禁止批量生产时靠人逐张看。
禁止生成失败后不记录原因。
禁止重复失败但不更新提示词模板。
```

---

## 十三、一句话原则

```text
前期靠人校准，批量靠系统反馈。
图片生成不是一次性动作，而是任务、提示词、画面、评分、返工、沉淀的闭环。
```
