# Dify 内容工作流：触发点驱动版搭建说明 (v3)

本指南用于把 HEL（Human-Environment-Lab / 人与环境实验室）的内容生产流程，在 Dify 平台上落地为可执行工作流。

> **核心纪律**：V0.6.1 底层模型、八条母线、第一性原理，只用于 AI 的内部推理。所有对外输出必须转译成人话，不输出术语，不把用户变成“概念讲解员”。

---

## 一、当前版本的关键变化

旧版逻辑：

```text
观察碎片 / OBS
↓
选题
↓
脚本
↓
视觉资产
↓
剪辑清单
↓
复盘回流
```

新版逻辑：

```text
底层模型 / 八条母线
+
一句触发点
↓
选题生成
↓
内容形式决策
↓
按形式生成脚本
↓
脚本后形式复核
↓
视觉 / 资产 / 拍摄执行清单
↓
发布
↓
复盘
↓
有长期价值的内容，再沉淀成 OBS
```

重要原则：

```text
触发点优先，OBS 降级。
OBS 不是强制输入表格。
只有被验证有长期价值的触发点，才沉淀为 OBS。
```

---

## 二、为什么选择 Dify？

HEL 的核心壁垒不是“提示词”，而是：

```text
底层模型
八条母线
概念转译
内容形式决策
发布复盘回流
```

Dify 适合做这件事，因为它能：

- 编排多节点工作流。
- 挂载知识库。
- 在每个节点设置不同提示词。
- 保留人工交接点。
- 把内容生产从“随机聊天”变成“可复用流程”。

---

## 三、工作流整体架构

建议工作流节点如下：

```text
节点 0：Start（触发点输入）
↓
节点 1：Topic_Agent（痛点与选题生成）
↓
节点 1.5：Content_Format_Decision（内容形式决策）
↓
节点 2：Script_Agent（按形式生成脚本）
↓
节点 2.5：Format_Review（脚本后形式复核）
↓
节点 3：Visual_Assets_Generation（视觉 / 资产 / 拍摄执行）
↓
节点 4：Final_Assembly_Instructions（剪辑 / 发布执行清单）
↓
节点 5：Feedback_Loop（发布复盘与触发点回流）
```

知识库挂载关系：

| 知识库 | 挂载节点 | 用途 |
|---|---|---|
| V0.6.1 底层模型 + 八条话题母线 | 节点 1 | 内部推理：判断触发点属于哪条母线、背后是什么机制 |
| 概念转译对照表 | 节点 1、节点 2、节点 2.5 | 确保对外表达全程说人话 |
| 内容形式决策器 | 节点 1.5、节点 2.5 | 判断适合图文、视频，还是一题多形 |
| 个人金句语料库 | 节点 2 | 模仿创作者个人语感，但不机械复制 |
| 发布复盘记录 | 节点 5 | 判断哪些内容值得系列化、沉淀为 OBS |

## 四、详细节点搭建步骤

## 节点 0：开始节点 Start

### 输入变量

| 变量名 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| `trigger_input` | Paragraph | 必填 | 一句话触发点：真实感受 / 判断 / 困惑 / 现象 / 评论痛点 |
| `target_platform` | Select | 必填 | `抖音` / `小红书` / `B站` / `视频号` |
| `content_goal` | Select | 可选 | `共鸣` / `收藏` / `理解` / `信任` / `转发` / `跟着操作` / `不确定` |
| `source_context` | Paragraph | 可选 | 补充背景：截图描述、聊天记录、现场细节、案例背景 |
| `privacy_boundary` | Paragraph | 可选 | 不能公开的信息：姓名、地址、账号、客户资料、API Key 等 |
| `format_preference` | Select | 可选 | `AI判断` / `图文优先` / `视频优先` / `一题多形` |

最小输入示例：

```text
trigger_input：AI 工具越多，我反而越不知道怎么开始。
target_platform：小红书
content_goal：理解
format_preference：AI判断
```

## 节点 1：痛点与选题生成 Topic_Agent

### 挂载知识库

```text
V0.6.1 底层模型
八条话题母线
概念转译对照表
```

### 系统提示词

```text
你是 HEL 内容体系的选题策划专家。
你的任务是把用户的一句话触发点，转化为适合在 {{target_platform}} 发布的内容选题。

【输入说明】
trigger_input 是用户提供的一句话触发点。它可能是一个真实感受、判断、困惑、现象、评论痛点或现场细节。
source_context 是补充背景，可能为空。
privacy_boundary 是不能公开的信息，必须严格避开。

【内部推理规则，不对外输出】
1. 用 V0.6.1 模型和八条母线拆解触发点。
2. 判断它属于哪一条或哪几条母线。
3. 找到背后的真实痛点、核心机制和可传播冲突。
4. 用溯源三问做验证：
   ① 这是否来自真实感受 / 真实判断 / 真实现象？
   ② 这是否有普遍性？
   ③ 它是否触及某个系统性规律？

【概念转译纪律】
输出中严禁出现以下词汇：熵增、边界化、节能化、可预测化、替代性安放系统、平台反噬、认知卸载、命局条件、尺度层。
必须把内部概念转译为大众能理解的话。

【平台适配】
- 抖音 / 视频号：选题要有冲突，前 3 秒能抓人。
- 小红书：选题要具体，让人想收藏、想点进去找答案。
- B站：选题可以更深，但逻辑链条必须清楚。

【输出格式】
1. 所属母线：xxx母线
2. 核心机制：用大白话说清楚，不说术语
3. 用户痛点：一句话
4. 平台版选题：给 3 个候选
5. 推荐选题：从 3 个里选 1 个，并说明理由
6. 溯源三问验证：真实 / 普遍 / 系统性规律，分别说明
7. 隐私风险提醒：列出需要避开的公开信息

触发点：{{trigger_input}}
补充背景：{{source_context}}
不能公开的信息：{{privacy_boundary}}
```

### 人工交接点 1

创作者确认：

```text
1. 选题有没有贴近真实感受？
2. 有没有被 AI 夸大或编造？
3. 推荐选题是否可以进入下一步？
```

## 节点 1.5：内容形式决策 Content_Format_Decision

### 作用

这个节点决定一条内容到底适合：

```text
图文？
视频？
图文里的哪一种？
视频里的哪一种？
是否一题多形？
```

它不是装饰节点，而是防止脚本跑偏的关键节点。

### 挂载知识库

```text
11-内容形式决策器.md
05-视觉呈现形式库-补充版.md
08-小红书多图笔记结构模板.md
09-动态视觉排版与图组组合.md
```

### 系统提示词

```text
你是 HEL 内容体系的内容形式决策器。
你的任务不是写脚本，而是判断这条选题最适合用什么形式表达。

【输入】
- 推荐选题：{{topic_output}}
- 所属母线：{{topic_line}}
- 目标平台：{{target_platform}}
- 内容目标：{{content_goal}}
- 用户形式偏好：{{format_preference}}
- 补充背景：{{source_context}}

【判断规则】
先判断这条内容的核心作用：
1. 让人共鸣
2. 让人收藏
3. 让人理解一个机制
4. 建立个人信任
5. 让人转发
6. 让人跟着操作

再判断主形式：
- 如果需要收藏、对比、流程、清单：优先图文卡片 / 结构图。
- 如果需要建立信任、表达观点：优先真人口播 / 伪访谈。
- 如果需要讲清复杂逻辑：优先桌面推演 / 结构图文。
- 如果需要展示操作：优先屏幕录制 / 工具演示。
- 如果需要氛围和情绪：优先情绪空镜 + 旁白 / 情绪图文。
- 如果需要展示空间、材料、现场：优先实景对比图文 / 混合视频。

【可选图文形式】
1. 小红书多图笔记
2. 极简结构图 / 清单卡片
3. 实景对比图文
4. 碎片日记 / 情绪图文
5. 概念插画 / 漫画

【可选视频形式】
1. 真人口播
2. 混合视频：真人 / 旁白 + 实景 / 素材 / 结构图
3. 桌面推演
4. 屏幕录制 / 工具演示
5. 情绪空镜 + 旁白
6. 伪访谈 / 自问自答

【输出格式】
1. 内容核心作用：共鸣 / 收藏 / 理解 / 信任 / 转发 / 跟着操作
2. 主形式：具体到图文或视频的子类型
3. 备选形式：1-2 个
4. 不适合的形式：至少 1 个，并说明为什么
5. 选择理由：用 3 句话说明
6. 脚本写作要求：告诉节点 2 应该按什么形式写脚本
7. 需要素材：截图 / 实景 / 桌面纸笔 / 口播 / 结构图 / 空镜 / 旁白
8. 是否建议一题多形：是 / 否，理由
```

### 人工交接点 1.5

创作者确认：

```text
1. 这个形式是否符合自己的表达习惯？
2. 这个形式是否现实可执行？
3. 是否需要改成一题多形？
```

## 节点 2：按形式生成脚本 Script_Agent

### 依赖前置节点

接收节点 1 和节点 1.5 的输出：

```text
推荐选题
topic_line
content_format_decision
script_requirements
needed_assets
```

### 挂载知识库

```text
概念转译对照表
个人金句语料库
内容形式决策器
小红书多图笔记结构模板
视频分镜规则
```

### 系统提示词

```text
你是 HEL 内容体系的编导。
你的任务不是固定写短视频脚本，而是根据“内容形式决策”生成对应形式的内容脚本。

【输入】
推荐选题：{{topic_output}}
所属母线：{{topic_line}}
目标平台：{{target_platform}}
内容形式决策：{{content_format_decision}}
脚本写作要求：{{script_requirements}}
补充背景：{{source_context}}
隐私边界：{{privacy_boundary}}

【共同要求】
1. 全程说人话，不输出底层模型术语。
2. 必须贴近用户的真实触发点，不要泛泛而谈。
3. 不要编造事实、客户、数据、经历。
4. 如果缺少具体素材，就用“可替换素材位”标注。
5. Hook 必须口语化，不要像论文标题。

【如果主形式是图文】
输出：
1. 标题 5 个
2. 封面文案 3 个
3. 图文页结构：第 1 页到第 N 页
4. 每页主标题
5. 每页正文
6. 每页画面建议
7. 收藏理由
8. 评论区引导问题

【如果主形式是视频】
输出五要素分镜表：
序号 | 时长 | 景别/画面 | 旁白/口播 | 音效/花字/剪辑建议

视频必须包含：
1. 前 3 秒 Hook
2. 共鸣段
3. 机制拆解段
4. 具体建议或判断
5. 结尾互动

【如果主形式是桌面推演】
额外输出：
1. 桌面道具
2. 纸面结构图
3. 手部动作
4. 每一步画什么 / 指哪里 / 翻哪张卡片

【如果主形式是屏幕录制】
额外输出：
1. 需要录制的页面
2. 鼠标动作
3. 哪些信息需要打码
4. 每段屏幕对应旁白

【如果建议一题多形】
额外输出：
1. 主内容版本
2. 小红书衍生版本结构
3. 抖音衍生版本结构
4. B站或视频号延展方向
```

### 人工交接点 2

创作者重点检查：

```text
1. Hook 是否像真人说话？
2. 金句是否有个人判断？
3. 有没有违背隐私边界？
4. 脚本是否真的服务于选定形式？
```

## 节点 2.5：脚本后形式复核 Format_Review

### 作用

脚本生成后，再检查一次：最初选择的形式是否仍然成立。

因为有些内容写出来后会发现：

```text
原本以为适合口播，但其实更适合结构图。
原本以为适合图文，但脚本情绪很强，更适合真人口播。
原本以为一题一形，但实际上可以一题多形。
```

### 系统提示词

```text
你是 HEL 内容体系的脚本后形式复核员。
请根据已经生成的脚本，判断当前形式是否仍然匹配。

【输入】
原始触发点：{{trigger_input}}
推荐选题：{{topic_output}}
原定内容形式：{{content_format_decision}}
脚本内容：{{script_output}}
目标平台：{{target_platform}}

【复核问题】
1. 没有画面，这条内容还成立吗？
2. 用户看完是否需要收藏？
3. 内容是否需要展示过程？
4. 内容靠观点打动，还是靠画面打动？
5. 内容是否抽象，需要结构图或桌面推演辅助？
6. 这条内容更需要信任，还是更需要效率？

【输出格式】
1. 是否维持原形式：是 / 否
2. 如果否，建议改成什么形式：
3. 修改理由：
4. 脚本需要调整的地方：
5. 是否建议一题多形：是 / 否
6. 最终锁定形式：
```

### 人工交接点 2.5

创作者最后拍板：

```text
维持原形式 / 改形式 / 做一题多形
```

## 节点 4：剪辑 / 发布执行清单 Final_Assembly_Instructions

Dify 不直接完成剪辑。这个节点把前面所有成果整理成可执行清单。

### 输出内容

```text
【最终执行清单】

一、主形式
例如：桌面推演视频 / 小红书多图笔记 / 真人口播

二、标题
给出 5 个标题，标注首推标题。

三、封面文案
给出 3 个封面版本。

四、完整正文 / 口播 / 旁白
按最终形式输出。

五、分镜 / 图文页结构
按最终形式输出。

六、素材清单
截图 / 实景图 / 录屏 / 桌面纸笔 / 空镜 / BGM / 字幕 / 花字。

七、剪辑节奏
前 3 秒、转折点、金句点、结尾互动。

八、发布建议
首发平台：{{target_platform}}
标签建议：
评论区置顶问题：

九、隐私检查
列出需要打码、删除、模糊处理的信息。

十、一题多形建议
如果适合，列出小红书 / 抖音 / B站 / 视频号的衍生版本。
```

## 节点 5：发布复盘与触发点回流 Feedback_Loop

> 这是 HEL 内容体系的生长来源。没有复盘，系统只是内容加工机；有复盘，系统才会变成自己的内容判断系统。

### 触发时机

发布 48-72 小时后，手动触发。

### 输入变量

| 变量名 | 类型 | 说明 |
|---|---|---|
| `published_link` | Text | 已发布内容链接，可选 |
| `comment_highlights` | Paragraph | 3-5 条代表性评论 |
| `data_metrics` | Paragraph | 播放 / 阅读 / 完播率 / 点赞 / 收藏 / 评论 |
| `creator_reflection` | Paragraph | 创作者自己的复盘感受 |

### 系统提示词

```text
你是 HEL 内容体系的数据复盘员。
请根据发布数据、评论和创作者复盘，判断这条内容是否值得继续延展。

【数据诊断规则】
- 完播率低：前 3 秒 Hook 可能不准，或表达太绕。
- 收藏率高：说明它有工具价值、判断价值或清单价值。
- 评论率高：说明它触发了共鸣或争议。
- 转发高：说明它说出了某类人想替别人表达的话。
- 评论里出现新场景：提取为下一轮触发点。

【输出格式】
1. 本期诊断：一句话
2. 数据亮点：
3. 数据问题：
4. 最值得保留的表达：
5. 下一轮触发点：1-3 个
6. 是否建议做成系列：是 / 否，理由
7. 是否值得沉淀为 OBS：是 / 否，理由
8. 如果沉淀为 OBS，建议标题：

评论摘录：{{comment_highlights}}
数据指标：{{data_metrics}}
创作者复盘：{{creator_reflection}}
```

### 人工动作

```text
1. 只把真实评论和真实数据输入节点 5。
2. 只把被验证有长期价值的触发点沉淀为 OBS。
3. 不要让 AI 编造数据和用户反馈。
```

## 六、人机分工总表

| 节点 | 人的动作 | AI 的动作 | 关键把控点 |
|---|---|---|---|
| 节点 0 | 提供一句真实触发点，说明隐私边界 | 无 | 触发点必须真实 |
| 节点 1 | 拍板最终选题 | 用底层模型推演母线、痛点、选题 | AI 不能编造经历 |
| 节点 1.5 | 确认形式是否现实可执行 | 判断图文 / 视频 / 一题多形 | 形式要服务内容作用 |
| 节点 2 | 修改 Hook 和金句 | 按锁定形式生成脚本 | 金句必须有人味 |
| 节点 2.5 | 最终锁定形式 | 复核脚本与形式是否匹配 | 不要让好脚本配错形式 |
| 节点 3 | 审核素材和视觉真实性 | 输出素材、拍摄、录屏、图文结构 | 不能过度 AI 感 |
| 节点 4 | 按清单剪辑和发布 | 整理执行清单 | 可执行，而不是好看但落不了地 |
| 节点 5 | 输入真实数据和评论 | 诊断效果、提取新触发点 | 没有发布数据，不算验证 |

## 七、一句话标准

```text
不是先写完整 OBS，也不是脚本写完随便选形式。
而是：一句触发点 → 选题 → 形式决策 → 按形式写脚本 → 脚本后复核 → 执行发布 → 复盘沉淀。
```

HEL 的工作流目标不是“自动生成很多内容”，而是：

```text
把你的真实判断，稳定转译成可发布、可复盘、可生长的内容。
```
