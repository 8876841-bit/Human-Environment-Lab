# Dify 视频工作流：框架设计与详细搭建说明 (v2)

本指南旨在将 HEL（人与环境实验室）的四阶段视频生产流水线，在 Dify 平台上落地为可执行的自动化工作流。

> **核心纪律（贯穿全文）**：V0.6.1 底层模型是创作者的"内功"，只用于 AI 的内部推理，**绝不直接出现在任何对外输出中**。所有面向用户的文案，必须经过"概念转译"，说人话，不说术语。

---

## 一、为什么选择 Dify？

HEL 的核心壁垒是**"逻辑编排"**和**"私有化知识库沉淀"**。

- **严密的逻辑控制**：内容必须严格按照"找痛点 → 写脚本 → 做画面 → 发布复盘"的步骤执行，并在脚本环节严格遵循"四步结构"和"五要素分镜"。Dify 的 Workflow 节点编排能力能做到这一点。
- **深度知识库反哺**：V0.6.1 底层模型、八条话题母线、个人金句语料库，都需要作为 AI 的推理基底。Dify 的 RAG 能力能精准挂载和检索这些长文本，且数据完全私有化。

---

## 二、工作流整体架构

整个工作流分为 **6 个节点**，形成从"碎片输入"到"数据回流"的完整闭环：

```
[碎片输入] → 节点1(选题) → 节点2(脚本) → 节点3(资产) → 节点4(执行清单) → [发布] → 节点5(复盘回流)
                ↑                                                                        |
                └──────────────── 新痛点回流，开启下一轮循环 ──────────────────────────────┘
```

**知识库挂载关系**：

| 知识库 | 挂载节点 | 用途 |
| :--- | :--- | :--- |
| V0.6.1 底层模型 + 八条话题母线 | 节点 1 | 内部推理：拆解痛点、打母线标签 |
| 概念转译对照表 | 节点 1、节点 2 | 确保输出全程不出现学术术语 |
| 个人金句语料库 | 节点 2 | 模仿创作者的个人语感 |

---

## 三、详细节点搭建步骤

### 节点 0：开始节点 (Start)

**输入变量**：

| 变量名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `obs_input` | Paragraph | 日常观察碎片或 OBS 日志原文 |
| `target_platform` | Select | 目标平台：`抖音` / `小红书` / `B站` / `视频号` |
| `content_format` | Select | 内容形式：`图文漫画` / `情绪空镜+旁白` / `桌面推演` / `伪访谈` |

> `target_platform` 和 `content_format` 从节点 1 就开始影响输出，而非只在脚本阶段才生效。

---

### 节点 1：痛点与选题生成 (Topic_Agent)

**挂载知识库**：V0.6.1 底层模型、八条话题母线、概念转译对照表

**系统提示词**：

```
你是 HEL 内容体系的选题策划专家。你的任务是把用户的真实观察，转化为适合在 {{target_platform}} 上发布的爆款选题。

【内部推理规则（不对外输出）】
1. 用 V0.6.1 模型的 15 个问题在内部拆解观察输入，识别背后的核心机制。
2. 判断该现象属于八条话题母线中的哪一条，以及对应的哪个"生活痛点专栏"。
3. 用"溯源三问"验证选题的原创性：
   ① 这是真实观察到的吗？
   ② 这是普遍存在的吗？
   ③ 这触及了某个系统性规律吗？
   三问全部通过才能输出。

【概念转译纪律（强制执行）】
输出中严禁出现以下词汇：熵增、边界化、节能化、可预测化、替代性安放系统、平台反噬、认知卸载、命局条件、尺度层。
必须将这些概念转译为对应的大众语言（参考知识库中的概念转译对照表）。

【平台适配要求】
- 抖音/视频号：选题要有强冲突感，能在前3秒制造情绪张力。
- 小红书：选题要有具体的解决方向，让人看到就想点进来找答案。
- B站：选题可以更深度，适合"为什么系列"或"底层逻辑拆解"。

【输出格式】
1. 所属母线（内部标签）：xxx母线 → 【xxx专栏】
2. 核心机制（内部用，一句话）：（用底层模型语言描述，不对外）
3. {{target_platform}} 版选题（大白话，直击痛点）：（最终对外的选题）
4. 溯源三问验证：✅ 真实 / ✅ 普遍 / ✅ 触及系统

输入的观察：{{obs_input}}
```

**人工交接点 1（必须）**：工作流在此暂停，由创作者审核选题，确认"溯源三问"是否真实成立，拍板决定是否采用。**AI 生成的选题只是候选，最终决策权在人。**

---

### 节点 2：结构化脚本生成 (Script_Agent)

**依赖前置节点**：接收节点 1 输出的"对外选题"和"所属母线"。

**挂载知识库**：概念转译对照表、个人金句语料库

**系统提示词**：

```
你是 HEL 内容体系的短视频编导。请根据传入的选题，为 {{target_platform}} 平台撰写一个 60-120 秒的视频脚本。

【平台调性要求】
- 抖音/视频号：放大情绪，制造冲突，给出现成答案，节奏快，前3秒必须有强冲突。
- 小红书：提供具体解决方案，强调审美与生活方式，语气像朋友聊天。
- B站：深度解析，讲透底层逻辑，可以稍长，但逻辑链条必须严密。

【脚本四步结构（必须严格遵循）】
1. Hook（前3秒）：大白话，直击场景，必须口语化，让人第一秒就觉得"说的就是我"。
2. 共鸣（5-15秒）：描述具体生活场景，放大情绪，让用户觉得"你懂我"。
3. 降维打击：引入底层逻辑，但必须全程用大众语言，参考以下转译对照表（严格执行）：
   - 熵增/密度压力 → "越住越乱、被掏空、被挤压"
   - 边界化/边界失效 → "私人空间、不被打扰、没有个人生活"
   - 节能化/秩序化 → "顺手、不费脑子、减少内耗"
   - 可预测化/预测失效 → "踩坑、翻车、心里没底"
   - 替代性安放系统 → "精神寄托、搭子、找个乐子"
   - 平台反噬/认知卸载 → "被算法裹挟、被工具绑架"
   - 命局条件/尺度层 → "原生家庭、打工人的命、大环境的锅"
4. 升华/行动号召：给出情绪抚慰或具体建议，结尾引导关注或互动。

【输出格式】
以"五要素分镜表"格式输出，每行包含：
序号 | 景别 | 画面描述 | 旁白文本 | 音效/花字建议

选题：{{topic_output}}
所属专栏：{{topic_line}}
```

**人工交接点 2（必须）**：创作者重点检查 Hook 是否够口语化、金句是否有个人风格。**AI 的初稿只是框架，金句必须由人修改注入个人语感。**

---

### 节点 3：视觉资产准备 (Visual_Assets_Generation)

本节点根据 `content_format` 变量，进入三条不同的分支逻辑：

#### 分支 A：图文漫画（适用于小红书）

- **AI 动作**：根据分镜表中的画面描述，生成治愈系漫画提示词（参照《04-治愈系漫画风格模板》中的固定提示词基底），调用图像生成 API（DALL-E 3 / Midjourney）生成图片。
- **输出**：5-7 张 3:4 比例图片（按《09-动态视觉排版》中的版式模块组合）。
- **人工把控**：审核画面是否符合治愈系风格，人物形象是否一致，文字是否清晰。

#### 分支 B：情绪空镜 + TTS 旁白（适用于抖音/视频号/B站）

- **AI 动作 1（视频素材）**：根据分镜表中的空镜描述，生成 AI 视频提示词，调用可灵等视频生成 API 生成空镜片段。
- **AI 动作 2（TTS 语音）**：提取分镜表中的旁白文本，调用火山引擎 TTS API，生成高质量旁白音频。
- **AI 动作 3（花字清单）**：从旁白中提取核心金句，输出花字清单（供剪辑时叠加字幕）。
- **人工把控**：审核空镜画面是否符合情绪基调（痛点段冷色调，治愈段暖色调）；如 AI 生成画面失真，用实拍素材替换。

#### 分支 C：桌面推演 / 伪访谈（需真人出镜）

- **AI 动作**：根据脚本生成"拍摄提纲"，包含：分镜顺序、每段时长建议、手部动作说明（桌面推演）或视线方向说明（伪访谈）、BGM 情绪建议。
- **输出**：一份可直接用于拍摄的"拍摄执行手册"。
- **人工把控**：此分支 AI 只负责规划，拍摄和出镜全部由创作者完成。

**人工交接点 3（必须）**：检查生成的视觉资产，确认画面不失真、不过度"AI 感"，必要时用实拍素材兜底。

---

### 节点 4：剪辑执行清单输出 (Final_Assembly_Instructions)

Dify 无法直接剪辑视频，此节点将前序所有成果整合为一份可直接操作的"剪辑执行清单"。

**输出内容**：

```
【剪辑执行清单】

一、完整旁白文本（最终版）
（逐句列出，含标点，方便对口型）

二、花字清单
（列出需要叠加的核心金句及建议出现时间点）

三、视听反差执行指令
- 第 X 秒（痛点转折处）：画面切暗色调 + BGM 切换为压迫感节奏
- 第 X 秒（降维打击处）：画面切暖色调 + BGM 切换为舒缓钢琴
- 第 X 秒（升华处）：画面拉远景 + 提示音效

四、素材清单
（列出所有已生成的图片/视频/音频文件链接或路径）

五、发布建议
- 首发平台：{{target_platform}}
- 封面文字建议：（提取 Hook 的核心一句话）
- 互动引导语：（建议在评论区置顶的问题，用于收集新痛点）
```

---

### 节点 5：发布复盘与痛点回流 (Feedback_Loop)

> **这是整个工作流最核心的环节，也是 HEL 内容体系"护城河"的来源。** 没有这个闭环，工作流只是内容生产机器；有了这个闭环，系统才能真正"生长"。

**触发时机**：视频发布 48-72 小时后，手动触发此节点。

**输入变量**：
- `comment_highlights`：从评论区手动摘录的高频反馈（3-5 条代表性评论）。
- `data_metrics`：完播率、互动率、收藏率的实际数据。

**系统提示词**：

```
你是 HEL 内容体系的数据分析师。请根据以下数据，诊断本次内容的效果，并提取可用于下一轮选题的新痛点。

【数据诊断规则】
- 完播率低（< 40%）→ 诊断：前3秒 Hook 没抓准，或概念转译不到位。建议：重写 Hook，进一步口语化。
- 互动率高（点赞+评论 > 5%）→ 诊断：情绪共鸣到位，转译概念成功。建议：将本期核心概念做成系列。
- 收藏率高（> 3%）→ 诊断：提供了实用价值。建议：强化干货解决方案类内容比重。
- 评论出现新抱怨/新场景 → 直接提取为新的 OBS 观察输入，进入下一轮循环。

【输出格式】
1. 本期诊断：（一句话总结效果）
2. 改进建议：（针对数据弱项的具体调整方向）
3. 新痛点提取：（从评论中提炼 1-3 个可直接投喂节点 1 的新观察）
4. 是否建议做成系列：是 / 否，理由：

评论摘录：{{comment_highlights}}
数据指标：{{data_metrics}}
```

**人工动作**：将"新痛点提取"的结果记录到 `03-观察日志` 中，作为下一轮内容的弹药，开启新循环。

## 四、实施路线图

| 阶段 | 搭建内容 | 目标 |
| :--- | :--- | :--- |
| **MVP 阶段** | 只搭节点 1 + 节点 2 | 跑通"输入观察 → 输出脚本"的核心逻辑，手动去剪映制作 |
| **半自动阶段** | 加入节点 3（分支 B 的 TTS 部分）+ 节点 4 | 实现旁白自动生成，减少重复劳动 |
| **全流程阶段** | 加入节点 5 + 图像/视频 API 接入 | 实现从输入到复盘的完整闭环 |

## 五、人机分工总表

| 节点 | 人的动作（灵魂与决策） | AI 的动作（效率与执行） | 关键把控点 |
| :--- | :--- | :--- | :--- |
| 节点 1 | 提供真实观察碎片；拍板最终选题 | 用 V0.6.1 内部推理，输出平台适配选题 | 选题必须由人拍板，AI 不能凭空捏造 |
| 节点 2 | 修改 Hook 使其口语化；注入个人金句语感 | 套用四步结构输出分镜初稿 | 金句必须有人的风格，拒绝学术说教 |
| 节点 3 | 审核视听资产；提供实拍素材兜底 | 生成图片/空镜/TTS/拍摄提纲（按内容形式分支） | 视觉呈现必须真实，不能过度"AI 感" |
| 节点 4 | 按清单在剪辑软件中完成情绪微调 | 整合输出剪辑执行清单 | 视听反差时机必须精准 |
| 节点 5 | 摘录评论、输入数据、将新痛点存入日志 | 诊断数据、提取新痛点 | 新痛点必须来自真实评论，不能 AI 捏造 |
