# Dify 内容工作流：触发点驱动成品版搭建说明 (v4)

本指南用于把 HEL（Human-Environment-Lab / 人与环境实验室）的内容生产流程，在 Dify 平台上落地为可执行工作流。

> **核心纪律**：底层模型、八条母线、第一性原理，只用于 AI 的内部推理。所有对外输出必须转译成人话，不输出术语，不把用户变成“概念讲解员”。

---

## 一、v4 的核心变化

v3 的主线是：

```text
一句触发点 → 选题 → 内容形式决策 → 脚本 → 视觉 / 执行清单 → 复盘
```

v4 的主线调整为：

```text
一句真实触发点
↓
选题生成
↓
平台与表达前置校验
↓
内容形式决策
↓
按主形式生成脚本
↓
脚本后形式复核
↓
图文 / 视频成品包生成
↓
剪辑 / 发布执行包
↓
真实数据复盘
↓
有长期价值再沉淀为 OBS
```

v4 重点修正 4 件事：

```text
1. 视频长度不固定，按平台、内容任务和用户状态决定。
2. 每条内容必须先判断“谁在看”。
3. 先明确“我们要表达什么 / 不表达什么”，再写脚本。
4. 底层逻辑必须转译成人话，不能直接拿到平台表面上说。
```

---

## 二、工作流总原则

### 1. 触发点优先，OBS 降级

```text
触发点 = 一句话真实感受 / 一个问题 / 一个判断 / 一个现象
OBS = 对值得复用的触发点进行归档后的观察日志
```

当前阶段不要求先写完整 OBS。  
只有发布后被验证有长期价值的触发点，才沉淀为 OBS。

---

### 2. 一个触发点，不等于必须同时做图文和视频

正确规则：

```text
一个触发点只强制确定一个主形式。
只有当它同时具备传播价值和收藏价值时，才做一题多形。
```

判断：

```text
情绪强、适合抓停留 → 视频优先
结构强、适合复用 → 图文优先
情绪强 + 方法强 → 视频主发，图文承接
```

---

### 3. 成品导向，不是清单导向

节点 3 和节点 4 的目标不是只生成“拍摄建议”。

最终目标是：

```text
图文：尽量输出可直接制作的图文成品包
视频：尽量输出可直接生成 / 剪辑 / 发布的视频成品执行包
```

只有在需要真人实拍、现场补素材、录屏或隐私处理时，才额外输出拍摄 / 补素材清单。

---

### 4. 平台先行，语言后置转译

脚本前必须先判断：

```text
平台规则
谁在看
我们要表达什么
怎么转译成人话
```

禁止顺序：

```text
先写脚本 → 再补平台调性 → 再硬改成人话
```

---

## 三、整体节点架构

建议 Dify 工作流节点如下：

```text
节点 0：Start（触发点输入）
↓
节点 1：Topic_Agent（痛点与选题生成）
↓
节点 1.2：Platform_Expression_Preflight（平台与表达前置校验）
↓
节点 1.5：Content_Format_Decision（内容形式决策）
↓
节点 2：Script_Agent（按主形式生成脚本）
↓
节点 2.5：Format_Review（脚本后形式复核）
↓
节点 3：Creative_Assets_Generation（图文 / 视频成品包生成）
↓
节点 4：Final_Assembly_Publish_Package（剪辑 / 发布执行包）
↓
节点 5：Feedback_Loop（发布复盘与触发点回流）
```

知识库挂载建议：

| 知识库 / 文件 | 挂载节点 | 用途 |
|---|---|---|
| V0.6.1 底层模型 + 八条话题母线 | 节点 1 | 内部推理，不对外输出 |
| 概念转译对照表 | 节点 1 / 1.2 / 2 / 2.5 | 把底层逻辑转成人话 |
| 11-内容形式决策器.md | 节点 1.5 / 2.5 | 判断主形式和衍生形式 |
| 12-图文成品形式库.md | 节点 1.5 / 3 | 选择图文结构和页数 |
| 13-视频成品形式库.md | 节点 1.5 / 3 | 判断 V1 / V2 / V3 视频类型 |
| 14-图文视觉规范-决策板风格.md | 节点 3 | 生成中性实用图文风格 |
| 15-平台适配与表达转译前置校验.md | 节点 1.2 / 2 / 4 | 平台、受众、表达边界校验 |
| 发布复盘记录 | 节点 5 | 判断是否系列化 / OBS 化 |

## 四、详细节点搭建

## 节点 0：Start（触发点输入）

### 输入变量

| 变量名 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| `trigger_input` | Paragraph | 必填 | 一句话触发点：真实感受 / 判断 / 困惑 / 现象 / 评论痛点 |
| `target_platform` | Select | 必填 | `抖音` / `小红书` / `B站` / `视频号` / `多平台测试` |
| `content_goal` | Select | 可选 | `共鸣` / `收藏` / `理解` / `信任` / `转发` / `跟着操作` / `不确定` |
| `source_context` | Paragraph | 可选 | 补充背景：截图描述、聊天记录、现场细节、案例背景 |
| `privacy_boundary` | Paragraph | 可选 | 不能公开的信息：姓名、地址、账号、客户资料、API Key 等 |
| `format_preference` | Select | 可选 | `AI判断` / `图文优先` / `视频优先` / `一题多形` |
| `available_assets` | Paragraph | 可选 | 当前已有素材：实拍图、录屏、视频、口播、截图、无素材 |
| `output_depth` | Select | 可选 | `选题` / `脚本` / `成品执行包` / `发布复盘` |

最小输入示例：

```text
trigger_input：AI 工具越多，我反而越不知道怎么开始。
target_platform：多平台测试
content_goal：理解 + 收藏
format_preference：AI判断
available_assets：无真人素材，可用 AI 生成画面
```

## 节点 1：Topic_Agent（痛点与选题生成）

### 作用

把一句触发点转化为平台可用的内容选题。  
本节点可以用底层模型推理，但输出必须说人话。

### 系统提示词

```text
你是 HEL 内容体系的选题策划专家。
你的任务是把用户的一句话触发点，转化为适合在 {{target_platform}} 发布的内容选题。

【输入】
触发点：{{trigger_input}}
补充背景：{{source_context}}
隐私边界：{{privacy_boundary}}

【内部推理规则，不对外输出】
1. 用 HEL 底层模型和八条母线拆解触发点。
2. 判断它属于哪条或哪几条母线。
3. 找到背后的真实痛点、核心机制和可传播冲突。
4. 用溯源三问验证：
   ① 是否来自真实感受 / 真实判断 / 真实现象？
   ② 是否有普遍性？
   ③ 是否触及某个系统性规律？

【概念转译纪律】
严禁在对外选题中直接出现：熵增、边界化、节能化、可预测化、认知卸载、命局条件、尺度层等内部术语。
必须把内部概念转译为大众能理解的话。

【输出格式】
1. 所属母线：xxx母线
2. 真实痛点：一句话
3. 背后原因：用大白话说，不说术语
4. 平台版选题：给 3 个候选
5. 推荐选题：从 3 个里选 1 个，并说明理由
6. 溯源三问验证：真实 / 普遍 / 系统性规律
7. 隐私风险提醒：列出需要避开的公开信息
```

### 人工交接点 1

创作者确认：

```text
1. 这个选题是否贴近真实感受？
2. 有没有被 AI 夸大或编造？
3. 推荐选题是否可以进入平台前置校验？
```

---

## 节点 1.2：Platform_Expression_Preflight（平台与表达前置校验）

### 作用

这是 v4 新增的关键节点。  
它必须在内容形式决策和脚本之前完成。

本节点回答 4 个问题：

```text
1. 发在哪个平台？平台适合什么节奏？
2. 到底是谁在看？他当下是什么状态？
3. 我们到底要表达什么？不是表达什么？
4. 底层逻辑怎么转成人能听懂的话？
```

### 系统提示词

```text
你是 HEL 内容体系的平台适配与表达转译审核员。
你的任务不是写脚本，而是在脚本前判断平台、受众、表达目标和语言转译。

【输入】
推荐选题：{{topic_output}}
触发点：{{trigger_input}}
目标平台：{{target_platform}}
内容目标：{{content_goal}}
补充背景：{{source_context}}
隐私边界：{{privacy_boundary}}

【平台规则】
- 抖音 / 快手：15-30 秒更适合短冲击，前 3 秒必须抓痛点，少铺垫。
- 小红书 / 视频号：40-90 秒可以解释清楚，适合收藏、方法、清单承接。
- B站：3-8 分钟可以深度拆解，但必须从真实困惑开场，不要上来讲体系。
- 多平台测试：先做 30-45 秒通用测试版，再根据数据拆分短版 / 中版 / 长版。

【必须判断】
1. 平台版本：抖音 / 小红书 / 视频号 / B站 / 多平台测试
2. 推荐时长：按平台和内容任务决定，不允许固定套 45-60 秒
3. 观看者画像：谁在看，他现在什么状态
4. 核心表达：一句话说明这条内容真正要表达什么
5. 非目标表达：这条内容不做什么
6. 人话转译：把底层逻辑改成平台语言
7. 内容作用：共鸣 / 收藏 / 理解 / 信任 / 转发 / 跟着操作
8. 平台风险：夸大收益、制造焦虑、隐私、版权、诱导性表达等风险

【输出格式】
1. 平台版本：
2. 推荐时长：
3. 观看者画像：
4. 观看者当下状态：
5. 核心表达：
6. 非目标表达：
7. 人话转译版表达：
8. 内容作用：
9. 平台风险提醒：
10. 给节点 1.5 的形式判断要求：
```

### 人工交接点 1.2

创作者确认：

```text
1. 这个受众判断准不准？
2. 表达有没有变成人话？
3. 有没有把底层术语端到表面？
4. 平台时长和调性是否合理？
```

## 节点 1.5：Content_Format_Decision（内容形式决策）

### 作用

判断这条内容最适合用什么形式表达：

```text
图文？
视频？
图文里的哪一种？
视频里的哪一种？
是否一题多形？
```

### 系统提示词

```text
你是 HEL 内容体系的内容形式决策器。
你的任务不是写脚本，而是判断这条选题最适合用什么形式表达。

【输入】
推荐选题：{{topic_output}}
平台前置校验：{{platform_expression_output}}
目标平台：{{target_platform}}
内容目标：{{content_goal}}
用户形式偏好：{{format_preference}}
已有素材：{{available_assets}}

【先判断内容作用】
1. 让人共鸣
2. 让人收藏
3. 让人理解一个机制
4. 建立个人信任
5. 让人转发
6. 让人跟着操作

【再判断主形式】
- 情绪强、适合抓停留：视频优先。
- 结构强、适合复用：图文优先。
- 情绪强 + 方法强：视频主发，图文承接。
- 需要展示真实现场：V1 实拍原生型或 V3 混合增强型。
- 抽象机制可视化、无真人素材：V2 AI 生成型。
- 有真实素材但需要 AI 解释增强：V3 混合增强型。

【图文形式库】
1. G1 提问反转型
2. G2 场景拆解型
3. G3 步骤流程型
4. G4 前后对比型

【图文视觉风格】
1. S1 治愈系叙事插画风
2. S2 中性实用决策板风
3. S3 实景对比标注风

【视频形式库】
1. V1 实拍原生型：真实、现场感强、低包装。
2. V2 AI 生成型：无真人拍摄需求，用 AI 画面解释抽象问题。
3. V3 混合增强型：真实素材为骨架，AI 负责解释、增强、包装和节奏。

【一题多形规则】
一个触发点只强制确定一个主形式。
只有当它同时具备传播价值和收藏价值时，才建议一题多形。

【输出格式】
1. 内容核心作用：
2. 主形式：具体到图文 / 视频子类型
3. 推荐平台版本：短冲击 / 解释收藏 / 深度拆解
4. 推荐时长 / 页数：
5. 是否建议衍生形式：是 / 否
6. 衍生形式：如果有，说明图文 / 视频如何分工
7. 不适合的形式：至少 1 个，并说明为什么
8. 选择理由：用 3 句话说明
9. 脚本写作要求：告诉节点 2 应该怎么写
10. 需要素材：截图 / 实景 / 录屏 / 口播 / 结构图 / AI 画面 / 旁白
```

### 人工交接点 1.5

创作者确认：

```text
1. 主形式是否合理？
2. 是否真的需要一题多形？
3. 这个形式是否现实可执行？
```

## 节点 2：Script_Agent（按主形式生成脚本）

### 作用

根据节点 1.2 和 1.5 的结果生成脚本。  
它不是固定写 45-60 秒短视频脚本，而是按平台、形式、用户状态来写。

### 系统提示词

```text
你是 HEL 内容体系的编导。
你的任务是根据“平台前置校验”和“内容形式决策”生成对应形式的内容脚本。

【输入】
推荐选题：{{topic_output}}
平台前置校验：{{platform_expression_output}}
内容形式决策：{{content_format_decision}}
脚本写作要求：{{script_requirements}}
补充背景：{{source_context}}
隐私边界：{{privacy_boundary}}

【共同要求】
1. 全程说人话，不输出底层模型术语。
2. 必须贴近真实触发点，不要泛泛而谈。
3. 不要编造事实、客户、数据、经历。
4. 如果缺少具体素材，就用“可替换素材位”标注。
5. Hook 必须口语化，不要像论文标题。
6. 必须遵守平台前置校验里的观看者画像和非目标表达。
7. 视频时长按平台版本来，不固定套模板。

【如果主形式是图文】
输出：
1. 标题 5 个
2. 封面文案 3 个
3. 图文页结构：第 1 页到第 N 页
4. 每页主标题
5. 每页正文
6. 每页画面建议
7. 收藏理由
8. 评论区引导问题

【如果主形式是视频】
输出：
1. 平台版本
2. 推荐时长
3. 完整旁白 / 口播
4. 分镜表：序号 | 时间 | 画面 | 旁白/口播 | 字幕/花字 | 音效/转场
5. 前 3 秒 Hook
6. 共鸣段
7. 反转 / 判断段
8. 具体方法段
9. 结尾互动

【如果建议一题多形】
额外输出：
1. 主内容版本
2. 衍生图文版本结构
3. 衍生短视频版本结构
4. B站或视频号延展方向
```

### 人工交接点 2

创作者重点检查：

```text
1. Hook 是否像真人说话？
2. 是否说中了这个人真实状态？
3. 有没有违背平台前置校验？
4. 有没有把底层术语拿到表面？
5. 脚本是否真的服务于选定形式？
```

## 节点 2.5：Format_Review（脚本后形式复核）

### 作用

脚本生成后，再检查一次形式是否仍然成立。

### 系统提示词

```text
你是 HEL 内容体系的脚本后形式复核员。
请根据已经生成的脚本，判断当前形式是否仍然匹配。

【输入】
原始触发点：{{trigger_input}}
推荐选题：{{topic_output}}
平台前置校验：{{platform_expression_output}}
原定内容形式：{{content_format_decision}}
脚本内容：{{script_output}}
目标平台：{{target_platform}}

【复核问题】
1. 没有画面，这条内容还成立吗？
2. 用户看完是否需要收藏？
3. 内容是否需要展示过程？
4. 内容靠观点打动，还是靠画面打动？
5. 内容是否抽象，需要结构图或桌面推演辅助？
6. 这条内容更需要信任，还是更需要效率？
7. 平台时长是否合理？
8. 是否需要做一题多形？

【输出格式】
1. 是否维持原形式：是 / 否
2. 如果否，建议改成什么形式：
3. 修改理由：
4. 脚本需要调整的地方：
5. 是否建议一题多形：是 / 否
6. 最终锁定形式：
7. 给节点 3 的成品包要求：
```

### 人工交接点 2.5

创作者最后拍板：

```text
维持原形式 / 改形式 / 做一题多形
```

## 节点 3：Creative_Assets_Generation（图文 / 视频成品包生成）

### 作用

根据最终锁定形式，生成可以进入制作或半自动生成的成品包。

注意：

```text
本节点不是只输出建议。
它要尽可能输出“可制作成品包”。
```

---

### A. 图文分支

#### A1：小红书多图笔记 / 收藏卡

输出：

```text
1. 图文页数
2. 每页标题
3. 每页正文
4. 每页视觉版式
5. 每页配图提示词
6. 每页留白区说明
7. 封面文案
8. 发布正文
9. 标签
10. 评论区引导
```

#### A2：中性实用决策板风格

适合：

```text
工具选择
路径判断
方法清单
流程拆解
任务对应表
```

输出必须符合：

```text
白底 / 米白底
深灰字
墨绿或橄榄绿强调
少量淡黄色高亮
人物弱化
结构优先
每页只讲一个判断点
```

---

### B. 视频分支

#### B1：V1 实拍原生型

适合：

```text
探家
现场观察
材料质感
施工问题
客户真实反应
生活现场
```

输出：

```text
1. 口播 / 旁白脚本
2. 分镜
3. 拍摄清单
4. 需要补拍的现场素材
5. 剪辑节奏
6. 字幕花字
7. 封面
8. 标题 / 文案 / 标签
```

说明：V1 可以输出拍摄清单，但拍摄清单不是终点，终点仍是可发布视频。

#### B2：V2 AI 生成型

适合：

```text
抽象焦虑
工具过载
判断系统缺失
空间 / 情绪 / 认知机制可视化
无真人拍摄需求的解释型内容
```

输出：

```text
1. 完整旁白
2. 分镜表
3. 每个镜头 AI 画面提示词
4. 字幕花字
5. 转场节奏
6. BGM 情绪
7. 封面图提示词
8. 标题 / 文案 / 标签
9. 平台注意事项
10. 优先素材测试镜头
```

禁止把 V2 输出成：

```text
拍摄清单
真人口播建议
现场素材建议
```

如果没有真人需求，就直接走 AI 画面成品执行包。


## 节点 5：Feedback_Loop（发布复盘与触发点回流）

> 没有发布数据，不算验证。  
> 没有复盘，系统只是内容加工机；有复盘，系统才会变成自己的内容判断系统。

### 触发时机

发布 48-72 小时后，手动触发。

### 输入变量

| 变量名 | 类型 | 说明 |
|---|---|---|
| `published_link` | Text | 已发布内容链接，可选 |
| `comment_highlights` | Paragraph | 3-5 条代表性评论 |
| `data_metrics` | Paragraph | 播放 / 阅读 / 完播率 / 点赞 / 收藏 / 评论 |
| `creator_reflection` | Paragraph | 创作者自己的复盘感受 |

### 系统提示词

```text
你是 HEL 内容体系的数据复盘员。
请根据发布数据、评论和创作者复盘，判断这条内容是否值得继续延展。

【数据诊断规则】
- 完播率低：前 3 秒 Hook 可能不准，或表达太绕。
- 收藏率高：说明它有工具价值、判断价值或清单价值。
- 评论率高：说明它触发了共鸣或争议。
- 转发高：说明它说出了某类人想替别人表达的话。
- 评论里出现新场景：提取为下一轮触发点。

【输出格式】
1. 本期诊断：一句话
2. 数据亮点：
3. 数据问题：
4. 最值得保留的表达：
5. 下一轮触发点：1-3 个
6. 是否建议做成系列：是 / 否，理由
7. 是否值得沉淀为 OBS：是 / 否，理由
8. 如果沉淀为 OBS，建议标题：
```

### 人工动作

```text
1. 只输入真实评论和真实数据。
2. 只把被验证有长期价值的触发点沉淀为 OBS。
3. 不让 AI 编造数据和用户反馈。
```

## 六、人机分工总表

| 节点 | 人的动作 | AI 的动作 | 关键把控点 |
|---|---|---|---|
| 节点 0 | 提供真实触发点，说明隐私边界 | 无 | 触发点必须真实 |
| 节点 1 | 拍板最终选题 | 用底层模型推演痛点和选题 | AI 不能编造经历 |
| 节点 1.2 | 确认平台、受众、表达边界 | 判断平台调性、观看者、转译方式 | 不把底层术语拿到表面 |
| 节点 1.5 | 确认主形式和衍生形式 | 判断图文 / 视频 / 一题多形 | 形式服务内容作用 |
| 节点 2 | 修改 Hook 和金句 | 按锁定形式生成脚本 | 金句必须有人味 |
| 节点 2.5 | 最终锁定形式 | 复核脚本与形式是否匹配 | 不让好脚本配错形式 |
| 节点 3 | 审核素材和视觉真实性 | 输出图文 / 视频成品包 | 不能过度 AI 感 |
| 节点 4 | 按执行包制作和发布 | 整理最终执行包 | 可执行，而不是只好看 |
| 节点 5 | 输入真实数据和评论 | 诊断效果、提取新触发点 | 没有数据不算验证 |

## 七、TP-001 应用样例

触发点：

```text
AI 工具越多，我反而越不知道怎么开始。
```

v4 判断：

```text
平台版本：抖音 / 小红书通用短视频测试版
推荐时长：30-45 秒
观看者：已经被 AI 工具搞焦虑、怕落后、想开始但不知道先学哪个的人
核心表达：先判断任务，再选择工具
非目标表达：不做工具大全，不做底层理论课，不制造逆袭焦虑
人话转译：你不是不会用 AI，是你还没想清楚现在要解决内容、代码，还是流程
内容作用：先共鸣，再给判断入口
主形式：V2 AI 生成型视频
衍生形式：小红书 5 页收藏卡
```

执行方向：

```text
视频负责抓焦虑和传播。
图文负责收藏和方法沉淀。
```

## 八、一句话标准

```text
不是先写完整 OBS，也不是脚本写完随便选形式。
而是：一句触发点 → 选题 → 平台与表达校验 → 形式决策 → 按形式写脚本 → 脚本后复核 → 成品执行包 → 发布复盘 → 有价值再沉淀。
```

HEL 的工作流目标不是“自动生成很多内容”，而是：

```text
把你的真实判断，稳定转译成可发布、可复盘、可生长的内容。
```
