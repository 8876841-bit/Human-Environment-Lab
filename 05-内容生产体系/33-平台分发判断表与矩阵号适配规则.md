# 33｜平台分发判断表与矩阵号适配规则

> 适用范围：Human-Environment-Lab 内容生产体系
>
> 适用对象：选题是否发布到小红书、抖音、视频号、B站，以及是否进入矩阵栏目 / 矩阵账号
>
> 核心目的：避免“一个选题全平台硬发”，改为“先判断主战场，再做平台改写”。

---

## 0. 第一性原理

内容矩阵不是多发几个账号。

内容矩阵的底层问题是：

```text
1. 这个话题最适合被谁看见？
2. 用户在这个平台上为什么愿意停？
3. 这个平台适合收藏、完播、信任，还是深度沉淀？
4. 这个话题适不适合被改写到其他平台？
5. 哪些平台暂时不值得发？
```

所以，HEL 不默认一个内容全平台搬运。

HEL 默认先判断：

```text
主平台
可适配平台
切片平台
暂不发布平台
```

---

## 1. 平台分发四级标准

以后每个选题都按 S / A / B / C 四级判断。

```text
S级：主战场
必须认真做完整版本。该平台最适合这个话题的用户动作和信任入口。

A级：适配后可发
不能直接搬运，要根据平台语气、节奏、结构改写。

B级：只做切片 / 引流 / 简化版
不适合完整展开，但可以截取一个点做短内容或入口内容。

C级：暂时不发
平台调性、用户动机或内容风险不匹配，先不发布。
```

## 2. 当前平台角色

## 2.1 小红书

```text
角色：主阵地
适合：收藏、生活方式、方法卡、图文视频混合、案例参考、经验判断
核心动作：收藏 / 评论 / 私信 / 复看
内容气质：真实、生活化、可执行、像经验分享
```

小红书适合：

```text
方法卡
判断表
案例拆解
生活方式
装修避坑
AI 使用方法
服务前置教育
```

---

## 2.2 抖音

```text
角色：强钩子测试场
适合：冲突、反差、短平快、强开头、问题刺痛
核心动作：停留 / 完播 / 评论 / 转发
内容气质：短句、直接、反转、节奏快
```

抖音适合：

```text
强问题
强反转
一个坑点
一个判断
一个情绪瞬间
一个短方法
```

---

## 2.3 视频号

```text
角色：信任沉淀与熟人传播
适合：稳重经验、真实生活、服务可信、熟人可转发内容
核心动作：转发 / 信任 / 私信 / 长尾触达
内容气质：稳、可信、不浮夸、适合熟人关系链
```

视频号适合：

```text
生活经验
真实转型
服务说明
专业建议
适合发给朋友/同事/家人的内容
```

---

## 2.4 B站

```text
角色：深度系统与过程复盘
适合：长内容、方法论、案例复盘、系列教程、底层逻辑
核心动作：关注 / 收藏 / 投币 / 长期信任
内容气质：解释充分、结构完整、能被追问
```

B站适合：

```text
深度拆解
完整案例复盘
系统教程
方法论展开
反例与边界讨论
```

## 4. 平台适配闸门

每个选题进入脚本生成前，必须先过平台适配闸门。

必须填写：

```text
选题：
母线：
信任入口：
生产方式：A / B / C
载体：视频 / 图文 / 长文 / 直播 / 服务页
主平台：
可适配平台：
切片平台：
暂不发布平台：
原因：
平台版本差异：
```

没有过这个闸门，不进入脚本生成。

---

## 5. 平台版本差异规则

同一个选题，不能同稿全平台发。

必须至少调整：

```text
1. 开头钩子
2. 语气
3. 信息密度
4. 例子数量
5. 结尾动作
6. 标题和封面
7. 评论区引导
```

---

## 6. 各平台改写方向

## 6.1 小红书改写方向

```text
更像真实经验分享
突出可收藏、可复看、可照着做
多用“我发现”“先别急”“这张卡可以收藏”
不要太像课程广告或机构报告
```

适合结构：

```text
问题共鸣
↓
判断卡
↓
例子
↓
模板
↓
评论区交作业
```

---

## 6.2 抖音改写方向

```text
前三秒更强
短句更密
反转更明显
画面节奏更快
一条只讲一个核心判断
```

适合结构：

```text
刺痛句
↓
反转句
↓
三步方法
↓
评论动作
```

---

## 6.3 视频号改写方向

```text
语气更稳
减少刺激感
增加经验感和可信度
适合转发给熟人
不要过度网感
```

适合结构：

```text
常见现象
↓
稳重判断
↓
简单方法
↓
适合转发的结尾
```

---

## 6.4 B站改写方向

```text
补充背景
解释模型
展开边界
加入反例
适合做系列
```

适合结构：

```text
问题背景
↓
模型提出
↓
为什么成立
↓
案例和反例
↓
边界
↓
下一集入口
```

## 7. TP-001 平台判断样例

## 7.1 基本信息

```text
选题：AI 工具越多，反而不知道怎么开始
母线：AI 认知秩序
信任入口：系统能力入口 / 情绪视觉入口
生产方式：B2 图文 + C1 纯 AI 视频
载体：小红书图文 / 纯 AI 短视频 / 平台改写脚本
```

## 7.2 平台等级

```text
小红书：S级
抖音：A级
视频号：A级
B站：B级 / A级
```

## 7.3 原因

```text
小红书：适合判断卡、收藏、评论交作业。
抖音：适合强反转短视频，测试“你不是不会用 AI，是一开始就问错了”。
视频号：适合稳重经验版，方便熟人转发。
B站：如果只做 30 秒短片则 B级；如果扩展成“为什么普通人用 AI 要先分任务”的深度解释，则 A级。
```

## 7.4 平台版本差异

```text
小红书：判断卡 / 收藏版
抖音：强反转 / 短视频版
视频号：稳重经验 / 熟人转发版
B站：底层逻辑 / 深度解释版
```

---

## 8. 矩阵号与栏目关系

前期不急着开很多账号。

先把信任入口作为栏目存在：

```text
真实空间档案
缝合怪木作中转站
Human-Environment-Lab
情绪漫画 / AI 视觉寓言
主理人转型日记
```

等某一类内容稳定后，再考虑独立账号。

判断是否独立开号，要看：

```text
1. 是否有稳定选题池
2. 是否有独立受众
3. 是否有独立转化目标
4. 是否能持续更新
5. 是否不会稀释主账号信任
```

---

## 9. 禁止事项

```text
1. 一个选题不判断平台，直接全平台发。
2. 小红书稿直接搬到抖音。
3. 抖音强冲突稿直接搬到视频号。
4. B站深度稿硬剪成碎片却没有完整逻辑。
5. 商业服务内容在抖音直接硬卖。
6. AI 视觉寓言没有解释层就发 B站。
7. 所有内容都想同时完成收藏、完播、转化、深度信任。
```

---

## 10. 最终原则

```text
平台不是终点，是筛选器。
矩阵不是多账号，是多入口。
不是所有话题都适合所有平台。
不是所有平台都值得发完整版本。
```

HEL 的平台策略是：

```text
先判断主战场。
再做平台改写。
能发则发。
不适合就不发。
不为了矩阵而矩阵。
```
