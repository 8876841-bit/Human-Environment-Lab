# 20-AI视频生成工作流规则

> 本文件用于沉淀 HEL 内容生产体系中的 AI 视频生成执行规则。  
> 来源：对《从第一性原理出发解析 AI 代理辅助短视频剪辑的底层逻辑》的借鉴转化。  
> 核心用途：避免“一句话出片”的幻觉，把视频生成拆成可审查、可测试、可复用的工作流。

---

## 一、核心判断

AI 视频生成的本质，不是模型突然会剪片。

它更接近：

```text
把创作中可形式化的部分结构化，
再把搜索、执行和校验自动化。
```

所以视频生成前，不能只写一句：

```text
帮我生成一条高级感短视频。
```

而必须先准备：

```text
目标
素材
分镜
每帧语义
时长
镜头规则
人物一致性规则
禁止事项
验收标准
```

一句话标准：

```text
先结构化，再生成。
先审分镜，再出片。
先跑候选，再选方向。
```

---

## 二、AI 视频工作流六层

AI 视频生成至少拆成六层。

```text
1. 目标层：这条视频要完成什么任务？
2. 表示层：把素材和脚本变成分镜、镜头标签、时间轴。
3. 搜索层：生成多个候选方案，而不是一次定终版。
4. 执行层：调用视频生成、剪辑、字幕、导出工具。
5. 验收层：人工检查人物、逻辑、节奏、内容、平台适配。
6. 约束层：处理版权、隐私、平台规则、AIGC标识等问题。
```

对 HEL 当前阶段来说，重点先抓三层：

```text
表示层
搜索层
验收层
```

也就是：

```text
分镜写清楚
多跑候选版本
人工用清单验收
```

## 三、视频生成输入包

每条视频进入即梦、可灵、Runway、Pika、剪映、Remotion 或其他工具前，必须先准备一个最小输入包。

## 最小输入包模板

```text
【视频生成输入包】

1. 主题：
2. 目标平台：抖音 / 小红书 / 视频号 / B站 / 多平台测试
3. 目标时长：
4. 主形式：实拍 / AI生成 / 混合增强
5. 关键帧素材：
6. 每帧语义：
7. 每帧时长：
8. 口播稿：
9. 字幕稿：
10. 统一人物/场景规则：
11. 允许变化：
12. 禁止事项：
13. 验收标准：
14. 是否需要 AIGC 标识：
15. 当前状态：测试 / 候选 / 待复盘 / 可发布
```

如果没有这个输入包，不进入视频生成。

## 四、TP-001 输入包示例

主题：

```text
AI 工具越多，反而不知道怎么开始。
```

目标平台：

```text
抖音 / 小红书通用测试
```

目标时长：

```text
20 秒测试版
35 秒正式测试版
```

关键帧：

```text
S1 混乱入口
S2 摇摆选择
S3 认知反转
S4 三类判断
S5 工具对应
S6 行动收束
```

每帧语义：

```text
S1：AI工具和教程入口太多，用户被信息包围。
S2：看到不同工具都想学，人物在选择之间摇摆。
S3：认知反转：不是工具不够，是任务没分清。
S4：给出三类判断：写东西 / 做东西 / 重复干活。
S5：不同任务对应不同工具。
S6：先写清任务，再选择一个工具开始。
```

统一规则：

```text
同一人物
同一脸型
同一发型
同一服装
同一内容世界
同一灯光与色调
同一核心道具体系
```

允许变化：

```text
镜头远近
拍摄角度
人物动作
空间局部
信息密度
信息层内容
```

禁止事项：

```text
不要换脸
不要换人物
不要换发型
不要换衣服
不要突然换成完全不同场景
不要变成科幻风
不要变成课程宣传片
不要出现大量真实软件 Logo
不要出现大量乱码文字
不要过度转场
不要强烈抖动
```

## 五、先审分镜，再出片

错误流程：

```text
有几张图
↓
直接丢进视频生成工具
↓
看 AI 发挥
```

正确流程：

```text
真实触发点
↓
脚本
↓
分镜
↓
关键帧
↓
每帧语义
↓
视频生成输入包
↓
候选视频
↓
人工验收
↓
再决定是否细修
```

重点：

```text
如果每一帧承担的语义不清楚，视频生成工具只会做画面过渡，不会做内容表达。
```

## 六、候选版本规则

AI 视频生成不追求一次成片。

当前阶段建议：

```text
同一组素材
同一套输入包
跑 2-3 个候选版本
```

每个候选只验收核心问题，不抠细节。

候选版本先看：

```text
1. 人物有没有明显漂移？
2. 是否像同一个内容世界？
3. 是否从混乱走向清晰？
4. 三类判断是否能看懂？
5. 是否适合继续加口播、字幕、BGM？
```

不在候选阶段过度纠结：

```text
手指小问题
局部文字不准
表格小字不清
微小道具变化
局部光影瑕疵
```

但如果出现以下问题，直接判为不通过：

```text
人物换了
场景跳了
主题看不懂
逻辑顺序反了
画面严重失真
信息完全乱码
情绪从混乱到清晰的过程不存在
```

## 七、视频生成验收清单

每条 AI 视频生成后，先按这张清单验收。

```text
1. 人物是否一致？
2. 场景是否属于同一个内容世界？
3. 画面是否有语义推进，而不是单纯图片在动？
4. 开头是否能在 3 秒内说中问题？
5. 中段是否有认知反转？
6. 方法部分是否能一眼看懂？
7. 结尾是否有明确行动？
8. 是否存在明显乱码、错字、畸形、崩坏？
9. 是否适合加口播和字幕？
10. 是否适合当前平台？
```

通过标准：

```text
前 7 条基本成立，可以进入后期包装。
前 5 条不成立，直接重跑。
```

## 八、不要把复杂系统提前做大

当前阶段不要急着做：

```text
多代理自动剪辑系统
全自动发布系统
复杂合规系统
大型风格参数库
多平台批量生成
复杂数据回流系统
```

当前只做：

```text
一条视频
一个触发点
一组关键帧
一个输入包
2-3 个候选版本
一次人工验收
一次发布复盘
```

跑通以后再扩。

## 九、视频生成和剪辑工具的分工

视频生成工具负责：

```text
让关键帧动起来
补充轻微镜头运动
生成自然过渡
制造画面连续性
```

剪辑工具负责：

```text
口播
字幕
BGM
节奏微调
转场精修
封面
导出规格
平台适配
```

不要期待视频生成工具一次完成所有事情。

正确分工：

```text
AI视频生成：负责画面候选
剪辑软件：负责最终包装
人工：负责判断和取舍
```

## 十、平台与合规提示

如果视频用于公开发布，需要注意：

```text
1. 是否使用真实人物照片或高度相似人物形象？
2. 是否需要获得授权？
3. 是否涉及平台不建议的夸大收益话术？
4. 是否需要 AIGC 标识？
5. 是否存在误导用户以为是真实拍摄的风险？
```

对外发布时，不要使用：

```text
学会这个就逆袭
普通人靠这个暴富
一条视频改变命运
不学就会被淘汰
```

可使用：

```text
先跑一个测试版
先验证流程能不能成立
先看这条内容是否能被理解
先用真实数据再决定是否放大
```

## 十一、与 HEL 主线的关系

AI 视频生成不是单独的技术尝试。

它属于 HEL 内容生产闭环中的一环：

```text
真实触发点
↓
第一性原理锚点
↓
平台转译
↓
形式决策
↓
图文 / 视频成品包
↓
视频生成测试
↓
人工验收
↓
发布
↓
复盘
```

它不能反过来支配内容。

也就是说：

```text
不是因为工具能生成视频，所以我们就做视频。
而是因为这个触发点适合视频表达，所以才调用视频生成工具。
```

---

## 十二、最终原则

```text
不要采购“会剪视频的 AI”神话。
要建设“可审查的视频工作流”。
```

真正的竞争力不是找到一个更神奇的模型，而是：

```text
目标定义足够清楚
素材组织足够稳定
分镜表示足够可审查
工具链足够可执行
人工验收足够硬
复盘机制足够真实
```

最后标准：

```text
如果视频只是动了，它不算跑通。
如果视频能把真实触发点从混乱讲到清楚，才算跑通。
```
