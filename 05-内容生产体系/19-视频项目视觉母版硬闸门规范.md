# 19｜视频项目视觉母版硬闸门规范

> 版本：V1  
> 状态：已沉淀为内容生产硬规则  
> 适用范围：所有视频项目、关键帧测试、AI 画面生成、animatic 粗剪前检查  
> 核心结论：**视觉母版不是审美偏好，而是视频连续性的总开关。**

---

## 一、为什么必须有视觉母版？

视频不是一组好看的单张图。

视频的第一性原理是：

```text
连续画面
+
时间推进
+
观众认知变化
```

一张图可以独立好看，但视频要求每一帧都能回答：

```text
它为什么接在上一镜头后面？
它为什么能推到下一镜头？
它如何推动用户从一个状态进入另一个状态？
```

如果没有视觉母版，就会出现：

```text
第一张像摄影封面
第二张像手绘插画
第三张像 PPT 信息图
人物一直换
空间一直换
色彩一直换
单张都不错，但成片不成立
```

所以视觉母版不是“画面风格建议”，而是视频是否可剪辑、可连续、可发布的前置条件。

---

## 二、从第一性原理拆解视觉母版

### 1. 视频需要连续性

连续性不是只有故事连续，还包括：

```text
人物连续
空间连续
色彩连续
画面语言连续
字幕样式连续
UI / 卡片系统连续
情绪推进连续
```

如果这些不连续，用户会感觉：

```text
这不是同一条视频。
```

即使主题相同，也会像临时拼接的素材。

---

### 2. 视觉系统承载账号识别

HEL 不是一次性视频，而是长期内容系统。

长期内容系统需要让用户逐渐建立识别感：

```text
我一看这个画面，就知道这是这个账号的表达方式。
```

所以视觉母版分两层：

```text
母线系列视觉母版
+
单个项目视觉母版
```

单个项目不能随意发明风格，必须继承所属母线的系列视觉。

---

### 3. 形式必须服务内容任务

视觉不是为了“好看”，而是为了帮用户完成认知变化。

例如 TP-001 的用户变化是：

```text
我很乱
↓
原来不是我笨
↓
是我任务没分清
↓
我可以先判断：写东西 / 做东西 / 重复干活
```

所以它需要的不是科技大片，也不是手绘治愈图，而是：

```text
从混乱到清楚的可视化过程。
```

---

## 三、HEL 的四层视觉结构

所有视频项目必须遵守四层结构：

```text
HEL 总视觉气质
↓
8 条话题母线的系列视觉母版
↓
单个项目的视频视觉母版
↓
单张关键帧 / 镜头画面
```

### 1. HEL 总视觉气质

所有母线共享：

```text
真实
清楚
克制
有判断
不炫技
不空泛
不装腔
不制造无意义焦虑
```

### 2. 8 条话题母线系列视觉母版

每条母线拥有自己的视觉系列。

### 3. 单个项目视觉母版

每个视频项目在生成关键帧前，必须从所属母线继承视觉规则，再锁定项目级人物、空间、色彩、镜头、UI 等。

### 4. 单张关键帧

关键帧不是海报。关键帧必须属于同一个项目视觉母版，并能连接前后镜头。

## 五、视频项目视觉母版硬闸门流程

所有视频项目必须按这个顺序执行：

```text
触发点
↓
平台判断
↓
时长判断
↓
脚本适配
↓
导演 Brief
↓
判断所属母线
↓
调用母线系列视觉母版
↓
锁定项目视觉母版
↓
视觉母版硬闸门检查
↓
关键帧测试
↓
animatic 粗剪
↓
正式视频生成
↓
剪辑发布
```

硬规则：

```text
没有视觉母版，不允许生成关键帧。
视觉母版不通过，不允许进入 KF02 / KF03。
```

## 六、视觉母版必须锁定的 8 个字段

### 1. 人物模板

必须写清：

```text
主角是谁？
是否出现人物？
是否固定同一人？
性别 / 年龄感？
服装？
发型？
视角：正脸 / 侧脸 / 背影 / 半背影？
是否允许换人？
```

没有锁人物时，AI 很容易每张图换一个人。

---

### 2. 空间模板

必须写清：

```text
主要空间是什么？
家庭书桌 / 办公桌 / 客厅 / 玄关 / 现场 / 城市？
光线环境？
背景元素？
桌面 / 环境复杂度？
是否允许换场景？
```

没有锁空间时，关键帧之间会像不同视频。

---

### 3. 画面语言模板

必须先选主画面语言：

```text
真实摄影感
插画感
信息图感
3D 感
混合风格
```

硬规则：

```text
同一条视频默认只能有一个主画面语言。
除非明确设定“双世界结构”，否则不允许摄影、手绘、PPT、科技风乱跳。
```

---

### 4. 色彩模板

必须写清：

```text
主色
辅助色
强调色
背景色
禁止色
```

色彩是账号识别和镜头连续性的重要部分。

---

### 5. 字幕与文字模板

必须写清：

```text
字体气质
每屏最大文字量
标题位置
重点词高亮方式
禁止文字样式
```

文字不是越多越清楚。短视频里：

```text
每屏只保留一个核心句。
```

---

### 6. UI / 卡片系统模板

如果画面包含 UI 浮层、工具卡片、判断卡片，必须锁定：

```text
卡片形状
圆角
阴影
线框
图标风格
是否使用真实 Logo
卡片文字量
卡片颜色
```

UI 系统不统一，视频会直接散掉。

---

### 7. 镜头变化规则

必须区分：

```text
哪些元素必须保持不变？
哪些元素允许变化？
```

常见固定项：

```text
人物
空间
色彩
画面语言
字幕样式
UI 卡片样式
```

常见可变项：

```text
卡片数量
信息密度
镜头远近
人物动作
画面秩序
字幕内容
```

---

### 8. 转场逻辑模板

关键帧必须提前写清：

```text
KF01 怎么进入 KF02？
KF02 怎么进入 KF03？
```

没有转场逻辑，关键帧就是独立海报。

---

## 七、关键帧生成前检查表

生成任何关键帧前，必须确认：

```text
1. 所属母线已确定
2. 系列视觉母版已确定
3. 项目视觉母版已锁定
4. 人物是否一致已写清楚
5. 空间是否一致已写清楚
6. 画面语言是否一致已写清楚
7. 色彩系统是否一致已写清楚
8. 字幕系统是否一致已写清楚
9. UI / 卡片系统是否一致已写清楚
10. KF01 → KF02 → KF03 的转场逻辑已写清楚
```

只要有一项没有完成：

```text
不允许生成关键帧。
```

---

## 八、关键帧验收规则

每张关键帧生成后，必须回答：

```text
1. 它继承了哪条母线的视觉母版？
2. 它有没有延续项目视觉母版？
3. 人物是否一致？
4. 空间是否一致？
5. 画面语言是否一致？
6. 色彩是否一致？
7. UI / 卡片系统是否一致？
8. 它为什么能接在上一镜头后面？
9. 它为什么能接到下一镜头？
10. 它是否服务这条内容的核心表达？
```

如果只是单张好看，但不能接进整条视频：

```text
判废。
```

---

## 九、硬性禁止

```text
禁止没有视觉母版就生图。
禁止同一条视频里人物随意变化。
禁止同一条视频里摄影、插画、PPT、科技风乱跳。
禁止只评价“这张图好不好看”。
禁止关键帧变成独立海报。
禁止关键帧不考虑前后镜头关系。
禁止把母线视觉和项目视觉混在一起不区分。
禁止因为某张图漂亮就破坏项目连续性。
```

## 十、TP-001 示例：AI 认知秩序母线

TP-001 属于：

```text
AI 认知秩序
```

它继承的母线系列视觉母版：

```text
浅色真实桌面
电脑屏幕
UI 浮层
决策卡片
任务分类
从混乱到清楚
```

TP-001 项目视觉母版：

```text
人物：同一个年轻人，灰色卫衣，背影 / 半背影，不换人
空间：同一个家庭办公桌，电脑前，桌面略乱但可读
画面语言：真实摄影感 + 少量清晰 UI 浮层
色彩：米白 / 浅灰 / 深灰 / 墨绿 / 少量黄色
文字：大字少字，每屏一个核心句
UI：白色圆角卡片，轻阴影，简洁可读
镜头变化：从工具弹窗混乱 → 任务分清 → 三张卡片完整展开
禁止：不换人物、不换空间、不换风格、不突然变手绘、不做 PPT 说明页、不做黑色科技风
```

KF01 / KF02 / KF03 的连续逻辑：

```text
KF01：工具卡片很多，用户不知道先学哪个。
↓
KF02：卡片冻结，中央出现反转句：不是你不会，是任务没分清。
↓
KF03：工具卡片退后，三张任务卡清晰出现：写东西 / 做东西 / 重复干活。
```

## 十一、一句话原则

```text
视觉母版不是为了统一好看，
而是为了保证内容能从一张图推进到下一张图，
从一个判断推进到下一个判断，
最终形成一条真正可剪辑的视频。
```
