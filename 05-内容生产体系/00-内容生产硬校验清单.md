# 内容生产硬校验清单

> 本文件是 HEL 内容生产体系的总闸门。  
> 所有触发点、选题、图文、视频、Dify 节点、发布包，都必须先过这张清单。  
> 它的作用不是增加流程负担，而是防止内容越做越多以后偏离主线。

---

## 一、使用位置

这张清单用于：

```text
触发点进入选题前
选题进入脚本前
脚本进入图文 / 视频成品包前
成品进入发布前
复盘沉淀 OBS 前
```

在 Dify 工作流中，它应挂载到：

```text
节点 1：Topic_Agent
节点 1.2：Platform_Expression_Preflight
节点 1.5：Content_Format_Decision
节点 2：Script_Agent
节点 2.5：Format_Review
节点 4：Final_Assembly_Publish_Package
```

---

## 二、一级硬校验：真实触发点

每条内容必须来自真实触发点。

### 必须回答

```text
1. 这句话是不是来自真实感受 / 真实判断 / 真实现象？
2. 这是不是用户或我自己真的遇到的问题？
3. 这是不是只为了蹭热点而硬造出来的？
```

### 通过标准

```text
能说清它来自哪里。
能说清为什么现在要做它。
能说清它背后的人群和场景。
```

### 不通过

```text
只是看到热点后强行套。
只是工具名堆叠。
没有真实困惑，没有真实场景。
```

---

## 三、二级硬校验：底层逻辑 / 第一性原理

HEL 不是简单追平台热点。  
每条内容必须有内部判断依据。

### 必须回答

```text
1. 这条内容解释的底层规律是什么？
2. 它对应八条母线中的哪一条或哪几条？
3. 它是否能从“需求 × 行为 × 环境 × 系统”中找到位置？
4. 它是否只是表层观点，还是触及了某个可复用机制？
```

### 通过标准

```text
能写出一句“第一性原理锚点”。
能说明它不是单纯技巧，而是某种规律的外显。
```

### 示例

```text
触发点：AI 工具越多，我反而越不知道怎么开始。
第一性原理锚点：工具过载会破坏普通人的判断顺序。
平台表达：你不是不会用 AI，是还没想清楚现在要解决内容、代码，还是流程。
```

### 不通过

```text
只有平台热词。
只有工具清单。
只有情绪，没有判断。
只有底层词汇，但无法转成人话。
```

---

## 四、三级硬校验：平台规则 / 平台调性

内容不能只在逻辑上正确，也要适合发布平台。

### 必须回答

```text
1. 这条内容首发平台是什么？
2. 这个平台更吃情绪、方法、真实感、过程，还是深度？
3. 这个平台适合多长？
4. 这个平台有什么表达风险？
```

### 基本判断

```text
抖音 / 快手：短、强、快，前 3 秒必须抓住问题。
小红书：具体、可收藏、可复用，标题封面要明确。
视频号：克制、可信、适合熟人传播，不要太夸张。
B站：可以讲深，但必须从真实困惑进入，逻辑链要完整。
```

### 不通过

```text
拿小红书收藏型内容直接发抖音。
拿抖音强钩子直接做 B站长视频。
视频时长固定套 45-60 秒。
不检查夸大收益、制造焦虑、隐私、版权风险。
```

---

## 五、四级硬校验：谁在看

不能写给“所有人”。

### 必须回答

```text
1. 这个内容到底给谁看？
2. 他现在是什么状态？
3. 他为什么会停下来？
4. 他看完要得到什么？
```

### 通过标准

```text
能描述一个具体人群。
能说出他们当下的焦虑、卡点、期待。
```

### 不通过

```text
受众写成“大众”“普通人”“所有学习 AI 的人”。
只写年龄，不写状态。
只写身份，不写他们为什么会被这条内容击中。
```

---

## 六、五级硬校验：表达什么 / 不表达什么

每条内容都必须有边界。

### 必须回答

```text
1. 这条内容真正要表达什么？
2. 它不表达什么？
3. 它不应该被误解成什么？
```

### 示例

```text
要表达：先判断任务，再选择工具。
不表达：AI 工具大全。
不表达：学会某个工具就能逆袭赚钱。
不表达：你必须同时学会所有工具。
```

### 不通过

```text
主题越写越大。
从一个触发点扩散成大而全课程。
为了吸引人说过度承诺。
```

---

## 七、六级硬校验：转译成人话

底层逻辑只做内部支撑，不能直接外显。

### 必须回答

```text
1. 这条内容的内部逻辑是什么？
2. 对外能不能用更普通的话说？
3. 有没有把术语直接端到平台表面？
```

### 转译标准

| 内部说法 | 对外表达 |
|---|---|
| 认知秩序缺失 | 你越看越乱，不知道先做哪一步 |
| 工具过载 | 工具太多，每个都想学，反而没开始 |
| 判断系统 | 先想清楚你要解决什么 |
| 任务分类 | 内容、代码、流程，你现在卡在哪一类 |
| 平台反噬 | 你以为自己在学习，其实被信息流带着跑 |

### 不通过

```text
直接说第一性原理、认知秩序、系统框架。
表达像论文、课程大纲、咨询报告。
用户听完觉得“好像很高级，但不知道跟我有什么关系”。
```

---

## 八、七级硬校验：形式服务内容

形式不是固定模板，而是服务内容任务。

### 必须回答

```text
1. 这条内容主要要抓情绪、讲清楚、让人收藏，还是建立信任？
2. 主形式是什么？
3. 是否真的需要一题多形？
```

### 判断规则

```text
情绪强、适合抓停留 → 视频优先
结构强、适合复用 → 图文优先
情绪强 + 方法强 → 视频主发，图文承接
真实现场强 → V1 实拍原生型 / V3 混合增强型
抽象机制强、无真人素材 → V2 AI 生成型
```

### 不通过

```text
每个触发点都默认图文 + 视频。
脚本写完才随便选形式。
图文页数越做越多但价值不增加。
视频时长固定套模板。
```

---

## 九、八级硬校验：成品导向

Dify 和 AI 的输出不能停在“建议”。

### 必须回答

```text
1. 这一步能不能进入制作？
2. 图文是否有页结构、文字、视觉说明？
3. 视频是否有旁白、分镜、画面提示词、字幕、转场、BGM、封面、文案？
4. 哪些部分还需要人工实拍、剪辑或审核？
```

### 通过标准

```text
图文能直接进入制图。
视频能直接进入素材测试或剪辑。
发布包包含标题、封面、文案、标签、评论引导、风险检查。
```

### 不通过

```text
只输出灵感。
只输出拍摄建议。
只输出脚本但没有分镜和执行说明。
把 Dify 当成直接剪辑工具。
```

---

## 十、九级硬校验：真实性与隐私

### 必须回答

```text
1. 有没有编造经历、用户反馈、数据、案例？
2. 有没有暴露客户、地址、账号、联系方式、隐私画面？
3. 有没有需要打码、模糊、删除的信息？
```

### 不通过

```text
AI 编造客户故事。
AI 编造发布数据。
AI 编造评论。
实拍素材泄露隐私。
```

---

## 十一、十级硬校验：复盘沉淀

发布后才算验证。

### 必须回答

```text
1. 有没有真实发布？
2. 有没有真实数据？
3. 有没有真实评论？
4. 这个触发点是否值得继续延展？
5. 是否值得沉淀为 OBS？
```

### 不通过

```text
没有发布就自称验证成功。
没有数据就沉淀成长期规律。
AI 编造反馈。
```

---

## 十二、发布前 12 项总检查

每条内容发布前必须检查：

```text
1. 触发点真实吗？
2. 第一性原理锚点清楚吗？
3. 平台和时长判断合理吗？
4. 受众是不是具体的人？
5. 要表达什么 / 不表达什么清楚吗？
6. 底层逻辑是否已经转成人话？
7. 主形式是否服务内容任务？
8. 是否真的需要一题多形？
9. 图文 / 视频是否已经进入成品执行包？
10. 是否有隐私、版权、夸大收益、制造焦虑风险？
11. 评论区问题是否能引导真实反馈？
12. 发布后如何复盘是否明确？
```

---

## 十三、一句话标准

```text
每条内容都必须：从真实触发点出发，用底层逻辑判断，按平台规则转译，最后生成可发布、可复盘的成品。
```
