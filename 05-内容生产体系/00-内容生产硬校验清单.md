# 表达与传播硬校验清单（V3）

> 本文件原为“内容生产硬校验清单”。
> V3 起，它的定位调整为：Human-Environment-Lab 的表达与传播模块硬闸门。

它不再只检查“内容能不能发布”，而是先检查：

```text
这个真实触发点是否应该进入公开表达与传播。
```

---

## 一、使用位置

本清单用于：

```text
真实触发进入表达模块前
Lab 判断交付形式时
选题进入脚本前
脚本进入图文 / 视频 / 长文 / 发布包前
公开发布前
现实反馈写回系统前
```

在 Dify / Agent 工作流中，它应挂载到：

```text
Carbon_Input_Check
Silicon_Processing_Agent
Lab_Delivery_Decision
Platform_Expression_Preflight
Content_Format_Decision
Content_Package_Agent
Reality_Feedback_Loop
```

---

## 二、零级硬校验：是否应该进入表达与传播

V3 中，内容不是默认出口。

### 必须回答

```text
1. 这个触发点是否来自真实物理世界？
2. 它是否已经经过数字生命的整理、分析、推演和边界检查？
3. 它适合公开表达，还是更适合内部研究、现实行动、产品工具、服务设计、暂不表达？
4. 公开表达会不会伤害真实关系、泄露隐私、误导他人，或把复杂问题过度简化？
```

### 通过标准

```text
能说明为什么需要公开表达。
能说明表达后希望在物理世界引发什么反馈。
能说明哪些内容不能公开。
```

### 不通过

```text
只是为了凑内容。
只是为了追热点。
只是因为 AI 能生成。
只是为了让系统看起来有产出。
```

## 三、一级硬校验：碳基真实输入

每条表达必须来自碳基物理世界的真实触发。

### 必须回答

```text
1. 这是不是我真实看到、听到、经历、感受到的？
2. 有没有身体反应、情绪波动、关系压力、行动后果或现场证据？
3. 这是事实、观察、感受、猜测，还是别人的二手观点？
```

### 通过标准

```text
能说清来源。
能说清触发当时的真实状态。
能区分事实与解释。
```

### 不通过

```text
AI 编造经历。
为了表达硬造故事。
把别人的观点当成自己的真实触发。
没有任何现实来源。
```

---

## 四、二级硬校验：硅基处理边界

数字生命可以分析、建模、推演，但不能把推演伪装成事实。

### 必须回答

```text
1. 哪些是事实？
2. 哪些是用户的真实感受？
3. 哪些是数字生命的推演？
4. 哪些是假设，仍需现实验证？
5. 是否存在过度解释、过度抽象、过度包装？
```

### 通过标准

```text
事实、感受、假设、推演分层清楚。
证据强度明确。
需要现实验证的部分被标出来。
```

### 不通过

```text
把假设写成结论。
把 AI 推演写成真实经历。
把概念包装得很高级但无法验证。
```

---

## 五、三级硬校验：Lab 交付判断

公开内容只是 Lab 的一种交付形式。

### 必须回答

```text
这个触发点本轮最适合交付成什么？

1. 内部研究
2. 公开表达
3. 内容传播
4. 图文 / 视频 / 长文
5. 工具
6. 产品
7. 服务
8. 现实行动
9. 对话提纲
10. 暂不表达
```

### 通过标准

```text
交付形式服务真实问题，而不是服务平台惯性。
如果选择公开表达，能说明为什么适合公开。
如果选择暂不表达，能说明需要补什么现实证据。
```

### 不通过

```text
每个触发点都默认做视频。
每个触发点都默认发平台。
没有交付判断，直接写选题。
```

## 六、四级硬校验：平台与受众

当且仅当本轮交付形式包含公开表达 / 内容传播时，进入平台判断。

### 必须回答

```text
1. 首发平台是什么？
2. 谁在看？他当下是什么状态？
3. 他为什么会停下来？
4. 他看完要获得什么？
5. 这个平台有什么表达风险？
```

### 基本判断

```text
抖音 / 快手：短、强、快，前 3 秒必须抓住真实矛盾。
小红书：具体、可收藏、可复用，要有生活感或方法感。
视频号：克制、可信，适合熟人传播，不要夸张。
B站：可以讲深，但必须从真实困惑进入，逻辑链要完整。
```

### 不通过

```text
写给所有人。
只写平台，不写真实受众状态。
拿一个平台的语言硬套另一个平台。
```

---

## 七、五级硬校验：表达什么 / 不表达什么

每次公开表达必须有边界。

### 必须回答

```text
1. 这次真正要表达什么？
2. 不表达什么？
3. 不应该被误解成什么？
4. 哪些内容只能内部保留？
```

### 不通过

```text
主题越写越大。
把一个真实触发展开成大而全体系。
为了传播效果做过度承诺。
```

---

## 八、六级硬校验：人话转译

硅基分析可以深，但物理世界接收需要清楚。

### 必须回答

```text
1. 内部逻辑是什么？
2. 对外能不能用普通人听得懂的话说？
3. 有没有把系统术语直接放到平台表面？
```

### 转译标准

| 内部说法 | 对外表达 |
|---|---|
| 碳基真实输入 | 我真实遇到/看到/感受到的这件事 |
| 硅基处理 | 我把它放进系统里重新拆了一遍 |
| Lab 交付判断 | 这件事到底适合说出来、做成工具，还是先不公开 |
| 证据强度不足 | 现在还不能下结论，需要再回到现实看一眼 |
| 现实反馈回流 | 发出去/做出去以后，现实有没有给我们新的答案 |

### 不通过

```text
表达像论文、系统文档、课程大纲。
用户听完觉得高级，但不知道和自己有什么关系。
```

## 九、七级硬校验：形式服务交付

形式不是默认模板，而是服务本轮交付目标。

### 必须回答

```text
1. 本轮要抓共鸣、解释机制、建立信任、收集反馈，还是推动行动？
2. 主形式是什么？
3. 是否真的需要一题多形？
4. 形式是否会扭曲真实？
```

### 判断规则

```text
情绪强、适合抓停留 → 视频优先。
结构强、适合复用 → 图文优先。
判断链复杂 → 长文 / B站 / 内部研究优先。
需要收集反馈 → 低成本公开表达优先。
涉及隐私或证据不足 → 暂不表达 / 内部笔记优先。
```

## 十、八级硬校验：成品执行

当确定要公开表达后，输出不能停在建议。

### 必须回答

```text
1. 图文是否有页结构、文字、视觉说明？
2. 视频是否有旁白、分镜、字幕、转场、封面、文案？
3. 长文是否有结构、标题、核心论证、结尾反馈问题？
4. 哪些部分需要人工实拍、录屏、剪辑或审核？
```

### 不通过

```text
只输出灵感。
只输出拍摄建议。
只输出脚本但没有执行说明。
把 Dify 或 AI 当成直接发布机器。
```

---

## 十一、九级硬校验：真实性、隐私与伦理

### 必须回答

```text
1. 有没有编造经历、反馈、数据、案例？
2. 有没有暴露姓名、地址、账号、联系方式、隐私画面？
3. 有没有需要打码、模糊、删除的信息？
4. 公开表达是否会伤害真实关系？
5. 是否把复杂的人简化成流量素材？
```

### 不通过

```text
AI 编造现实。
用真实关系换内容。
把他人的生活过度消费。
为了传播效果放大焦虑或收益承诺。
```

---

## 十二、十级硬校验：现实反馈与规则回流

发布后才算进入物理世界验证。

### 必须回答

```text
1. 有没有真实发布 / 交付 / 对话 / 行动？
2. 有没有真实反馈？
3. 反馈验证了什么？推翻了什么？
4. 是否要更新数字生命的记忆、模型、边界或判断规则？
5. 是否要更新 Human-Environment-Lab 的表达、交付或实验规则？
```

### 不通过

```text
没有反馈就自称验证成功。
没有现实结果就沉淀成稳定规则。
AI 编造评论、数据或用户反应。
```

---

## 十三、发布前 12 项总检查

```text
1. 它是否来自碳基真实？
2. 事实、感受、假设、推演是否分清？
3. 是否经过数字生命的边界把控？
4. 是否真的适合公开表达？
5. 目标平台和真实受众是否明确？
6. 要表达什么 / 不表达什么是否清楚？
7. 是否已经转成人话？
8. 主形式是否服务交付目标？
9. 是否具备成品执行条件？
10. 是否完成隐私、伦理、版权、夸大风险检查？
11. 发布后要验证什么是否明确？
12. 反馈回来写入哪里是否明确？
```

---

## 十四、一句话标准

```text
每次公开表达都必须：
从碳基真实出发，经过硅基处理和 Lab 交付判断，
再按平台语言转成物理世界能接收的内容，
最后用真实反馈回流更新数字生命和 Lab。
```
