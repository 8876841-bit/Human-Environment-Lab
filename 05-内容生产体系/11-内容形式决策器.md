# 11-内容形式决策器

> 本文件解决一个问题：一条触发点或脚本，到底适合做成图文里的哪一种，还是视频里的哪一种。

---

## 一、核心结论

内容形式不能靠感觉选，也不能等脚本完全写完以后才选。

正确流程是：

```text
触发点
↓
选题生成
↓
形式初判：先判断它更适合图文、视频，还是一题多形
↓
按形式生成脚本
↓
脚本后复核：根据脚本实际作用，锁定最终呈现方式
↓
进入视觉 / 分镜 / 执行清单
```

也就是说：

```text
脚本前先定方向。
脚本后再复核。
最终选择主形式 + 可选衍生形式。
```

---

## 二、为什么不能等脚本写完才选形式？

因为不同形式需要不同脚本结构。

```text
图文脚本：更重信息层级、标题、卡片结构、收藏价值。
口播脚本：更重语言节奏、前 3 秒 Hook、情绪递进。
混合视频脚本：更重画面切换、旁白、素材组织。
桌面推演脚本：更重逻辑拆解、步骤演示、屏幕或纸面操作。
情绪空镜脚本：更重旁白质感、停顿、氛围和画面留白。
```

如果完全写完脚本后才决定形式，容易出现：

```text
脚本文字是对的，但画面不成立。
内容逻辑是对的，但平台形式不适配。
适合收藏的内容被做成了快节奏视频。
适合口播建立信任的内容被做成了干巴巴图文。
```

---

## 三、第一步：判断这条内容的“核心作用”

每条内容先判断它到底在完成什么任务。

| 核心作用 | 更适合的形式 |
|---|---|
| 让人共鸣 | 口播 / 情绪图文 / 情绪空镜 |
| 讲清一个机制 | 结构图文 / 桌面推演 / 混合视频 |
| 展示一个空间或材料 | 实景对比图文 / 混合视频 |
| 提供避坑清单 | 小红书多图卡片 / 结构化图表 |
| 建立个人信任 | 真人口播 / 伪访谈 / 混合视频 |
| 解释 AI 工具或工作流 | 桌面推演 / 屏幕录制 / 结构图文 |
| 讲一个真实案例 | 案例图文 / 混合视频 / 伪访谈 |
| 输出价值观或深度思考 | 口播 / 情绪空镜 + 旁白 / 长图文 |
| 需要收藏复用 | 多图笔记 / 清单卡片 / 流程图 |
| 需要强冲突传播 | 抖音短视频 / 真人口播 / 混合视频 |

---

## 四、图文形式选择表

### 1. 小红书多图笔记

适合：

```text
痛点明确
有解决方案
需要收藏
可以拆成 5-7 张图
```

典型结构：

```text
封面痛点
↓
细节共鸣
↓
机制拆解
↓
方案清单
↓
总结金句
```

适合母线：空间秩序、工艺机制、商业服务、AI 认知秩序。

---

### 2. 极简结构图 / 清单卡片

适合：

```text
信息密度高
需要讲清逻辑
用户可能会保存
适合做判断表、流程表、责任边界表
```

适合主题：

```text
AI 工具怎么选
客户为什么缺判断系统
谁收费谁担责
一个流程为什么会卡住
```

适合母线：AI 认知秩序、商业服务、工艺机制。

---

### 3. 实景对比图文

适合：

```text
有现场图
有前后变化
视觉差异明显
空间或材料本身就是重点
```

适合母线：空间秩序、材料感官、案例探家。

---

### 4. 碎片日记 / 情绪图文

适合：

```text
不是讲方法，而是讲一种真实感受
内容偏转型、焦虑、疲惫、意义感
画面可以少，文字要真
```

适合主题：

```text
工作室停滞后的空心感
不想做 AI 时代牛马
旧身份开始失效
真实生活为什么反而更重要
```

适合母线：真实生活转型、意义与文明观察。

---

### 5. 概念插画 / 漫画

适合：

```text
概念抽象
真人和实景不好拍
需要把看不见的机制画出来
希望内容更轻、更有传播感
```

适合主题：

```text
AI 工具过载
被算法裹挟
判断系统缺失
人的生活被工具反向控制
```

适合母线：AI 认知秩序、意义与文明观察、真实生活转型。

---

## 五、视频形式选择表

### 1. 真人口播

适合：

```text
观点强
需要建立信任
内容来自个人判断
画面不是重点，语言是重点
```

适合主题：

```text
AI 时代普通人最缺的不是工具，是判断系统
旧行业失效后，人要先重建自己的生活秩序
客户真正缺的不是工厂，而是有人帮他判断
```

适合母线：AI 认知秩序、真实生活转型、商业服务、意义与文明。

---

### 2. 混合视频：真人 / 旁白 + 实景 / 素材 / 结构图

适合：

```text
既要有人设信任
又需要画面辅助理解
有案例、截图、现场或结构图可以穿插
```

适合主题：

```text
一个家为什么越住越累
某个案例背后暴露了什么生活方式
一个商业流程为什么会让客户踩坑
```

适合母线：案例探家、空间秩序、工艺机制、商业服务。

---

### 3. 桌面推演

适合：

```text
逻辑复杂
需要一步步拆
适合用纸、笔、卡片、流程图讲清楚
真人可以只露手或半身
```

适合主题：

```text
AI 工具到底怎么分层
Codex、Dify、n8n 分别适合干什么
全屋定制责任边界怎么拆
客户为什么不是缺工厂，而是缺判断系统
```

适合母线：AI 认知秩序、商业服务、工艺机制。

---

### 4. 屏幕录制 / 工具演示

适合：

```text
内容本身是工具操作
需要看到界面、按钮、流程、结果
用户看完可以跟着做
```

适合主题：

```text
如何用 Dify 跑一个内容工作流
如何用 Codex 整理仓库
如何用 AI 把触发点变成脚本
```

适合母线：AI 认知秩序。

---

### 5. 情绪空镜 + 旁白

适合：

```text
内容偏情绪、意义、生活状态
不需要强解释
需要氛围、停顿和共鸣
```

适合主题：

```text
真实生活为什么变得稀缺
人为什么不能只剩效率
旧身份失效之后的空白感
```

适合母线：真实生活转型、意义与文明观察、材料感官。

---

### 6. 伪访谈 / 自问自答

适合：

```text
一个问题有冲突
适合一问一答
可以把复杂观点拆成对话
比单人口播更有节奏
```

适合主题：

```text
为什么 AI 越强，我反而越焦虑？
为什么学工具不是最重要的？
为什么客户明明能找工厂，还是会踩坑？
```

适合母线：AI 认知秩序、商业服务、真实生活转型。

## 六、脚本后复核规则

脚本写出来后，用下面 6 个问题复核形式是否选对。

### 1. 没有画面，内容还成立吗？

```text
成立 → 口播 / 图文 / 情绪旁白
不成立 → 混合视频 / 实景对比 / 屏幕录制
```

### 2. 用户看完需要收藏吗？

```text
需要收藏 → 多图笔记 / 清单卡片 / 流程图
不一定收藏 → 口播 / 情绪视频 / 混合视频
```

### 3. 内容需要展示过程吗？

```text
需要过程 → 桌面推演 / 屏幕录制 / 混合视频
不需要过程 → 口播 / 图文卡片 / 情绪空镜
```

### 4. 内容是靠观点打动，还是靠画面打动？

```text
靠观点 → 口播 / 伪访谈 / 长图文
靠画面 → 实景对比 / 混合视频 / 情绪空镜
```

### 5. 内容抽象吗？

```text
抽象 → 概念插画 / 桌面推演 / 结构图
不抽象 → 口播 / 实景 / 多图笔记
```

### 6. 这条内容更需要“信任”，还是更需要“效率”？

```text
需要信任 → 真人口播 / 伪访谈 / 混合视频
需要效率 → 图文卡片 / 屏幕录制 / 清单
```

## 七、最终输出格式

每条内容在进入制作前，必须输出一份“形式决策结果”。

```text
【内容形式决策】

1. 主形式：
   例如：桌面推演视频

2. 备选形式：
   例如：小红书结构图文 / 口播短视频

3. 不适合的形式：
   例如：情绪空镜，因为这条内容需要讲清逻辑，不适合只做氛围。

4. 选择理由：
   这条内容的核心作用是解释 AI 工具选择逻辑，需要拆步骤、画关系、讲判断，所以优先桌面推演。

5. 需要的素材：
   工具截图 / 桌面纸笔 / 流程图 / 旁白 / 封面标题

6. 输出物：
   分镜表 / 拍摄清单 / 剪辑清单 / 小红书衍生图文结构
```

---

## 八、放进 Dify 的节点位置

建议在 Dify 里加入一个节点：

```text
节点 1.5：Content_Format_Decision（内容形式决策）
```

位置：

```text
触发点输入
↓
节点 1：痛点与选题生成
↓
节点 1.5：内容形式决策
↓
节点 2：按已选形式生成脚本
↓
节点 2.5：脚本后形式复核
↓
节点 3：视觉 / 资产 / 拍摄执行
```

作用：

```text
1. 避免脚本写完才发现形式不匹配。
2. 让脚本从一开始就为对应形式服务。
3. 保留一题多形的衍生空间。
```

---

## 九、一句话标准

```text
不是“脚本好了以后随便选个形式”。
而是“选题后先定形式方向，脚本后再复核锁定”。
```

内容形式的选择标准不是好不好看，而是：

```text
这条内容最需要完成什么作用？
它是要让人共鸣、收藏、理解、信任，还是转发？
```
