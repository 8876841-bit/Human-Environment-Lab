# 11-内容形式决策器

> 本文件解决一个问题：一条真实触发点，到底应该先做成图文、视频，还是一题多形。  
> 它必须与 `00-内容生产硬校验清单.md`、`10-Dify工作流搭建实施指南.md`、`16-平台规则与发布调性表.md`、`17-第一性原理到平台表达转译表.md` 保持一致。

---

## 一、核心结论

内容形式不能靠感觉选，也不能等脚本写完以后才随便选。

正确流程是：

```text
真实触发点
↓
第一性原理锚点
↓
平台与表达前置校验
↓
内容形式初判
↓
按主形式生成脚本
↓
脚本后复核
↓
锁定最终形式
↓
输出图文 / 视频成品包
```

核心标准：

```text
形式不是为了好看。
形式必须服务：底层判断、平台调性、用户状态和内容任务。
```

---

## 二、形式决策前必须完成 4 个判断

### 1. 第一性原理锚点

每条内容先问：

```text
这条内容到底在解释什么底层规律？
```

例如：

```text
触发点：AI 工具越多，我反而越不知道怎么开始。
第一性原理锚点：工具过载会破坏普通人的判断顺序。
```

如果没有第一性原理锚点，不能进入形式决策。

---

### 2. 平台规则 / 平台调性

同一个触发点，不同平台的形式可能不同。

```text
抖音 / 快手：优先短视频，抓停留和评论。
小红书：优先图文卡、清单、方法、收藏价值。
视频号：表达更克制，重可信度和真实感。
B站：可以做长视频，重逻辑链和系列沉淀。
```

禁止：

```text
所有平台共用一个脚本。
所有视频都默认 45-60 秒。
所有触发点都默认图文 + 视频。
```

---

### 3. 谁在看

不能只写“普通人”或“大众”。

必须写清：

```text
谁在看？
他现在什么状态？
他为什么会停下来？
他看完要得到什么？
```

---

### 4. 表达边界

每条内容必须明确：

```text
要表达什么？
不表达什么？
不应该被误解成什么？
```

形式选择必须服务这个边界。

---

## 三、内容核心作用判断表

| 核心作用 | 更适合的形式 |
|---|---|
| 抓住情绪 / 共鸣 | 短视频 / 口播 / 情绪空镜 / 情绪图文 |
| 讲清一个机制 | 结构图文 / 桌面推演 / V2 AI 生成型 / V3 混合增强型 |
| 让人收藏复用 | 小红书多图卡片 / 清单卡 / 流程图 / 判断表 |
| 展示真实现场 | V1 实拍原生型 / V3 混合增强型 / 实景对比图文 |
| 建立个人信任 | 真人口播 / 伪访谈 / V3 混合增强型 |
| 展示工具操作 | 屏幕录制 / 桌面推演 / V3 混合增强型 |
| 做深度解释 | B站长视频 / 桌面推演 / 长图文 |
| 做快速测试 | V2 AI 生成型 / 抖音短视频 / 小红书图文卡 |

---

## 四、图文形式选择表

### G1：提问反转型

适合：

```text
为什么会这样？
你以为是 A，其实是 B。
一个常见现象背后有更深原因。
```

常见结构：

```text
P1：封面提问
P2：场景代入
P3：常见误解
P4：反转判断
P5：机制解释
P6：轻解决 / 收束
```

---

### G2：场景拆解型

适合：

```text
一个空间
一个动作
一个家庭场景
一个工作状态
需要拆成几个层次解释
```

---

### G3：步骤流程型

适合：

```text
怎么做
先做什么后做什么
工具使用路径
选择流程
判断流程
```

---

### G4：前后对比型

适合：

```text
调整前后
错误 vs 正确
混乱 vs 有序
旧方式 vs 新方式
```

---

## 五、图文视觉风格选择表

### S1：治愈系叙事插画风

适合：

```text
生活状态
空间心理
情绪观察
真实生活转型
轻解释内容
```

风险：

```text
不能过度唯美。
不能为了温柔牺牲信息清楚度。
```

---

### S2：中性实用决策板风

适合：

```text
AI 工具选择
路径判断
方法清单
流程拆解
商业责任边界
```

标准：

```text
白底 / 米白底
深灰字
墨绿或橄榄绿强调
表格清楚
人物弱化
一页一个判断点
```

---

### S3：实景对比标注风

适合：

```text
探家
空间问题
材料细节
施工工艺
前后对比
现场风险说明
```

标准：

```text
实景图优先。
标注服务解释。
不改变真实比例和结构。
不做过度美化。
```

---

## 六、视频形式选择表

### V1：实拍原生型

适合：

```text
真实现场
探家
材料质感
客户反应
施工问题
生活现场
```

终点：

```text
拍摄清单 + 可发布成片。
```

拍摄清单不是终点。

---

### V2：AI 生成型

适合：

```text
抽象机制
AI 工具焦虑
判断系统缺失
无真人素材
需要快速测试选题
```

终点：

```text
AI 生成视频成品包。
```

禁止把 V2 输出成：

```text
拍摄清单
真人口播建议
现场素材建议
```

---

### V3：混合增强型

适合：

```text
已有真实素材
但需要 AI 结构图、字幕、旁白、转场解释
```

终点：

```text
有素材 → 直接混合增强成片。
缺素材 → 成片包 + 补拍清单。
```

---

## 七、一题多形规则

不是每个触发点都要同时做图文和视频。

正确规则：

```text
每个触发点只强制确定一个主形式。
只有当它同时具备传播价值和收藏价值时，才做一题多形。
```

判断：

```text
只需要抓情绪 → 视频优先
只需要收藏复用 → 图文优先
既有情绪又有方法 → 视频主发，图文承接
```

TP-001 的判断：

```text
视频负责抓焦虑和传播。
图文负责收藏和方法沉淀。
```

## 八、脚本后复核规则

脚本生成后，必须重新问：

```text
1. 没有画面，这条内容还成立吗？
2. 用户看完是否需要收藏？
3. 内容是否需要展示过程？
4. 内容靠观点打动，还是靠画面打动？
5. 内容是否抽象，需要结构图或桌面推演辅助？
6. 这条内容更需要信任，还是更需要效率？
7. 是否符合平台调性和平台规则？
8. 是否仍然围绕第一性原理锚点？
9. 是否真的需要一题多形？
```

如果脚本写出来后发现形式不匹配，必须改形式，而不是硬做。

---

## 九、最终输出格式

每条内容在进入制作前，必须输出一份“形式决策结果”。

```text
【内容形式决策】

1. 真实触发点：
2. 第一性原理锚点：
3. 目标平台与平台调性：
4. 观看者画像与状态：
5. 内容核心作用：共鸣 / 收藏 / 理解 / 信任 / 转发 / 跟着操作
6. 主形式：图文 / V1 / V2 / V3 / 其他
7. 图文结构或视频类型：G1-G4 / V1-V3
8. 视觉风格：S1 / S2 / S3
9. 推荐时长 / 页数：按平台决定
10. 是否建议一题多形：是 / 否，理由
11. 不适合的形式：至少 1 个
12. 需要素材：截图 / 实景 / 录屏 / 口播 / 结构图 / AI 画面 / 旁白
13. 成品包要求：图文页结构 / 视频分镜 / 提示词 / 发布文案 / 标签
14. 平台风险提醒：
```

---

## 十、放进 Dify 的节点位置

建议在 Dify 里作为：

```text
节点 1.5：Content_Format_Decision（内容形式决策）
```

位置：

```text
触发点输入
↓
节点 1：痛点与选题生成
↓
节点 1.2：平台与表达前置校验
↓
节点 1.5：内容形式决策
↓
节点 2：按主形式生成脚本
↓
节点 2.5：脚本后形式复核
↓
节点 3：图文 / 视频成品包生成
```

---

## 十一、一句话标准

```text
不是“脚本好了以后随便选个形式”。
而是“从真实触发点和第一性原理出发，按平台调性判断主形式，再生成可制作成品包”。
```
