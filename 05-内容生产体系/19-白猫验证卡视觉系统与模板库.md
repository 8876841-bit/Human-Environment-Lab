# 19-白猫验证卡视觉系统与模板库

> 本文件用于沉淀 HEL 内容生产体系中的一种图文表达形式：**白猫验证卡**。  
> 它不是对外部参考图的换皮，而是把参考形式拆解后，转化为 HEL 自己的“真实问题 → 拆解 → 验证 → 沉淀”视觉表达系统。

---

## 一、定位

白猫验证卡不是普通插画，也不是单纯可爱 IP 卡片。

它的定位是：

```text
真实问题的图解验证记录
```

它服务于 HEL 的内容生产主线：

```text
真实触发点
↓
混乱现场
↓
底层判断
↓
验证动作
↓
复盘沉淀
↓
可复用规则
```

和普通“知识卡”的区别：

| 类型 | 核心特征 | 问题 |
|---|---|---|
| 普通知识卡 | 总结一个方法 | 容易变成正确废话 |
| 可爱动物说明书 | 用动物降低理解门槛 | 容易只剩风格，缺少真实验证 |
| 白猫验证卡 | 从真实问题出发，拆解、验证、沉淀 | 必须有真实触发点或测试动作支撑 |

一句话标准：

```text
别人做“可爱方法论说明书”。
我们做“真实问题的白猫验证记录”。
```

---

## 二、为什么不是简单换皮

外部参考图值得学习的不是动物形象，而是它的底层结构：

```text
1. 标题先给判断
2. 抽象概念物件化
3. 信息模块化
4. 阅读路径可视化
5. 角色降低理解压力
6. 底部给行动口令
```

但 HEL 不能只复制这些。

HEL 必须额外增加三件事：

```text
1. 真实触发点
2. 验证状态
3. 复盘沉淀
```

否则就会变成参考图的影子。

---

## 三、白猫角色设定

白猫不是装饰物，而是工作室的视觉研究员。

角色定位：

```text
白猫研究员
```

角色职责：

```text
观察混乱
拆解问题
做验证
提醒别跳步
把经验收纳成规则
```

角色气质：

```text
冷静
敏锐
克制可爱
不装专家
会提醒你别乱来
```

视觉设定：

```text
一只纯白猫
黑色圆眼
简洁线描
橙色围巾作为识别色
软萌但不幼稚
动作服务信息，不抢信息
```

禁忌：

```text
不要每次重新设计白猫
不要把白猫画得过度儿童绘本化
不要让白猫只负责卖萌
不要让白猫动作与内容无关
```

## 四、固定信息结构

每张白猫验证卡都应该包含以下层级。

### 1. 顶部强判断标题

标题必须先给判断，不要先铺背景。

常用句式：

```text
先XX，再XX。
别XX，先XX。
XX之后，才叫XX。
把XX做成XX。
表面是XX，真正卡在XX。
```

示例：

```text
先判断，再选工具。
别先收藏100个教程。
表面是工具太多，真正卡在任务没分清。
真实现场，才有真实答案。
复盘一次，能力升级一次。
```

### 2. 副标题人话解释

副标题负责降低理解门槛。

它回答：

```text
这张图到底要解决什么？
为什么这个判断重要？
用户看完能做什么？
```

示例：

```text
别让工具先打乱你的思考顺序。
不解决真实卡点，努力都会白费。
从生活里找问题，从现场找方向。
```

### 3. 左上角小标签

用于形成 HEL 的研究感和证据感。

建议包含：

```text
触发点编号
所属母线
验证状态
样本数量
下一步动作
```

示例：

```text
HEL-TP001
母线：AI认知秩序
状态：待验证
样本：0/1
下一步：发布测试
```

### 4. 中间主隐喻

抽象概念必须物件化。

常用隐喻表：

| 抽象逻辑 | 可视化隐喻 |
|---|---|
| 整理 | 抽屉 / 盒子 / 文件夹 |
| 流程 | 路径 / 回路 / 跑道 |
| 筛选 | 篮子 / 筛子 / 分拣箱 |
| 验证 | 清单 / 打勾 / 检测台 |
| 沉淀 | 工具箱 / 方法盒 / Skill箱 |
| 混乱 | 乱纸 / 弹窗 / 缠线 / 堆叠入口 |
| 判断 | 放大镜 / 问号卡 / 分叉路 |
| 发布 | 小旗 / 纸飞机 / 平台出口 |

### 5. 信息模块

不要大段铺文字。

优先使用：

```text
卡片
抽屉
标签
勾选框
表格块
流程箭头
圆形节点
警示贴纸
```

每张卡最多保留：

```text
1 个主结论
3-5 个关键点
1 条主要路径
1 个验证动作
1 句收束口令
```

### 6. 验证状态

这是 HEL 与普通知识卡的关键差异。

常用状态：

```text
待验证
已验证
一次样本
样本不足
已复盘
可复用
暂不建议照搬
```

状态不只是装饰，而是提醒：

```text
这不是空泛方法论，而是有验证阶段的研究记录。
```

### 7. 底部行动口令

最后必须留下一个可执行动作。

示例：

```text
先把任务写清，再决定用什么工具。
先跑一条，再谈方法论。
没验证，不发布结论。
先筛掉一次性动作，再沉淀长期能力。
```

## 六、统一视觉规范

### 1. 风格定位

```text
手绘信息插画风
轻漫画说明书风
极简线描知识卡风
真实问题研究卡
```

不是：

```text
摄影风
3D潮玩风
厚涂插画风
写实海报风
儿童绘本风
课程宣传海报风
```

### 2. 色彩系统

控制在 6 色以内。

| 颜色 | 用途 |
|---|---|
| 黑色 | 主线稿、主标题 |
| 橙色 | 品牌强调色、白猫围巾、重点线 |
| 蓝色 | 流程、判断、路径 |
| 绿色 | 正确、可复用、已验证 |
| 红色 | 警示、不要这样、风险 |
| 灰色 | 背景、阴影、次级说明 |

### 3. 排版规则

```text
标题在上方
主画面居中
白猫服务信息结构
阅读路径从上到下、从左到右
每一块信息都装进容器里
边角允许小提醒
底部必须有收束句
```

### 4. 文案密度

每张卡建议：

```text
标题：8-14字
副标题：10-20字
模块：3-5个
每个模块：3-10字为主
底部收束：10-20字
```

禁忌：

```text
不要一张图塞满段落
不要让标题变成空泛金句
不要让模块文字超过画面承载能力
不要把解释全部压进一张图
```

## 八、适用题材

适合：

```text
AI工具选择
内容生产流程
图文 / 视频样品复盘
Dify工作流节点解释
家装真实现场拆解
客户判断清单
经验沉淀
方法库建设
SOP总结
```

不适合：

```text
信息量特别大的教程
需要严肃合同措辞的商业文件
强情绪故事
完整长案例复盘
需要大量真实照片支撑的案例展示
```

如果内容需要大量证据和长逻辑，白猫验证卡只能作为入口，不应该承载全部内容。

## 九、质检清单

每张白猫验证卡发布前检查：

```text
1. 有没有真实触发点？
2. 标题是否先给判断？
3. 是否有 HEL 母线或验证状态？
4. 白猫动作是否服务内容？
5. 抽象逻辑是否已经物件化？
6. 信息是否模块化？
7. 阅读路径是否清楚？
8. 是否有底部行动口令？
9. 是否避免了单纯卖萌？
10. 是否避免照搬参考图？
11. 是否能说明下一步怎么验证？
12. 是否只承载一个主要结论？
```

未通过以下任一项，不建议发布：

```text
只是可爱，没有结构。
只是结构，没有真实问题。
只是模仿，没有 HEL 验证状态。
只是结论，没有行动动作。
```

## 十、与 TP-001 的关系

TP-001 可使用模板 A：白猫验证卡。

对应关系：

| 项目 | TP-001 内容 |
|---|---|
| 标题 | 先判断，再选工具 |
| 真实触发点 | AI 工具越多，我反而越不知道怎么开始 |
| 母线 | AI 认知秩序 |
| 状态 | 待验证 |
| 三类选项 | 写东西 / 做东西 / 重复干活 |
| 验证动作 | 发布一条短视频 + 一组图文，观察停留、收藏、评论 |
| 收束口令 | 先把任务写清，再决定用什么工具 |

TP-001 不应该只做“白猫 + 工具分类”。

它必须体现：

```text
真实触发点
→ 工具混乱
→ 任务没分清
→ 三类动作判断
→ 发布测试
→ 复盘沉淀
```

## 十一、底层原则

白猫验证卡的核心不是可爱，而是：

```text
把真实混乱整理成可验证、可复用的秩序。
```

最终判断标准：

```text
如果这张卡只让人觉得可爱，它失败了。
如果这张卡让人知道下一步该怎么验证，它才成立。
```
