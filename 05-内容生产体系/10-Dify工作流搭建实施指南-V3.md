# Dify 工作流搭建实施指南 V3

> 本文件是 V3 版本的 Dify / 多 Agent 同步方向。
> 原 `10-Dify工作流搭建实施指南.md` 保留为 V2 / V4.1 内容生产参考。

V3 不再把 Dify 定义为“内容生产流水线”。

它的新定位是：

```text
Human-Environment-Lab 的 Lab 交付判断与表达传播工作流底座。
```

---

## 一、V3 主线

```text
真实触发
↓
碳基输入确认
↓
硅基数字处理
↓
Lab 交付判断
↓
表达传播执行包 / 其他交付形式
↓
物理世界验证
↓
反馈回流
```

核心变化：

```text
不是每个触发点都进入内容生产。
不是每个输出都必须公开发布。
不是所有价值都等于播放量。
```

---

## 二、Dify 在 V3 中负责什么

Dify 负责：

```text
1. 接收真实触发。
2. 引导用户补齐碳基真实信息。
3. 调用数字生命的硅基能力进行整理、分析、建模、推演。
4. 判断这个触发点适合哪种 Lab 交付形式。
5. 当且仅当适合公开表达时，调用内容生产模块。
6. 发布或交付后，记录现实反馈并生成规则更新建议。
```

Dify 不负责：

```text
1. 替用户编造现实经历。
2. 替用户决定最终价值选择。
3. 默认把所有触发点做成爆款内容。
4. 在证据不足时输出确定结论。
5. 未经人工确认直接发布。
```

---

## 三、建议节点架构

```text
节点 0：Start（真实触发输入）
↓
节点 0.5：Carbon_Input_Check（碳基真实性确认）
↓
节点 1：Silicon_Processing_Agent（硅基整理、分析、建模、推演）
↓
节点 1.5：Lab_Delivery_Decision（Lab 交付判断）
↓
节点 2：Platform_Expression_Preflight（仅当进入公开表达时启用）
↓
节点 2.5：Content_Format_Decision（形式决策）
↓
节点 3：Content_Package_Agent（图文 / 视频 / 长文 / 发布包）
↓
节点 4：Reality_Feedback_Loop（现实反馈与规则回流）
```

---

## 四、节点 0：Start（真实触发输入）

### 输入变量

```text
trigger_input：真实触发，一句话也可以。
body_reaction：身体 / 情绪反应。
surface_problem：它表面看起来像什么问题。
deep_suspicion：我怀疑背后是什么问题。
source_context：现场、对话、截图、经历、材料。
privacy_boundary：不能公开的信息。
available_assets：可用素材。
initial_delivery_preference：用户初步想做成什么，可填不确定。
```

### 最小输入示例

```text
trigger_input：我发现自己学 AI 工具越学越乱。
body_reaction：焦虑、烦、觉得被工具推着跑。
surface_problem：好像是我不会学习工具。
deep_suspicion：可能不是工具问题，是我没有任务顺序。
source_context：最近收藏了很多工具，但真正能用起来的很少。
privacy_boundary：无。
initial_delivery_preference：不确定。
```

## 五、节点 0.5：Carbon_Input_Check

### 作用

确认输入是否来自碳基物理世界的真实触发。

### 系统提示词方向

```text
你是 Human-Environment-Lab 的碳基输入审核员。
你的任务不是写内容，而是判断用户输入是否来自真实物理世界。

请区分：
1. 事实
2. 感受
3. 猜测
4. 二手观点
5. 需要补证据的部分

如果证据不足，不要进入内容生产。
```

### 输出格式

```text
1. 真实触发摘要：
2. 碳基真实性：强 / 中 / 弱
3. 事实：
4. 感受：
5. 推测：
6. 缺失证据：
7. 能否进入硅基处理：是 / 否 / 暂缓
8. 需要用户补充什么：
```

## 六、节点 1：Silicon_Processing_Agent

### 作用

调用数字生命的硅基能力，对真实触发做整理、分析、建模、推演和反证。

### 系统提示词方向

```text
你是用户在数字世界中的硅基分身。
你不负责伪装成有身体经验。
你负责保存、整理、分析、建模、推演、反驳和边界把控。

你必须标清：
哪些是事实，哪些是假设，哪些是你的推演。
```

### 输出格式

```text
1. 核心矛盾：
2. 深层问题：
3. 临时假设：
4. 反例 / 可能误判：
5. 证据强度：强 / 中 / 弱
6. 可验证动作：
7. 数字边界提醒：哪些不能被当成事实
8. 可继续研究的问题：
```

---

## 七、节点 1.5：Lab_Delivery_Decision

### 作用

这是 V3 的关键节点。

它决定本轮触发点应该交付成什么，而不是默认进入选题。

### 可选交付形式

```text
1. 内部研究
2. 公开表达
3. 内容传播
4. 图文 / 视频 / 长文
5. 工具原型
6. 产品实验
7. 服务设计
8. 现实行动
9. 对话提纲
10. 暂不表达
```

### 输出格式

```text
1. 推荐交付形式：
2. 为什么不是默认做内容：
3. 如果公开表达，表达目的是什么：共鸣 / 理解 / 信任 / 反馈 / 行动
4. 如果暂不表达，需要补什么现实证据：
5. 是否进入 Platform_Expression_Preflight：是 / 否
6. 人工确认问题：这个判断是否符合你的现实边界？
```

---

## 八、节点 2：Platform_Expression_Preflight

仅在节点 1.5 判断“适合公开表达 / 内容传播”后启用。

### 必须判断

```text
1. 目标平台。
2. 谁在看。
3. 观看者当下状态。
4. 核心表达。
5. 非目标表达。
6. 第一性原理 / 内部判断如何转成人话。
7. 隐私、伦理、版权、夸大风险。
8. 发布后要验证什么现实反馈。
```

---

## 九、节点 2.5：Content_Format_Decision

### 判断规则

```text
情绪强、适合抓停留 → 视频优先。
结构强、适合复用 → 图文优先。
判断链复杂 → 长文 / B站 / 内部研究优先。
需要收集反馈 → 低成本公开表达优先。
涉及隐私或证据不足 → 暂不表达 / 内部笔记优先。
```

输出必须说明：

```text
1. 主形式是什么。
2. 为什么选择这个形式。
3. 是否真的需要一题多形。
4. 不适合什么形式。
5. 需要哪些真实素材。
```

## 十、节点 3：Content_Package_Agent

当确定公开表达后，输出可执行包。

### 图文包至少包含

```text
标题
封面文案
页结构
每页主标题
每页正文
每页画面说明
发布正文
标签
评论区反馈问题
隐私检查
```

### 视频包至少包含

```text
平台版本
推荐时长
口播 / 旁白
分镜表
前 3 秒 Hook
字幕 / 花字
镜头或画面提示
封面建议
发布文案
评论区反馈问题
隐私检查
```

### 长文包至少包含

```text
标题
开头真实触发
核心问题
分析结构
反例或边界
结尾行动 / 反馈问题
```

## 十一、节点 4：Reality_Feedback_Loop

### 输入

```text
发布平台 / 交付对象：
真实数据：
代表评论 / 反馈：
用户自己的感受：
是否引发新行动：
是否出现误解：
```

### 输出

```text
1. 本轮现实反馈验证了什么：
2. 推翻了什么：
3. 哪些只是噪声：
4. 是否更新数字生命记忆：
5. 是否更新 Lab 规则：
6. 是否沉淀为 OBS：
7. 下一轮真实触发：
```

---

## 十二、人工交接点

必须人工确认的节点：

```text
1. Carbon_Input_Check 后：这是否真的来自你的现实经验？
2. Silicon_Processing_Agent 后：AI 有没有过度推演？
3. Lab_Delivery_Decision 后：是否真的适合公开表达？
4. Content_Package_Agent 后：是否有隐私、伦理或失真风险？
5. Reality_Feedback_Loop 后：哪些反馈能写成规则？
```

---

## 十三、一句话标准

```text
Dify 在 V3 中不是内容自动化机器，
而是帮助 Human-Environment-Lab 判断一个真实触发如何从碳基现实进入硅基处理，
再以合适的形式回到物理世界接受验证的循环工作流。
```
