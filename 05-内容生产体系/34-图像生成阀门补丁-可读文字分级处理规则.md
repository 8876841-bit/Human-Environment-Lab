# 34｜图像生成阀门补丁：可读文字分级处理规则

> 适用范围：Human-Environment-Lab 图像生成与图生视频流程
>
> 适用对象：人物基准图、视频初始帧、故事板、封面图、图文卡片、信息海报、视频补充画面
>
> 核心目的：避免 AI 生成图里的文字失控，区分“什么时候必须无字”“什么时候可以有字”“什么时候文字必须后期添加”。

---

## 0. 总原则

不是所有图片都不能有文字。

但在不同任务里，文字的风险等级不同。

```text
基准图 / 视频起始帧：文字通常是风险变量。
图文卡片 / 信息海报：文字是交付主体。
封面图：文字要后期可控。
故事板：文字可以做内部说明，但不适合作为最终图像内容。
```

核心判断：

```text
文字如果承担信息表达，就必须可控。
AI 直接画进图里的可读文字，默认不可控。
```

---

## 1. 为什么视频起始帧要限制可读文字

KF01 这类初始帧的任务是：

```text
锁人物
锁情绪
锁场景
锁构图
为 3 秒图生视频提供稳定底盘
```

它不是最终海报，也不是图文卡片。

因此，在起始帧里，可读文字通常属于：

```text
高风险
低必要
后期更好控制
容易破坏视频稳定性
```

---

## 2. 可读文字的主要风险

### 2.1 准确性风险

AI 容易生成：

```text
错字
乱码
拼写错误
错误工具名
错误标签
不稳定字体
中英文混杂
```

知识类内容里，文字错误会直接损害专业感。

---

### 2.2 可控性风险

同一个内容后续可能拆成：

```text
小红书版
抖音版
视频号版
B站版
```

每个平台的标题、字幕、钩子、评论引导都不同。

如果文字一开始被焊死在图里，后续每次改文案都要重新生成图像。

---

### 2.3 视频稳定性风险

静态图里的文字进入图生视频后，常见问题：

```text
文字抖动
文字变形
字形粘连
笔画消失
边缘发糊
局部漂移
```

所以视频初始帧阶段，不建议让文字承担阅读功能。

---

### 2.4 注意力风险

S1 这类开场段的任务是让用户感受到：

```text
AI 工具很多
人有点被信息围住
任务还没分清
```

如果画面中出现太多可读文字，用户会开始读文字，而不是感受状态。

---

## 3. 可读文字分级规则

以后不再简单说“绝对不能有字”，而是分级处理。

---

## 3.1 A 级禁令：直接淘汰

出现以下情况，直接判不合格：

```text
1. 明显错字
2. 明显乱码
3. 明确软件名称
4. 大块可读标题或段落
5. 中英文混乱且影响专业感
6. 字遮挡人物脸部、眼睛或关键表情
7. 文字成为画面主角，但内容不可控
8. 文字在视频初始帧中承担核心信息表达
```

适用场景：

```text
人物基准图
视频起始帧
图生视频初始帧
情绪画面
背景补充画面
```

---

## 3.2 B 级警告：可以酌情保留

以下情况可以保留，但要检查是否影响后期：

```text
1. 模糊 UI 线条
2. 无法读清的抽象卡片纹理
3. 非信息功能的小图标
4. 不承担阅读功能的装饰性字符
5. 远景中无法识别的书页/笔记纹理
```

判断标准：

```text
用户不会去读它
它不承担核心信息
它不影响人物和构图
它进入视频后不会明显变形抢戏
```

---

## 3.3 C 级允许：必须后期添加

以下文字可以出现，但必须在剪辑、设计、排版阶段后期添加：

```text
标题
字幕
任务卡文字
工具名称
平台钩子
评论区引导
步骤说明
封面文案
信息图表文字
```

这些文字属于内容资产，不应该交给图像模型随机生成。

---

## 4. 不同图像任务的文字规则

| 图像任务 | 可读文字规则 | 原因 |
|---|---|---|
| 人物基准图 | 不建议有可读文字 | 主要锁人物、气质、妆造 |
| 视频起始帧 | A级禁令严格执行 | 主要锁画面底盘，文字会影响图生视频 |
| 情绪氛围图 | 不建议有可读文字 | 主要传达情绪，不负责读信息 |
| 故事板图 | 可以有内部标注，但不作为最终画面 | 只供制作理解 |
| 小红书封面 | 文字后期加 | 方便改标题、控字体、控安全区 |
| 图文卡片 | 必须有准确文字，但用设计工具排版 | 文字是交付主体 |
| 信息图 / 长图 | 必须后期设计文字 | 保证准确、对齐、可修改 |
| 视频字幕 | 后期加 | 保证节奏、准确性、平台适配 |

---

## 5. KF01 专用规则

KF01 是 S1 混乱开场段的初始帧。

### KF01 允许

```text
抽象 AI 工具卡片
模糊 UI 图标
半透明卡片
不可读信息线条
弱化的图形元素
```

### KF01 禁止

```text
明确工具名
可读标题
中英文标签
乱码
大块文字
工具清单
卡片文字遮脸
```

### KF01 正确做法

```text
底图只负责人物、场景、情绪、构图和抽象卡片。
真正要读的文字，后期用字幕和卡片设计加上。
```

---

## 6. 标准提示词写法

生成视频起始帧时，应加入：

```text
卡片只作为抽象信息元素，不要出现可读文字，不要生成明确软件名称，不要出现文字乱码。可以用模糊图标、抽象色块、简洁 UI 卡片来表现。
```

还要加入负面提示：

```text
不要可读中文，不要可读英文，不要明确软件名称，不要文字乱码，不要大块文字，不要标题，不要工具名。
```

---

## 7. 验收表

图像生成后，先检查文字问题。

```text
1. 有没有明显可读文字？
2. 有没有错字或乱码？
3. 有没有明确软件名称？
4. 文字有没有遮住人物？
5. 文字是不是承担了核心信息表达？
6. 这些文字后期能不能轻松替换？
7. 如果进入图生视频，文字会不会抖动或变形？
```

判断：

```text
如果 1-5 中任意一项严重，淘汰。
如果只是模糊 UI 线条，可进入下一项检查。
```

---

## 8. 最终原则

```text
起始帧阶段，文字不是资产，是失控项。
成品卡片阶段，文字是资产，必须后期精排。
```

HEL 的图像生成原则：

```text
让 AI 负责画面。
让人负责文字。
让剪辑负责节奏。
让平台版本负责表达差异。
```

---

## 9. 一句话标准

```text
能读的字，必须可控；
不可控的字，不要出现在底图里。
```
