# 05-内容生产体系

本目录存放了 Human-Environment-Lab (HEL) 从底层世界观向大众内容（抖音、小红书、视频号、B站）转化的全套生产体系设计文档。

这些文档基于“内容是长出来的，不是拼出来的”这一核心理念，将 V0.6.1 底层模型作为养分根基，构建了一套会呼吸、可生长的数字内容生产系统。

---

## 当前输入原则

```text
触发点优先，OBS 降级。
```

日常输入不强制先写完整 OBS。最小输入可以只是一句话触发点：

```text
AI 工具越多，我反而越不知道怎么开始。
```

系统根据触发点进行底层模型推演，生成选题、脚本、分镜和发布包。只有被验证有长期价值的触发点，才沉淀为 `03-观察日志/OBS-XXX.md`。

## 目录结构与核心文档

### [01-自媒体内容体系设计.md](./01-自媒体内容体系设计.md)
**核心解决：“讲什么”与“怎么做”的问题。**
- 建立了“概念转译层”，将晦涩的学术术语（如熵增、边界化）翻译为有痛点的大众语言。
- 将八条话题母线重组为八个“生活痛点专栏”（如【越住越累的真相】、【被 AI 逼疯的打工人】）。
- 设计了包含“找痛点 → 写脚本 → 做画面 → 发布复盘”的四阶段内容生产工作流。

### [02-生长型内容系统.md](./02-生长型内容系统.md)
**核心解决：“为什么做”与“护城河”的问题。**
- 明确了“生长型”与“摘取组合型”内容的本质区别。
- 定义了树状结构：根（模型）→ 干（母线）→ 枝（专栏）→ 叶（内容）→ 养分回流（复盘）。
- 确立了保证原创性的“溯源三问”机制，以及系统与人共同成长的“双向成长机制”。

### [03-表达形式与运营机制.md](./03-表达形式与运营机制.md)
**核心解决：“长什么样”与“怎么铺设”的问题。**
- 梳理了四大图文形式矩阵与三种视频形式分类。
- 制定了从脚本到成品的“五要素分镜”把控标准与情绪节奏曲线。
- 设计了“碎片投喂 → 结构化洗练 → 入库归档”的知识库沉淀机制。
- 规划了“大一统主账号 → 平台切片分发 → 垂直账号裂变”的三阶段矩阵策略。

### [04-治愈系漫画风格模板.md](./04-治愈系漫画风格模板.md)
**核心解决：“视觉标准化”与“量产复用”的问题。**
- 总结了“治愈系叙事漫画”的视觉要素与六格叙事结构。
- 提供了可直接复用于 Midjourney 等 AI 绘图工具的固定提示词模板（含中英文）。
- 给出了将该视觉风格固化为专栏级 IP 资产的系列化建议。

### [05-视觉呈现形式库-补充版.md](./05-视觉呈现形式库-补充版.md)
**核心解决：“除了漫画还能怎么呈现”的问题。**
- 补充三种图文形式：极简结构图（骗收藏）、电影感实景对比（情绪反差）、碎片日记（深夜共鸣）。
- 补充三种视频形式：情绪空镜+TTS旁白（易量产）、桌面推演（讲逻辑）、伪访谈（塑人设）。

### [06-视频生产流水线与工具选型.md](./06-视频生产流水线与工具选型.md)
**核心解决：“视频如何高质高效且原创”的问题。**
- 设计了“投喂选题 → 脚本生成 → 资产合成 → 剪辑发布”四节点流水线及各节点把控点。
- 对比 Dify 与扣子（Coze），建议以 Dify 为核心底座（逻辑编排+知识库+私有化），扣子用于快速 MVP 验证。

### [07-人机结合共创机制.md](./07-人机结合共创机制.md)
**核心解决：“哪些事人做、哪些事 AI 做”的问题。**
- 确立“人管灵魂与决策、AI 管效率与执行”的分工原则。
- 明确四个节点的人机交接点与关键把控点（选题人拍板、金句人修改、画面人把关、情绪人微调）。
- 三条最佳实践：痛点必须来自真实观察、建立个人语料库、工艺类内容用实拍兜底。

### [08-小红书多图笔记结构模板.md](./08-小红书多图笔记结构模板.md)
**核心解决：“一张图不够，要成组出现”的问题。**
- 设计了 1+N 多图笔记结构：封面 → 细节共鸣 → 机制拆解 → 多方案 → 总结升华。

### [09-动态视觉排版与图组组合.md](./09-动态视觉排版与图组组合.md)
**核心解决：“连发20篇同一版式太单调”的问题。**
- 五种基础版式模块：大画幅留白、拍立得侧写、上下对比、杂志拼图、极简流程。
- 两种组合公式（情绪共鸣型/干货解决型）+ 随机灵活组合策略，防止审美疲劳。

### [10-Dify工作流搭建实施指南.md](./10-Dify工作流搭建实施指南.md)
**核心解决：“如何在 Dify 里落地自动化工作流”的问题。**
- 将 HEL 内容体系落到 Dify 节点：触发点输入、选题、脚本、资产、执行清单、发布复盘。
- 强调底层模型只用于内部推理，对外输出必须转译成人话。

### [11-内容形式决策器.md](./11-内容形式决策器.md)
**核心解决：“一条内容到底做图文还是视频，以及选哪种图文/视频形式”的问题。**
- 明确“选题后先定形式方向，脚本后再复核锁定”。
- 建立图文形式与视频形式选择表。
- 加入 Dify 节点 1.5：Content_Format_Decision（内容形式决策）。

### [PROGRESS-会话进展与决策记录.md](./PROGRESS-会话进展与决策记录.md)
**跨会话接续用。** 记录核心定位、已确立的关键决策、文档清单与待办事项。

## 使用指南

1. **日常输入**：先输入一句真实触发点，不强制写完整 OBS。
2. **选题策划**：根据底层模型、八条母线和概念转译机制，生成平台化选题。
3. **形式决策**：参考 `11-内容形式决策器.md`，先判断适合图文、视频，还是一题多形。
4. **内容生产**：按锁定形式生成脚本、分镜、视觉资产和执行清单。
5. **系统复盘**：发布后复盘，只有被验证有长期价值的触发点才沉淀为 OBS，反哺底层模型。
