# 20｜关键帧镜头任务阀门

> 版本：V1.1  
> 状态：已沉淀为视频关键帧硬规则  
> 适用范围：所有视频项目的 KF01 / KF02 / KF03 等关键帧生成与验收  
> 核心结论：**视觉母版保证一致，镜头任务阀门保证推进；阀门不是为了限制画面，而是为了防止画面没有任务。**

---

## 一、为什么需要关键帧镜头任务阀门？

视觉母版解决的是：

```text
这几张图是不是属于同一个视频？
```

但它不能自动解决：

```text
这几张图有没有各自完成不同叙事任务？
```

如果只有视觉母版，没有镜头任务阀门，就会出现：

```text
人物一致了
空间一致了
风格一致了
但 KF02 只是 KF01 换了标题
KF03 只是 KF02 换了卡片
整条视频没有真正推进
```

这就是“同一张图换文案”的假进展。

所以视频关键帧必须同时过两道闸门：

```text
视觉母版闸门：保证它们像同一条视频。
镜头任务闸门：保证它们不是同一张图。
```

---

## 二、第一性原理

视频不是图片集合。

视频的本质是：

```text
时间中的认知变化。
```

每一个关键帧都必须推动观众从一个认知状态进入下一个认知状态。

如果一张关键帧没有让用户的理解发生变化，它就不是镜头推进，只是视觉重复。

关键帧必须回答：

```text
上一帧，用户处在什么状态？
这一帧，用户发生了什么理解变化？
下一帧，用户要被带到哪里？
```

但关键帧阀门不能把画面锁死。

它要控制的是：

```text
镜头有没有任务
认知有没有推进
是否能接上下一个镜头
```

它不应该强行规定：

```text
构图一定怎么摆
人物一定做哪个动作
卡片一定放左边还是右边
画面一定长成某一种固定样子
```

---

## 三、V1.1 升级原则：硬控任务 + 放开表达

V1.1 的核心调整是：

```text
从“死规定画面”
改成“硬控任务 + 放开表达”。
```

### 1. 必须硬控的东西

```text
1. 当前关键帧的主任务
2. 和上一帧相比的认知变化
3. 能否自然接到下一帧
4. 是否延续项目视觉母版
5. 是否避免只是换标题
```

### 2. 可以放开的东西

```text
1. 构图方式
2. 镜头远近
3. 人物动作
4. 卡片位置
5. 视觉隐喻
6. 信息密度
7. 动态表现方式
8. 分区方式
```

### 3. 一句话原则

```text
好画面不应该被阀门误杀。
没有任务的画面才应该被阀门拦下。
```

---

## 四、主任务 + 允许副任务

V1.0 使用“唯一任务”，容易把画面做窄。

V1.1 改为：

```text
主任务必须唯一。
副任务可以存在，但不能抢主任务。
```

### 主任务

主任务回答：

```text
这一帧最重要的认知推进是什么？
```

### 允许副任务

副任务回答：

```text
这一帧可以顺带为下一帧埋什么钩子？
```

例如 TP-001 的 KF02：

```text
主任务：让用户明白“不是你不会，是任务没分清”。
允许副任务：为 KF03 的“写东西 / 做东西 / 重复干活”做预告。
```

但如果三张任务卡在 KF02 已经成为最终主角，就会抢走 KF03 的任务，应当收回。

---

## 五、关键帧的三种合格变化

关键帧之间必须至少发生一个“主变化”。

辅助变化最多两个，不要为了变化而变化。

### 1. 信息状态变化

```text
信息从多变少
信息从散变整
信息从模糊变明确
信息从背景变主角
```

### 2. 认知状态变化

```text
不知道问题是什么 → 知道问题是什么
以为是自己不会 → 明白是任务没分清
以为要学所有工具 → 明白先解决眼前一件事
```

### 3. 画面秩序变化

```text
乱 → 停住
散 → 分区
满 → 留白
工具为主 → 任务为主
背景压力 → 前景判断
```

没有这些变化，只是换标题，不算合格关键帧。

## 六、关键帧任务卡 V1.1

每张关键帧生成前，必须先填写这张任务卡。

```text
关键帧编号：KF__
主任务：
允许副任务：
上一帧状态：
这一帧必须发生的主变化：
可以自由发挥的表达方式：
下一帧要接到哪里：
用户看完这一帧应产生的理解：
画面中必须出现的变化证据：
禁止重复上一帧的内容：
不能抢走下一帧的内容：
验收一句话：
```

如果这张任务卡没有写清楚，不允许生成关键帧。

## 七、关键帧生成前 10 问

生成任何关键帧前必须回答：

```text
1. 这是第几帧？KF01 / KF02 / KF03？
2. 这一帧的主任务是什么？
3. 允许的副任务是什么？
4. 上一帧用户看到的状态是什么？
5. 这一帧必须发生什么主变化？
6. 下一帧要接到什么状态？
7. 这一帧和上一帧的区别，用户 1 秒能看出来吗？
8. 这一帧有没有只是重复上一帧的构图和信息？
9. 这一帧有没有提前讲完下一帧的内容？
10. 这一帧是否仍然延续视觉母版？
```

只要第 7 条不成立，直接判废。

---

## 八、关键帧验收标准

每张关键帧生成后，必须判断：

```text
1. 是否延续项目视觉母版？
2. 是否完成当前镜头主任务？
3. 是否没有让副任务抢主任务？
4. 是否和上一帧有明显叙事差异？
5. 是否让用户理解发生变化？
6. 是否能自然接到下一帧？
7. 是否没有变成独立海报？
8. 是否没有只是换标题？
9. 是否没有把下一帧的信息提前讲完？
10. 是否保留了画面表达自由度？
```

通过标准：

```text
同一条视频 + 不同镜头任务 + 清晰认知推进 + 画面有表达余地
```

不通过标准：

```text
风格统一但内容重复
单张好看但无法推进
标题换了但画面任务没变
规则卡太死导致画面僵硬
```

---

## 九、通用规则与项目规则分离

通用阀门只规定：

```text
镜头必须有任务。
关键帧之间必须有认知推进。
关键帧必须能接上下帧。
关键帧必须延续视觉母版。
```

项目文件才规定：

```text
这个项目的人物是谁。
空间是什么。
卡片长什么样。
KF01 / KF02 / KF03 具体要怎么表达。
```

不能把某一个项目的具体布局变成所有项目的通用规则。

例如 TP-001 可以使用“左乱右清”的表达，但其他项目不一定必须左乱右清。只要它完成当前镜头任务，可以使用其他表达。

---

## 十、表达自由度清单

只要不破坏主任务，以下都可以自由设计：

```text
1. 近景 / 中景 / 远景
2. 正面 / 背影 / 侧面 / 俯视
3. 左右分区 / 前后层次 / 中心聚焦 / 卡片展开
4. 冻结 / 淡化 / 收拢 / 推远 / 聚焦
5. 人物动作：抓头、停顿、抬头、看向卡片、开始记录
6. UI 动作：弹出、冻结、归类、退后、变淡、展开
7. 画面隐喻：乱线变直线、卡片归类、路径出现、光线变清楚
```

但不能自由到破坏：

```text
人物连续性
空间连续性
画面语言连续性
主任务清晰度
```

## 十一、TP-001 示例

TP-001 的三张关键帧任务必须这样区分。

---

### KF01｜混乱入口

#### 主任务

```text
让用户 1 秒看懂：AI 工具太多，我不知道先学哪个。
```

#### 允许副任务

```text
建立人物和空间，让用户代入“我也这样”。
```

#### 上一帧状态

```text
无。视频开场。
```

#### 这一帧必须发生的主变化

```text
从空白进入信息过载。
用户看到大量工具、教程、收藏、提醒。
```

#### 用户理解

```text
我也有这种感觉：工具太多，越看越乱。
```

#### 画面证据

```text
工具卡片多
教程收藏多
通知多
人物困惑
桌面略乱
```

#### 禁止

```text
不要提前出现三张任务卡。
不要提前解释“任务没分清”。
不要让画面太清楚。
```

#### 验收一句话

```text
这是混乱，不是解决方案。
```

---

### KF02｜认知反转

#### 主任务

```text
让用户明白：不是我不会，也不是工具不够，是任务没分清。
```

#### 允许副任务

```text
预告 KF03 的三个任务入口，但不能让三张任务卡成为最终主角。
```

#### 上一帧状态

```text
工具很多，教程很多，用户不知道先学哪个。
```

#### 这一帧必须发生的主变化

```text
混乱必须被打断。
用户必须看到一个从“工具很多”到“任务没分清”的认知转折。
```

可选表达方式：

```text
方案 A：工具卡片冻结，反转句成为中心。
方案 B：人物动作从抓头变成停住，屏幕出现反转句。
方案 C：混乱搜索结果被归类成三个任务方向。
方案 D：工具卡片退后，任务卡开始浮现。
方案 E：画面从满屏工具压迫，变成有留白和判断句。
```

这些方案都可以，不必强制一个固定构图。

#### 下一帧要接到哪里

```text
KF03：三张任务卡成为主角，用户获得清晰选择。
```

#### 用户理解

```text
原来问题不是我不会，而是我没有先分清任务。
```

#### 画面证据

```text
工具卡片不再继续扩散。
反转句必须成为当前画面的认知中心。
任务卡可以出现，但只能是开始出现或辅助出现。
```

#### 禁止

```text
不要继续像 KF01 一样满屏工具卡。
不要只把标题从“AI工具越多越乱”换成“不是你不会”。
不要让三张任务卡完全抢走 KF03 的任务。
不要换人物、换空间、换风格。
```

#### 验收一句话

```text
这是转折，不是更干净的 KF01。
```

---

### KF03｜清晰选择

#### 主任务

```text
让用户马上知道自己可以从哪类任务开始。
```

#### 允许副任务

```text
为后面的工具对应表做铺垫。
```

#### 上一帧状态

```text
用户已经明白问题是任务没分清。
```

#### 这一帧必须发生的主变化

```text
工具退后。
三张任务卡成为主角。
每张卡给出 2-3 个具体例子。
用户从理解问题进入行动判断。
```

#### 用户理解

```text
我现在可以先问自己：我要 AI 帮我写东西、做东西，还是重复干活。
```

#### 画面证据

```text
写东西：标题 / 文案 / 脚本
做东西：网页 / 表格 / 图片
重复干活：整理 / 分类 / 提醒
```

#### 禁止

```text
不要再让工具名占主角。
不要再保持 KF01 的信息混乱。
不要只重复“任务没分清”。
```

#### 验收一句话

```text
这是选择入口，不是反转解释。
```

## 十二、三帧之间的差异必须能被肉眼看出

TP-001 三帧差异应当是：

```text
KF01：满，乱，焦虑，工具多。
KF02：停，打断，反转，任务开始被看见。
KF03：清楚，稳定，任务卡成为主角。
```

如果 KF02 只是：

```text
工具少一点
标题换一句
右侧多三张卡
```

但没有“打断 / 停顿 / 认知转折”，则判废。

---

## 十三、总导演检查顺序

以后每次生成关键帧前，总导演必须按这个顺序检查：

```text
1. 先看平台和时长是否已定。
2. 再看脚本是否适配平台。
3. 再看视觉母版是否锁定。
4. 再看当前关键帧编号。
5. 再看这一帧的主任务和允许副任务。
6. 再看它和上一帧的差异。
7. 再看它是否提前抢走下一帧任务。
8. 最后才允许生成图。
```

注意：

```text
视觉母版解决一致性。
镜头任务阀门解决推进性。
表达自由度解决画面生命力。
三者缺一不可。
```

---

## 十四、硬性禁止

```text
禁止因为风格一致就认为关键帧合格。
禁止用同一构图反复换标题。
禁止让 KF02 变成 KF01 的精简版。
禁止让 KF03 提前完全出现在 KF02。
禁止只判断“好不好看”。
禁止关键帧没有认知推进。
禁止把项目案例里的具体布局当成所有项目的通用规则。
禁止为了执行规则，把画面做僵。
```

---

## 十五、一句话原则

```text
关键帧不是同风格海报，
而是观众认知变化的节点。

阀门不是为了限制画面，
而是为了防止画面没有任务。
```
