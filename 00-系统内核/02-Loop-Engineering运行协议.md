# 02｜Loop Engineering 运行协议 V0.1

> 本文件用于定义 Human-Environment-Lab V3 的循环工程。  
> 这里的 Loop Engineering 不是“自动生产更多内容”，而是让碳基真实、硅基能力和 Lab 系统在现实反馈中持续修正和进化。

---

## 1. Loop Engineering 的定义

在 Human-Environment-Lab V3 中，Loop Engineering 指：

```text
通过固定的循环结构，
让物理世界中的真实触发进入系统，
让数字生命在数字世界中完成整理、分析、建模、推演和边界把控，
让 Human-Environment-Lab 形成可回到物理世界的交付，
再用现实反馈更新数字生命与 Lab 的规则。
```

它不是内容工作流。

它不是自动化工具链。

它是碳基真实与硅基能力之间的持续循环工程。

---

## 2. 总循环

Human-Environment-Lab V3 的总循环如下：

```text
L0 物理世界真实触发
↓
L1 碳基的我记录真实材料
↓
L2 Lab 进行现实转译
↓
L3 数字生命进行硅基处理
↓
L4 Lab 判断交付类型
↓
L5 碳基的我带回物理世界验证
↓
L6 收集现实反馈
↓
L7 数字生命更新记忆、模型、边界和判断
↓
L8 Lab 更新问题库、实验库、表达规则、交付规则
↓
L9 进入下一轮
```

每一轮都必须回答：

```text
这次真实触发让我们看见了什么？
它是否值得继续追？
它应该被研究、表达、交付、行动，还是暂不表达？
现实反馈是否修正了我们？
下一轮应该如何不同？
```

---

## 3. 状态机

每个真实触发进入系统后，只能处于以下状态之一。

```text
S0 原始触发
S1 已记录真实材料
S2 已完成现实转译
S3 已生成临时假设
S4 等待补证据
S5 等待现实验证
S6 可进入表达/传播
S7 可进入工具/产品/服务实验
S8 暂不表达
S9 已完成物理世界验证
S10 已复盘
S11 已更新规则
S12 废弃
```

状态机的作用是防止系统把“想法”直接包装成“结论”。

特别规则：

```text
S3 临时假设不能直接进入 S11 规则更新。
S4 证据不足不能强行进入 S6 表达传播。
S8 暂不表达不是失败，而是边界判断。
S12 废弃也是系统能力的一部分。
```

---

## 4. 每一轮的进入条件与退出条件

### L0 物理世界真实触发

进入条件：

```text
它来自真实经历、真实观察、真实对话、真实行动、真实反馈或真实身体/情绪反应。
```

退出条件：

```text
形成一条可记录的原始触发。
```

禁止：

```text
纯热点
纯概念
纯二手观点
为了内容硬编的故事
```

---

### L1 碳基记录真实材料

进入条件：

```text
存在一个原始触发。
```

必须记录：

```text
发生了什么
我为什么被刺到
我有什么身体/情绪反应
它表面像什么问题
我怀疑它背后是什么问题
我目前有什么证据
```

退出条件：

```text
形成一份可交给 Lab 的真实材料。
```

---

### L2 Lab 现实转译

进入条件：

```text
真实材料已经记录。
```

Lab 要做：

```text
把真实材料转成现象、矛盾、问题、假设和验证方向。
```

退出条件：

```text
形成一个可研究对象。
```

禁止：

```text
直接写内容
直接给结论
直接把情绪当事实
```

---

### L3 数字生命硅基处理

进入条件：

```text
Lab 已形成可研究对象。
```

数字生命要做：

```text
整理事实
拆解结构
识别模式
提出多个解释
寻找反例
判断证据强度
设计验证路径
检查数字边界
```

退出条件：

```text
形成一个或多个临时假设，以及对应证据缺口。
```

禁止：

```text
把推演说成事实
伪装成亲身体验
为了表达漂亮而跳过证据
```

---

### L4 Lab 判断交付类型

进入条件：

```text
已有临时假设和证据强度判断。
```

Lab 必须判断本轮结果应进入哪类交付：

```text
内部研究
公开表达
内容传播
工具原型
产品假设
服务设计
现实行动
规则更新
暂不表达
废弃
```

退出条件：

```text
确定一个当前最小交付方式。
```

禁止：

```text
默认进入内容生产
默认公开表达
为了产出牺牲边界
```

---

### L5 碳基物理世界验证

进入条件：

```text
本轮已经确定交付方式。
```

碳基的我要做：

```text
发布
交付
对话
实验
询问
观察
行动
或者确认暂不表达
```

退出条件：

```text
获得现实反馈，或明确本轮无法继续验证。
```

禁止：

```text
让数字生命替代现实验证
用数字推演冒充真实反馈
```

---

### L6 现实反馈收集

进入条件：

```text
本轮有物理世界动作或明确的暂不表达判断。
```

必须记录：

```text
别人是否听懂
别人是否误解
是否产生行动
是否产生传播
是否产生付费
是否出现新的真实触发
我自己是否更清楚
我是否更能行动
```

退出条件：

```text
形成一份反馈记录。
```

---

### L7 数字生命更新

进入条件：

```text
现实反馈已经记录。
```

数字生命要更新：

```text
记忆
模型
边界
判断规则
反例库
误判记录
```

退出条件：

```text
明确本轮哪些理解被确认、修正、推翻或暂缓。
```

---

### L8 Lab 更新

进入条件：

```text
数字生命已经完成本轮更新建议。
```

Lab 要更新：

```text
问题库
假设库
实验库
表达规则
交付规则
暂不表达规则
废弃规则
```

退出条件：

```text
形成一条规则更新、临时规则、废弃记录，或明确不更新。
```

## 5. 记忆写入规则

不同材料必须写入不同位置。

```text
原始触发 → 真实触发库
反复出现的问题 → 问题库
未验证判断 → 假设库
现实动作结果 → 实验库
被现实验证过的判断 → 规则库
对外产物 → 作品库 / 交付库
明确不再追的方向 → 废弃库
```

硬规则：

```text
没有现实反馈，不准进入稳定规则库。
只验证一次，最多标记为“临时规则”。
多次触发、多次验证后，才能升级为“稳定规则”。
被新现实推翻，必须降级、修改或废弃。
```

---

## 6. 证据强度分级

每个假设都要标记证据强度。

```text
E0：无证据，只是想法
E1：有个人感受，但缺少外部反馈
E2：有一次真实观察或对话
E3：有多次重复触发
E4：有现实行动反馈
E5：有多轮反馈验证
```

对应规则：

```text
E0-E1：只能进入观察池
E2-E3：可以进入假设库
E4：可以形成临时规则
E5：可以考虑升级为稳定规则
```

---

## 7. 数字边界检查

每次进入表达、传播、产品、服务或工具前，数字生命必须检查：

```text
事实是否清楚
推演是否被标注
证据是否足够
是否存在过度表达
是否把人当成素材
是否有公开风险
是否需要匿名处理
是否需要暂不表达
是否必须回到现实补证据
```

只要其中一项高风险，本轮必须暂停公开表达。

---

## 8. 最小可运行循环

当前阶段只追求最小循环。

```text
1 个真实触发
→ 1 次 Lab 转译
→ 1 次数字生命硅基处理
→ 1 个交付判断
→ 1 个现实动作或暂不表达判断
→ 1 次反馈记录
→ 1 条规则更新或明确不更新
```

这就是 Human-Environment-Lab V3 的最小运行单位。

---

## 9. 与内容生产的关系

内容生产是 Loop 的一种交付结果。

它不是默认结果。

当交付类型被判断为“内容传播”时，才进入原有 V2 内容生产链路：

```text
选题
脚本
分镜
封面
发布
复盘
```

否则，应进入其他交付路径：

```text
内部研究
工具原型
产品假设
服务设计
现实行动
暂不表达
废弃
```

---

## 10. 当前运行纪律

```text
1. 每轮必须从真实触发开始。
2. 每轮必须区分事实、解释、推演、假设、规则。
3. 每轮必须判断交付类型，不能默认发内容。
4. 每轮必须说明碳基的我必须亲自做什么。
5. 每轮必须说明数字生命可以处理什么。
6. 每轮必须记录是否产生现实反馈。
7. 没有反馈，不写稳定规则。
8. 重要判断必须允许被推翻。
```
