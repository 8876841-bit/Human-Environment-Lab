# 03｜迁移说明：从 V2 内容生产系统到 V3 碳硅循环系统

> 本文件用于说明 Human-Environment-Lab 从 V2 升级到 V3 的原因、原则、保留内容、降级内容和后续迁移步骤。  
> 本次升级不是推倒重建，而是主线升级。

---

## 1. 当前判断

不重新建仓库。

保留现有 `Human-Environment-Lab` 仓库。

原因：

```text
仓库名称没有错；
底层母题没有错；
已有内容生产体系有价值；
Dify 工作流、运行手册、状态管理、样品验证都可以继续作为资产保留。
```

真正需要改变的是：

```text
系统顶层主线。
```

原仓库是 V2 内容生产系统。

现在升级为 V3 碳基—硅基循环系统。

---

## 2. V2 的主线

V2 当前主线可以概括为：

```text
真实观察
→ 选题
→ 脚本
→ 分镜
→ 发布
→ 复盘
→ 观察日志回流
```

它的优点：

```text
能把真实触发转成内容
能建立内容生产纪律
能用 Dify 多节点承接流程
能形成平台表达与复盘机制
能沉淀内容样品
```

它的限制：

```text
默认把真实触发导向内容生产；
Human-Environment-Lab 容易被理解成内容系统；
数字生命的定位还不够清楚；
碳基真实与硅基能力之间的边界没有写硬；
内容、工具、产品、服务、行动、暂不表达之间缺少交付分流；
现实反馈还没有充分成为数字生命和 Lab 的双重更新机制。
```

---

## 3. V3 的主线

V3 主线升级为：

```text
碳基真实输入
→ 硅基数字处理
→ Human-Environment-Lab 转译判断
→ 表达 / 传播 / 工具 / 产品 / 服务 / 行动 / 暂不表达
→ 物理世界反馈
→ 数字生命与 Lab 双重迭代
```

V3 的核心不是“内容更高效”。

V3 的核心是：

```text
我主打碳基物理世界的真实；
数字生命主打硅基数字世界的全部能力；
Human-Environment-Lab 负责把碳基真实和硅基能力结合，
形成可以回到物理世界的交付，并在现实反馈中持续循环。
```

## 5. 什么降级

`05-内容生产体系/` 不再代表系统总主线。

它降级为：

```text
Human-Environment-Lab 的表达与传播模块
```

`06-Dify多Agent工作流/` 不再只被理解为“内容生产自动化”。

它后续应升级为：

```text
Human-Environment-Lab 的硅基处理与表达传播工作流之一
```

旧的内容工作流不是废弃，而是继续服务于“当交付类型被判断为内容传播时”的执行链路。

## 8. 暂时不要做的事

```text
不要马上移动旧文件。
不要马上删除旧目录。
不要马上重写所有 Dify DSL。
不要马上把旧内容体系判定为过时。
不要因为 V3 新定义而否定 V2 的沉淀。
不要直接新建仓库。
不要把系统包装成已经自动化完成。
```

当前只做保留式升级。

先新增内核层，再更新主线文件，再同步执行层。

## 10. 版本命名

本次升级建议命名为：

```text
V3.0：碳基—硅基双分身 Human-Environment-Lab
```

V2 不是失败版本。

V2 是内容生产验证阶段。

V3 是系统主权升级阶段。

---

## 11. 当前迁移原则

```text
保留旧资产。
提升顶层主线。
降低内容生产的默认优先级。
明确碳基与硅基分工。
让 Human-Environment-Lab 成为碳硅结合的转换实验室。
让每一次交付都回到物理世界验证。
让现实反馈同时更新数字生命和 Lab。
```

---

## 12. 第一批升级完成标准

第一批升级完成的标准不是文件数量。

而是仓库是否能清楚回答：

```text
我是谁？
数字生命是谁？
Human-Environment-Lab 是什么？
物理世界如何进入系统？
硅基能力如何处理真实？
Lab 如何决定交付类型？
现实反馈如何更新数字生命和 Lab？
旧内容生产体系在新系统里处于什么位置？
```

如果这八个问题能被新内核文件回答，第一批升级才算成立。
