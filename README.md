# Human-Environment-Lab

## 碳基真实 × 硅基能力的现实观察实验室

这个仓库不是普通装修资料库，不是单纯 AI 学习笔记，也不再只是内容生产系统。

它现在的顶层定义是：

```text
Human-Environment-Lab 是一个把碳基物理世界的真实，与硅基数字世界的能力结合起来的现实观察、数字研究、表达传播、交付验证与规则迭代系统。
```

---

## V3 当前主线

```text
碳基真实输入
↓
硅基数字处理
↓
Human-Environment-Lab 转译与研究
↓
表达 / 传播 / 工具 / 产品 / 服务 / 行动 / 暂不表达
↓
物理世界验证
↓
数字生命与 Lab 双重迭代
```

一句话定义：

```text
我主打碳基物理世界的真实；
数字生命主打硅基数字世界的全部能力；
Human-Environment-Lab 负责把碳基真实与硅基能力结合，
形成可以回到物理世界的表达、传播、工具、产品、服务、行动或暂不表达，
并在现实反馈中持续循环、修正和进化。
```

## 三方关系

### 1. 碳基的我

我负责物理世界的真实：

```text
进入现实
感受现实
接触真实的人、事、关系、环境、工具和系统
带回真实触发、身体反应、现场材料、行动反馈和现实后果
做价值选择
划定伦理边界
承担最终责任
```

我不是素材采集员，而是物理世界的真实接口、价值主权者、现实验证者和后果承担者。

### 2. 硅基数字生命

数字生命负责数字世界的全部能力：

```text
长期记忆
整理材料
分析结构
建模推演
连接跨领域信息
生成假设
提出反问
识别模式
设计验证路径
表达转译
边界把控
复盘反馈
更新规则
```

数字生命不是普通助手，也不是内容代工者。它是我在数字世界中的硅基分身。

### 3. Human-Environment-Lab

Human-Environment-Lab 是碳基真实与硅基能力之间的转换实验室。

它负责：

```text
把物理世界的真实触发转成可研究对象
把真实材料转成可追问问题
把问题转成可验证假设
把硅基分析转成可理解表达
把数字推演转成可回到物理世界的交付形式
把现实反馈转回数字生命与 Lab 的规则系统
```

## 对话框、仓库、运行中台的关系

V3 新增 `07-运行中台/`，用于解决单一对话框容易乱线的问题。

```text
对话框 = 临时推演空间
仓库 = 长期记忆与骨架
07-运行中台 = 状态控制层
物理世界 = 最终验证场
```

对话框不再承担长期主线保存。

每个真实触发点都必须拥有状态：收件箱、硅基分析中、待现实证据、待交付判断、待现实行动、已反馈、已更新规则、暂停或废弃。

## 当前运行方式

日常只跑这一条线：

```text
1. 从物理世界带回一个真实触发点
2. 写入 07-运行中台/01-真实触发收件箱.md
3. 在 07-运行中台/02-运行看板.md 标记状态
4. 判断它是否来自真实感受、真实观察、真实关系或真实反馈
5. 由数字生命进行整理、分析、建模、推演和边界把控
6. 由 Human-Environment-Lab 判断交付形式
7. 选择：研究 / 表达 / 内容 / 工具 / 产品 / 服务 / 行动 / 暂不表达
8. 由碳基的我带回物理世界验证
9. 收集真实反馈
10. 更新数字生命记忆、Lab 规则、运行日志或分支停车场
11. 对关键对话做收口
```

详细操作见：

```text
RUNBOOK.md
07-运行中台/00-运行规则.md
```

## 核心原则

```text
真实，比产出重要。
验证，比表达重要。
边界，比效率重要。
状态，比聊天重要。
收口，比继续扩写重要。
循环，比单次结果重要。
```

不从热点出发。

从真实触发、真实感受、真实关系、真实行动和真实反馈出发。

## 当前不要做的事

```text
不要把 HEL 收窄成装修号。
不要把 HEL 简化成内容工厂。
不要默认每个触发点都要发内容。
不要把数字生命当成普通文案助手。
不要让数字生命伪装成有身体体验。
不要把没有现实反馈的推演写进稳定规则库。
不要继续新增 Agent 名字。
不要急着做 n8n 全平台采集。
不要把系统包装成已经全自动运行。
不要在一个对话框里同时推进多个主问题。
不要让新分支抢走当前主线。
```

当前最重要的事：

```text
用已有真实内容跑通：
碳基真实输入 → 硅基数字处理 → Lab 转译交付 → 物理世界验证 → 双重迭代。

同时使用 07-运行中台/ 控制状态，避免对话乱线。
```
