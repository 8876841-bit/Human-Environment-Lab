# 03-内容与视频总链路

版本：V3.3  
状态：ACTIVE / EXECUTION-CHAIN

本文件是 `09-内容与视频执行中台/` 的唯一主链路文件。

它不重新定义原创根基，只规定数字生命如何调用根基，并指挥 Human-Environment-Lab 执行内容、视频、平台、数据和反馈工作。

---

## 0. 当前关系

```text
有形的我 = 现实入口 / 真实材料 / 最终主权
数字生命 = 脑 / 原创判断 / AI 能力调用 / 底层逻辑控制
Human-Environment-Lab = 手和脚 / 内容与视频执行系统
```

本链路的目标不是“把内容发出去”。

本链路的目标是：

```text
让数字生命指挥 HEL，
把真实观察转化为可分析、可生成、可制作、可发布、可复盘、可训练的内容与视频系统。
```

## 2. 链路总原则

### 2.1 从真实观察出发，不从热点出发

正确起点是：

```text
真实生活
真实现场
真实行为
真实感受
真实困惑
真实反馈
真实素材
```

热点、同行、平台趋势可以作为参考材料，但不能作为原创内容的第一来源。

---

### 2.2 内容分析不是独立理论模块

当前不再新建庞大的“内容分析模块”。

内容分析的定义是：

```text
在执行链路中调用原创根基进行价值判断。
```

它调用的是：

```text
真实观察优先
需求 × 行为 × 环境 × 系统 = 原创选题
八条母线
第一性原理锚点
用户真实感受
平台表达转译
AI 给骨架，人工给灵魂
发布不是结束，反馈才是训练
```

禁止：

```text
根基一套，分析一套，生成一套，平台一套。
```

---

### 2.3 内核深，外显浅

数字生命可以在内部使用：

```text
底层逻辑
第一性原理
八条母线
系统规律
结构关系
用户状态
平台机制
```

但对外表达必须转成：

```text
用户能听懂的问题
用户能代入的状态
用户能理解的判断
用户能执行的动作
用户愿意停留的表达
```

禁止把内部术语直接端上平台。

---

### 2.4 成品导向，不是建议导向

HEL 输出目标不是：

```text
建议
方向
灵感
拍摄清单
执行建议
```

而是尽量输出：

```text
可发布的图文成品包
可生成的视频执行包
可剪辑的成片包
可平台改写的发布包
可复盘的数据回流包
```

---

### 2.5 平台前置，不是脚本后补

禁止顺序：

```text
先写脚本
→ 再硬套平台调性
→ 再临时改成人话
```

正确顺序：

```text
先判断平台
再判断谁在看
再判断内容任务
再判断表达边界
最后生成脚本和成品包
```

---

### 2.6 发布不是结束，反馈才是训练

真正要回收的是：

```text
用户是否听懂
平台是否分发
评论是否暴露真实需求
收藏是否证明复用价值
完播是否证明节奏成立
私信 / 咨询是否证明信任形成
数据是否验证选题判断
反馈是否更新数字生命
```

闭环目的不是优化技巧，而是验证判断、训练数字生命、提升 HEL 的执行能力。

## 3. 节点定义

## 01 现实输入

负责什么：

```text
把有形的我在现实世界获得的材料，送入数字生命判断。
```

输入：

```text
现实观察
现场素材
用户评论
平台反馈
同行内容
行业信息
案例素材
私信咨询
账号数据
线下对话
```

输出：

```text
可进入判断的现实材料包
```

停止标准：

```text
来源清楚。
事实、感受、推测能分开。
不能把没有来源的内容写成事实。
```

---

## 02 原创判断

负责什么：

```text
判断这条材料有没有原创内容价值。
```

输入：

```text
现实材料包
真实触发点
用户需求
平台反馈
```

输出：

```text
原创锚点
```

必须调用：

```text
需求 × 行为 × 环境 × 系统 = 原创选题
```

每条内容至少回答：

```text
人在追求什么？
人产生了什么行为？
环境如何影响行为？
它发生在哪个系统里？
```

停止标准：

```text
有真实来源。
有原创锚点。
能说清用户感受。
否则不进入生成。
```

---

## 03 内容能力等级判断

负责什么：

```text
判断这条内容当前要打哪一层能力，而不是默认发布。
```

输入：

```text
原创锚点
内容机会
平台任务
当前账号能力
```

输出：

```text
本条内容对应的能力等级目标
```

调用：

```text
09-内容与视频执行中台/02-内容碾压等级.md
```

可选方向：

```text
表达优势
选题优势
结构优势
生产优势
视频优势
平台优势
数据优势
投放优势
信息采集优势
商业转化优势
系统执行优势
```

停止标准：

```text
明确这条内容要解决哪一层能力问题。
不能只说“发一条”。
```

---

## 04 内容任务定义

负责什么：

```text
把原创锚点转成明确内容任务。
```

输入：

```text
原创锚点
能力等级目标
用户真实感受
平台任务
```

输出：

```text
内容任务说明
```

必须回答：

```text
这条内容解释什么问题？
用户为什么会停下来？
看完要得到什么？
这条内容要建立什么判断或信任？
```

停止标准：

```text
任务清楚。
不是泛泛表达。
不是为了填发布日历。
```

---

## 05 平台与受众判断

负责什么：

```text
在生成前判断平台、受众、节奏和边界。
```

输入：

```text
内容任务
首发平台
目标用户
表达边界
```

输出：

```text
平台前置判断
```

必须回答：

```text
谁在看？
他现在什么状态？
他为什么会停下来？
平台适合什么节奏？
这条内容适合短冲击、中解释还是长拆解？
有什么审核、版权、隐私、夸大风险？
```

停止标准：

```text
不允许所有平台共用一个脚本。
不允许脚本写完后再硬套平台。
```

---

## 06 形式决策

负责什么：

```text
判断这条内容应该以什么形式出现。
```

输入：

```text
内容任务
平台前置判断
素材条件
制作能力
```

输出：

```text
内容形式决策
```

可选形式：

```text
图文
口播
实拍视频
AI 视频
实拍 + AI 混合视频
长文
短观点
直播切片
暂不表达
```

停止标准：

```text
形式服务内容任务。
不能因为想做视频就硬做视频。
不能因为方便就全部做图文。
```

---

## 07 内容生成

负责什么：

```text
把通过前置判断的内容任务转成可执行成品。
```

输入：

```text
内容任务
原创锚点
平台判断
形式决策
用户感受
```

输出：

```text
标题组
封面文案
正文 / 图文结构
口播脚本
分镜说明
发布文案
```

停止标准：

```text
普通人能听懂。
平台能接收。
没有丢掉底层判断。
能进入视频或发布制作。
```

---

## 08 视频生成 / 视频制作

负责什么：

```text
把内容转成可生成、可剪辑、可发布的视频执行包。
```

视频生成包括：

```text
AI 视频提示词
镜头设计
首尾帧设计
画面风格控制
素材生成
配音、音效、BGM 方向
```

视频制作包括：

```text
剪辑节奏
镜头排序
字幕
转场
音效
BGM
成片质检
平台版本
```

输出：

```text
视频执行包
AI 视频生成包
剪辑制作包
成片检查清单
```

停止标准：

```text
视频不是文字脚本的机械翻译。
每个镜头都服务信息、情绪或证据。
成片能进入平台发布前检查。
```

---

## 09 发布运营

负责什么：

```text
把成品放进平台语境，而不是简单复制发布。
```

输入：

```text
成品包
首发平台
目标用户
发布时间
发布文案
标签
评论引导
```

输出：

```text
平台发布包
```

停止标准：

```text
平台表达已适配。
标题、封面、正文、标签、评论引导一致。
发布后知道要看什么反馈。
```

---

## 10 数据 / 投放 / 评论 / 转化分析

负责什么：

```text
判断内容有没有产生真实作用。
```

输入：

```text
播放
完播
点赞
收藏
评论
转发
转粉
私信
咨询
成交
投放消耗
转化路径
```

输出：

```text
反馈分析报告
```

必须区分：

```text
平台分发反馈
用户理解反馈
内容价值反馈
商业信任反馈
制作质量反馈
投放效率反馈
```

停止标准：

```text
不能只看播放量。
必须能说清这条内容验证了什么，没验证什么。
```

---

## 11 反馈回流

负责什么：

```text
把平台和现实反馈转回数字生命更新。
```

输入：

```text
反馈分析报告
评论真实问题
用户误解
咨询内容
转化路径
失败原因
```

输出：

```text
数字生命更新项
HEL 执行改进项
待验证问题
```

停止标准：

```text
没有反馈，不更新稳定规则。
有反馈，也要区分偶然反馈和可复用规律。
```

---

## 12 更新数字生命

负责什么：

```text
把被验证过的判断、表达方式、平台规律、用户问题，写回数字生命的规则系统。
```

输出：

```text
更新的判断规则
更新的表达规则
更新的平台规则
更新的视频制作规则
更新的信息采集方向
```

硬边界：

```text
只能更新数字生命的解释、调度和执行规则。
不能反向改写原始根基。
```


每个文件必须回答：

```text

输入是什么？

```

## 5. 当前禁令

```text
禁止从热点直接生成内容。
禁止没有原创锚点就进入脚本。
禁止把内容分析做成另一套理论。
禁止让 HEL 重新定义根基。
禁止把视频生成当成简单画面提示词。
禁止把视频制作当成剪辑清单。
禁止把平台运营当成复制发布。
禁止把数据复盘当成看播放量。
禁止把发布当成碾压。
```
