# 03-内容生成总链路

版本：V3.3
状态：ACTIVE / EXECUTION-CHAIN

本文件用于把旧仓库中分散的内容生成流程，合并成 Human-Environment-Lab 当前阶段的正式执行链。

当前关系：

```text
有形的我 = 现实入口 / 真实材料 / 最终主权
数字生命 = 脑 / 原创判断 / AI 能力调用 / 底层逻辑控制
Human-Environment-Lab = 手和脚 / 内容与视频执行系统
```

本链路的目标不是“把内容发出去”。

本链路的目标是：

```text
让数字生命指挥 HEL，
把真实观察转化为可分析、可生成、可制作、可发布、可复盘、可训练的内容与视频系统。
```

---

## 一、总链路

HEL 当前内容生成总链路为：

```text
信息采集
→ 内容分析
→ 原创判断
→ 选题判断
→ 平台与受众前置校验
→ 内容形式决策
→ 标题 / 封面 / 文案 / 脚本生成
→ 分镜 / 图文 / 视频执行包生成
→ 视频生成
→ 视频制作
→ 发布适配
→ 数据复盘
→ 反馈回流
→ 更新数字生命
```

这条链路合并了旧仓库中的几条关键资产：

```text
02-内容引擎/内容生成引擎-V1.md
05-内容生产体系/10-Dify工作流搭建实施指南.md
05-内容生产体系/11-内容形式决策器.md
05-内容生产体系/13-视频成品形式库.md
05-内容生产体系/16-平台规则与发布调性表.md
05-内容生产体系/17-第一性原理到平台表达转译表.md
```

旧链路里的“观察 → 选题 → 脚本 → 画面 → 剪辑 → 发布 → 数据 → 复盘 → 再观察”继续保留，但在 V3.3 中被升级为更完整的内容与视频执行链。

## 二、链路总原则

### 1. 从真实观察出发，不从热点出发

HEL 不能从平台热点、同行模板、爆款标题直接开始生成内容。

正确起点是：

```text
真实生活
真实现场
真实行为
真实感受
真实困惑
真实反馈
真实素材
```

热点、同行、平台趋势可以作为参考材料，但不能作为原创内容的第一来源。

---

### 2. 内核深，外显浅

数字生命可以在内部使用：

```text
底层逻辑
第一性原理
八条母线
系统规律
结构关系
用户状态
平台机制
```

但对外表达必须转成：

```text
用户能听懂的问题
用户能代入的状态
用户能理解的判断
用户能执行的动作
用户愿意停留的表达
```

禁止把内部术语直接端上平台。

---

### 3. 成品导向，不是建议导向

HEL 输出的目标不是：

```text
建议
方向
灵感
拍摄清单
执行建议
```

而是尽量输出：

```text
可发布的图文成品包
可生成的视频执行包
可剪辑的成片包
可平台改写的发布包
可复盘的数据回流包
```

只有在需要真人实拍、现场补素材、隐私确认、版权确认时，才额外输出补充清单。

---

### 4. 平台前置，不是脚本后补

禁止顺序：

```text
先写脚本
→ 再硬套平台调性
→ 再临时改成人话
```

正确顺序：

```text
先判断平台
再判断谁在看
再判断内容任务
再判断表达边界
最后生成脚本和成品包
```

---

### 5. 发布不是结束，反馈才是训练

内容发布只是进入现实与平台系统的一步。

真正要回收的是：

```text
用户是否听懂
平台是否分发
评论是否暴露真实需求
收藏是否证明复用价值
完播是否证明节奏成立
私信 / 咨询是否证明信任形成
数据是否验证选题判断
反馈是否更新数字生命
```

闭环目的不是优化技巧，而是验证判断、训练数字生命、提升 HEL 的执行能力。

## 03 原创判断

### 输入

```text
真实触发点
内容机会
观察材料
用户需求
平台反馈
```

### 输出

```text
原创锚点
```

### 必须通过的公式

```text
需求 × 行为 × 环境 × 系统 = 原创选题
```

每条内容至少要回答：

```text
人在追求什么？
人产生了什么行为？
环境如何影响行为？
它发生在哪个系统里？
```

### 数字生命负责

```text
判断是否有原创根基
判断属于哪条观察母线
判断是否有第一性原理锚点
判断是否只是套热点、套模板、套情绪
```

### HEL 负责

```text
把原创判断转成可继续执行的选题材料
```

### 禁止

```text
没有真实来源就生成观点。
没有原创锚点就进入脚本。
没有用户感受就进入平台表达。
```

## 04 选题判断

### 输入

```text

```

### 输出

```text

```

### 选题必须说明

```text
这条选题解释什么问题？
用户为什么会停下来？

它背后的底层规律是什么？
它适合首发在哪个平台？

```

### 选题等级

```text
A：强触发 + 强结构 + 强平台表达，优先制作
B：有真实触发，但结构或平台表达需打磨
C：只适合内部研究或等待更多证据
D：暂不执行
```

## 06 内容形式决策

### 输入

```text
选题
平台前置判断
用户状态
内容任务
表达边界
```

### 输出

```text
主形式判断
```

### 可选形式

```text
图文
短视频
中视频
长视频
口播
实拍
AI 生成视频
混合增强视频
长文
直播脚本
私域表达
一题多形
```

### 判断规则

```text
情绪强、冲突强、抓停留 → 短视频优先
结构强、方法强、收藏价值强 → 图文优先
真实现场强 → 实拍 / 混合增强优先
抽象机制强 → AI 生成 / 图示 / 桌面推演优先
逻辑链长 → B站长视频 / 长文优先
情绪强 + 方法强 → 视频主发，图文承接
```

### 最终原则

```text
形式不是为了好看。
形式必须服务：底层判断、平台调性、用户状态和内容任务。
```

## 五、一次完整执行的最小案例

### 触发点

```text
为什么很多建材人觉得过两年市场会变好？
```

### 信息采集

```text
行业对话、建材人原话、房地产市场数据、平台评论、同行观点。
```

### 内容分析

```text
这句话表面是市场判断，实际可能包含旧周期经验、生存压力、政策想象和自我安慰。
```

### 原创判断

```text
人在旧系统下行时，会把结构性变化误判成周期低谷，从而用“再熬两年”逃避重构。
```

### 选题判断

```text
选题：为什么很多传统行业的人，总觉得“再熬两年就好了”？
等级：B。原因：真实触发强，但还缺 5 个建材人原话。
```

### 平台前置

```text
小红书：适合做图文观察笔记，强调“你说的变好，到底是哪种变好？”
抖音：适合短视频反问，抓住“你等的是市场，还是旧模式回来？”
B站：适合长视频拆解传统行业周期判断。
```

### 内容形式

```text
当前先做内部研究 / 小红书图文草稿。
暂不直接做抖音强观点视频，因为证据不足。
```

### 下一步

```text
收集 5 个建材行业相关者原话：
你说的“变好”具体指什么？
客户会变多？价格会回升？利润会回来？还是只是不会比现在更差？
```

### 反馈回流

```text
如果收集到真实原话，再进入正式内容生成和平台发布包。
```

## 六、硬性禁令

HEL 内容生成链路禁止：

```text
1. 从热点直接生成内容。
2. 从同行模板直接改写内容。
3. 没有真实触发就进入脚本。
4. 没有第一性原理锚点就进入形式决策。
5. 没有平台前置判断就写脚本。
6. 把所有内容默认做成视频。
7. 把所有内容默认一题多形。
8. 把视频生成误认为视频制作。
9. 把发布当成结束。
10. 只看播放量，不看反馈是否训练数字生命。
11. 把账号矩阵当成当前必做动作。
12. 把内容生产降级成普通发布。
```
